# 서울카페쇼 2026 도면을 최신 공식 배치도로 다시 뽑기

_2026-11-17 · Ted 결정_

## 무엇을 했나

- `src/lib/floorplan-cafeshow-2026.json`을 exporum 공식 배치도(exhibitionId=19)에서 다시 만들었다. 기존 데이터는 2026-10-02에 뽑은 597칸이었고, 새로 뽑은 데이터는 615칸이다.
  - 새로 생긴 칸 20개, 없어진 칸 2개(C620, D383)
  - 홀 벽 기준으로 0.5m 넘게 옮겨진 칸 189개
- `scripts/floorplan-from-exporum.mjs`에서 바꾼 곳:
  - exporum에 새로 생긴 `sponsor` 분류를 참가 부스로 넣는다(`EXHIBITOR_CATEGORIES`). `organizer`는 계속 시설이다.
  - ㄱ자 부스 3곳(A841, A919, A119)은 `RECT_OVERRIDES`로 공식 배치도 모양에 맞춰 자른다. API가 이 부스를 감싸는 네모로 주기 때문에 이웃 부스와 1m 겹친다.
  - 부스 왼쪽 위 모서리를 5cm 단위로 반올림한다. 반올림하지 않으면 1~2cm짜리 겹침 13쌍이 `floorplans.test.ts`의 겹침 검사에 걸린다.
- 테스트를 고쳤다. 기대 칸 수를 615로 바꾸고, 카페쇼 겹침 예외(A107×A111)를 없앴다.
- `data/intake/cafeshow-2026.json`에서 없어진 C620, D383 두 줄을 뺐다.

## 왜 이렇게 했나

- 10-02 데이터는 공식 배치도와 많이 어긋났다. B홀은 60/165칸, D홀은 24/115칸만 자리가 맞았다. Figma 지도 페이지에 그린 부스 예시가 그대로 개발로 들어가는데(Ted 11-16), 그 예시를 지금 공식 배치도에 맞춰 다시 그렸다.
- 후원사 칸은 관람객이 찾아가는 부스다. 시설로 두면 지도에서 부스로 고를 수 없다.
- ㄱ자 부스는 JSON을 손으로 고치지 않고 스크립트 안의 보정 표로 자른다. 다시 뽑아도 같은 결과가 나오게 하려는 것이다. API 값이 바뀌면 자르지 않고 경고만 낸다.

## 버린 방법

- **API가 준 그대로 두기:** 앱 지도에서 부스가 겹쳐 보이고, 겹침 예외 목록이 계속 늘어난다.
- **JSON 직접 수정:** 다음에 다시 뽑으면 수정한 내용이 사라진다.
