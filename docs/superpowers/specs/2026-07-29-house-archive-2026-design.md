# HOUSE ARCHIVE 2026 전시 추가

날짜: 2026-07-29
신규 전시: `house-archive-2026` (하우스 아카이브: 홈 디깅 페어)

## 배경

Roam에 세 번째 전시를 올린다. 개막이 **2026-08-13**이라 2주 남았다.

| 항목 | 값 |
|---|---|
| 전시명 | 하우스 아카이브: 홈 디깅 페어 |
| 기간 | 2026-08-13(목) ~ 2026-08-16(일) |
| 장소 | 코엑스 더 플라츠 2층 (63.0 × 35.3m, 2,224㎡, 최대 114부스) |
| 공식 사이트 | https://www.housearchive.kr (Wix SPA) |
| 부스 수 | 104 (기획존 5 + 부스존 68 + 테이블마켓 26 + CENTER 5) |

기존 두 전시(SIBF·SIF)와 달리 이 전시는 **공식 플랫폼의 디지털 도면이 없다.** 자료는
도면 이미지 2장과 참여자 명단 이미지 1장뿐이다.

## 왜 저작 포맷을 만들지 않는가

이 작업의 초기 구상은 "미터 단위 블록 저작 포맷"이었다. 그릴링으로 폐기했다.

- **도면 이미지가 추출 가능하다.** 부스가 단색 채우기 + 검은 테두리라, 배경색을 빼고
  런-길이 + union-find로 라벨링하는 40줄 파이썬(PIL만, numpy 불필요)으로 사각형이
  뽑힌다. 실제로 좌측 36개 / 우측 44개를 검출해 확인했다. 손으로 옮길 일이 없으므로
  저작 포맷을 쓸 사람이 없다.
- **분량도 포맷을 정당화하지 못한다.** SIF는 914개였지만 여기는 104개다.

저작 포맷은 **진짜로 추출 불가능한 도면**(스캔한 종이, 저해상도 사진)이 나올 때 만든다.
`expandFloorplan()` 같은 펼치기 계층도 마찬가지로 만들지 않는다.

## 데이터 소스

### 도면 (`public/`)

- `하우스아카이브_도면 좌측.png` — 1314 × 1700
- `하우스아카이브_도면 우측.png` — 1318 × 1678

공식 사이트 캐러셀의 두 슬라이드다. Wix 정적 자산에서 통짜 원본을 찾지 못했다.

**두 이미지는 겹치지 않고 맞붙는다.** 픽셀 상관으로 확인했다 — 겹침량을 40px부터
420px까지 키우며 평균 픽셀차를 재면 최소가 하한(42px)에서 25.3으로 나오고 겹침을 키울수록
119까지 나빠진다. 진짜 겹침이 있었다면 특정 값에서 0에 가까운 골이 생겨야 하는데 없다.
즉 실제 겹침은 0에 가깝다. 정합 파라미터:

```
좌표계 = 좌측 이미지 기준
좌측:  (x, y)            그대로
우측:  (x + 1314, y + 8)
```

y 오프셋 +8은 이음매에서 잘린 부스 4개의 높이가 양쪽에서 정확히 일치하는 것으로
교차 검증된다(`G14` 277px, `G13` 96px가 양쪽 동일, y 차이 8px 일관).

**이음매에서 잘린 부스**(`C06`·`C07`·`G13`·`G14`)는 좌측의 오른쪽 조각과 우측의 왼쪽
조각을 **하나로 합쳐야** 한다. 검출 결과를 그대로 쓰면 한 부스가 둘로 쪼개진다.

### 참여자 명단

`하우스아카이브 참여자 명단.png` — 104개 부스 전부의 코드 · 국문명 · 영문명. 전사해서
`src/lib/booth/house-archive-2026.json`으로 만든다.

## 스케일

**32 px/m.** 표준부스가 96 × 64px이고 더 플라츠 표준부스가 3m × 2m이므로
96/3 = 32, 64/2 = 32로 두 축이 일치한다. 2칸 부스 192 × 64px = 6m × 2m로도 확인된다.

검출된 크기 분포(가로·세로 두 방향 합산):

| 픽셀 | 실치수 | 개수 |
|---|---|---|
| ~96×64 / ~64×88 | 3m × 2m (표준) | 27 |
| ~192×64 / ~64×184 | 6m × 2m (2칸) | 20 |
| 기타 | H01~H05 · CENTER 5개 | ~12 |

캔버스는 **부스 바운딩 박스**로 잡는다. SIF가 ocreo의 좌표계를 그대로 쓴 것과 같다.
도면 이미지 전체 폭(≈2624px = 82m)은 홀 실폭 63m보다 크다 — 여백·제목·로비가 포함된
그래픽이기 때문이다. 홀 실치수에 억지로 맞추지 않는다.

## 카테고리 — 5개 테마 + 테이블마켓

부스 코드의 앞글자가 곧 테마이고, 도면의 부스 색과도 일치한다.

| 접두 | 테마 | 도면 색 | 개수 |
|---|---|---|---|
| C | COLLECT HOUSE (수집) | 분홍 | 15 |
| G | GATHER HOUSE (관계) | 노랑 | 14 |
| M | MAKE HOUSE (창작) | 베이지 | 13 |
| R | REST HOUSE (쉼) | 연두 | 13 |
| E | EXPLORE HOUSE (탐험) | 살구 | 13 |
| T | 테이블 마켓 | 무색 | 26 |

기획존 `H01`~`H05`는 각 테마 × 브랜드 콜라보(빅슬립 · 헤르시 · 아지카진 매직월드 ·
모티프원 · 샤론)다. **테마 카테고리를 그대로 쓰고** `tags`에 `기획존`을 더한다.

**축이 둘인데 `Booth.categoryId`는 하나다.** 카테고리는 테마로 잡고, 존·등급은 `tags`에
얹는다. 추천 품질 때문이다 — 5개 테마가 Roam의 가치 슬러그와 거의 1:1로 붙어
(`COLLECT→goods`, `GATHER→social`, `MAKE→inspiration`, `REST→rest`,
`EXPLORE→discovery`) `deriveValueTags`가 그대로 먹는다. 부스 enrichment를 손으로 채우기
전에도 첫날부터 추천이 성립한다. 반대로 카테고리를 존으로 잡으면 "부스존 68개"라는
무의미한 덩어리가 되고 추천 신호가 0이 된다.

`T01`~`T26`은 도면에 테마색이 없어 **테마 없는 별도 등급**으로 둔다. 더 플라츠는 내부
특성상 다른 방식의 부스 설치가 가능해서 실제로 다른 등급이다.

**CENTER 5개**(COLLECT/GATHER/MAKE/EXPLORE/REST HOUSE CENTER)는 참가 부스가 아니라 테마
앵커 공간이므로 `kind: "facility"`로 넣는다. 추천·피드에서 빠지고 지도에는 남는다.

## 홀 프리셋 — `src/lib/venues/coex.ts`

Roam이 다루는 전시는 전부 코엑스에서 열린다. 새 도면을 받았을 때 홀만 알면 바로 좌표계를
잡을 수 있도록 공식 제원을 상수로 박는다.

```ts
export const COEX_HALLS = {
  "hall-a":    { name: "A홀",      m: [144.0, 72.0], area: 10368, booths: 520, standardBooth: [3, 3] },
  "hall-b":    { name: "B홀",      m: [90.0, 81.0],  area: 8010,  booths: 360, standardBooth: [3, 3] },
  "hall-c":    { name: "C홀",      m: [144.0, 72.0], area: 10348, booths: 520, standardBooth: [3, 3], pillarPitch: 18 },
  "hall-d":    { name: "D홀",      m: [81.0, 81.0],  area: 7281,  booths: 360, standardBooth: [3, 3] },
  "the-platz": { name: "더 플라츠", m: [63.0, 35.3],  area: 2224,  booths: 114, standardBooth: [3, 2] },
} as const;
```

전시별로 `hall` 키와 `unitsPerMeter`를 기록한다: HOUSE ARCHIVE = `the-platz` / 32,
SIF = `hall-c` / 20, SIBF = `hall-a` / 17.7(개략도라 근사).

> 이 상수는 한 번 YAGNI로 잘렸다가 되살아났다. 잘랐던 이유는 "오늘 소비처가 없다"였고,
> 되살린 이유는 사용자가 소비처를 지정했기 때문이다 — 아무 홀 도면이나 받았을 때 즉시
> 작업을 시작할 수 있어야 한다. 앱 런타임이 아직 안 읽더라도 이 표 자체가 산출물이다.

## 검증

1. **불변식** — 부스 104개, 코드 유일, 겹침 0, 캔버스 이탈 0, 이름 빈 값 0.
   `floorplans.test.ts`에 SIF와 같은 형태로 트립와이어(부스 개수·캔버스 크기)를 건다.
2. **스케일 검산** — 표준부스가 3m × 2m로 떨어지는지. 안 떨어지면 정합이 틀린 것이다.
3. **시각 대조** — 새 데이터를 렌더해 원본 PNG 2장과 나란히 놓고 확인한다. 특히
   **이음매 부근**(C06·C07·G13·G14)이 하나의 온전한 부스로 합쳐졌는지.
4. **앱 실행** — mock 모드로 지도를 띄워 부스 104개가 렌더되는지, 테마별 색이 맞는지,
   `T01`~`T26`이 별도 등급으로 보이는지.
5. `npx tsc --noEmit` · `npx vitest run` · `npx eslint <변경 파일>`

## 범위 밖

- **미터 저작 포맷 / `expandFloorplan()`** — 위 사유로 폐기.
- **지도 비주얼 시스템 통일** — 전시 무관 라벨·색·통로 규칙은 별건.
- **SIBF 도면 재작성** — 개략도인 걸 알지만 이번에 안 건드린다.
- **거리·도보시간 표시** — `unitsPerMeter`가 열어주는 기능이지만 별건.
- **부스 enrichment 저작** — 요약·근거·굿즈는 개막 후에도 채울 수 있다.

## 미해결

- **부스별 상세 정보가 없다.** 명단에 코드·국문명·영문명뿐이고 소개·인스타·이미지가
  없다. SIF는 ocreo API에서 가져왔지만 여기는 출처가 없다. 지도·목록·검색은 성립하되
  부스 상세는 빈약하다. 개막 전 브랜드별 인스타를 수집할지는 별도 결정.
- **운영 DB 반영 경로.** 지오메트리는 코드의 `FLOORPLANS`가 이기므로 배포로 끝나지만,
  전시·홀·카테고리·부스 104행은 Supabase에 넣어야 한다. 마이그레이션으로 작성하고
  적용은 사용자가 한다(`supabase/`는 gitignore).
