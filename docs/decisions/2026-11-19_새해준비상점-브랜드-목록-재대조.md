# 새해 준비상점 N.27 브랜드 목록 다시 대조 (2026-11-19)

_2026-11-19 · 헤더 요청으로 진행. 운영 반영은 Ted가 `/admin/intake`에서 한다_

## 무엇을 했나

- 주최 측 사이트를 11-09 수집과 같은 길로 다시 읽었다. 목록 `https://www.newyear-store.com/program/brands?page=1&size=500`에서 `data-id`(주최 측 브랜드 번호)를 뽑고, 상세 팝업이 부르는 `/api/company/{id}`로 브랜드마다 이름, 소개, 분류, 사진 첨부를 받았다. 사이트 표기 "전체 261건"과 받은 수가 같다.
- 브랜드 번호(`ny-{id}` 열쇠)로 레포 파일(251곳)과 Roam-design `official-brands-2026-11-16.csv`(261행)를 맞췄다. CSV와 지금 사이트는 번호 261개가 똑같다.
- `data/brands/newyear-store-2026.json`에 새로 올라온 11곳을 더했다(ny-285, 296, 301, 304~311). 칸을 채우는 방식은 11-09 파일과 같다: 이름 = 사이트 표기 이름(`signNameKo`), 영문 표기와 법인 이름은 `aliases`, 법인 이름이 표기와 다르면 `company`, 소개 = 사이트 `intro` 원문 그대로(`collected`), 분류 = 사이트 분류 이름. 인스타는 넣지 않았다(11-09 파일도 확인된 곳만 넣었고, 이번 11곳은 사이트에 계정이 없다).
- 사진은 11-09처럼 Roam에 내려받았다. 사이트 사진을 긴 변 640px, 로고를 240px webp로 `public/booths/newyear-store-2026/`에 두었고 파일 이름은 `NY{번호}_{순서}.webp`, `logo/NY{번호}.webp`다.
- ny-261 이름을 "어떤웅주"에서 사이트 표기 "어떤우주"로 고쳤다. 열쇠가 그대로라 인입은 같은 브랜드(인스타와 파일 열쇠 둘 다)에 잇고, 새 브랜드를 만들지 않는다. 옛 표기는 `aliases`에 남겼다.

## 왜 이렇게 했나

- 번호로 맞춰야 이름 표기만 바뀐 곳(ny-261, ny-165)을 새 브랜드나 빠진 브랜드로 잘못 세지 않는다.
- brands.v1은 기존 브랜드의 이름을 바꾸지 않는다(`brands-plan.ts`: 기존 브랜드에 이으면 참가 사실과 이름은 그대로 두고 빈 칸만 채운다). 그래서 운영 이름 "어떤웅주"는 이 파일로 안 고쳐진다. Ted가 브랜드 화면에서 고친다.
- 사이트에서 빠진 ny-200 fabric은 파일에서 지우지 않았다. 참가를 지우는 건 Ted 판단이고, 파일에서 지워도 운영 참가 사실은 안 지워진다.
- 이름만 같은 기존 브랜드(뷰릿, 네츄럴굿띵스)는 레포 규칙대로 자동으로 합치지 않았다. Ted가 같다고 확인하면 `exhibitorId`를 적는다(11-10에 16곳을 같은 방법으로 처리했다).

## 고치지 않고 남긴 것

- 이미 운영에 들어간 브랜드의 소개, 분류, 사진이 사이트에서 바뀐 곳(소개 3, 분류 5, 사진 5)은 파일을 그대로 두었다. 인입은 빈 칸만 채우므로 파일을 바꿔도 운영 값은 안 바뀐다. 목록은 PR 본문에 있다.
- `data/intake/_review/newyear-store-2026.json`(부스 번호가 나오면 쓰는 intake.v1 초안)은 이번에 손대지 않았다. 부스 번호가 나오면 사이트에서 다시 만든다.

## 버린 방법

- CSV의 인스타 계정을 새 11곳에 넣기: 인스타가 같으면 기존 브랜드에 자동으로 이어지는데, 뷰릿은 CSV 계정이 운영 브랜드 계정과 같아 사람 확인 없이 합쳐진다. 사람이 확인하는 이름만 같음 단계를 건너뛰게 된다.
- 이름으로만 대조: 표기만 바뀐 곳을 추가와 삭제로 잘못 센다.
