# 브랜드 먼저 인입(brands.v1)

_2026-11-10. 결정: Ted("브랜드가 우선이다"). 구현 판단은 아래에 근거와 함께 적는다._

## 무엇을 바꿨나

- `/admin/intake`가 `brands.v1` 파일도 받는다. 파일 `version`으로 가른다(1이면 부스 `intake.v1`, `"brands.v1"`이면 브랜드).
  - 형식 `src/lib/intake/brands-schema.ts`, 계획(순수) `src/lib/intake/brands-plan.ts`, 적용 `src/lib/intake/brands-apply.ts`.
- 부스 연결(`src/lib/exhibitor/plan.ts`)에 규칙 하나를 더했다: 부스가 인스타나 도메인으로 안 맞으면, **같은 행사**에
  부스가 아직 없는 참가 사실의 표기 이름(또는 aliases)과 이름 키가 정확히 같을 때 그 참가 사실에 배정한다.
- 워커(`src/lib/brands/draft.ts`)는 원문만 있는 공식 소개(collected, display 없음)에 말투 변환본을 채운다.

## 왜

부스 번호는 행사 직전에야 나오는데, 참가 브랜드 명단과 소개, 인스타는 그보다 훨씬 먼저 공개된다(새해 준비상점 251곳이
그 예). 지금 구조는 exhibitor가 부스에서만 생겨서, 명단이 먼저 나와도 브랜드 칸(소개, 링크, 사진)을 채울 수 없었다.
브랜드를 먼저 넣어 두면 카드뉴스와 브랜드 프로필 작업이 부스 번호를 기다리지 않는다.

## 규칙

| 상황 | 동작 | 근거 |
|---|---|---|
| 인스타나 도메인이 기존 브랜드와 겹침 | 그 브랜드를 쓴다 | identity.ts 하나뿐인 판정(설계 2026-10-02 §4) |
| 이름만 같음 | 새로 만들고 미리보기에 "이름 같은 기존 브랜드"로 보여 준다 | 0040 원칙, "분주" 사례 |
| 파일에 `exhibitorId`를 적음 | 그 기존 브랜드에 잇는다. 없는 id거나 인스타·도메인이 다른 브랜드를 가리키면 오류 | 미리보기의 이름 일치를 사람이 보고 확정하는 자리. 자동 병합이 아니다 |
| 파일 안에서 인스타나 도메인이 같음 | 하나로 묶는다(먼저 나온 항목이 대표, 나머지 이름은 aliases) | 같은 판정 |
| 인스타와 도메인이 서로 다른 기존 브랜드 둘에 맞음 | 오류로 돌려주고 건너뛴다 | 어느 쪽인지 사람이 골라야 한다 |
| `exhibitionSlug` 있음 | 참가 사실을 만든다(display_name, aliases, source_urls, metadata.brandKey). 이미 있으면 건너뛴다 | |
| `exhibitionSlug: null` | 참가 사실 없이 브랜드만 | |
| 프로필 칸 | intro, links, photos를 **비어 있을 때만**. 상태와 무관하게 값이 있으면 그대로 | intake.v1 "빈 칸만 채운다" |

- **멱등**: 새로 만든 브랜드의 `exhibitor.metadata.brandKeys`에 `brands.v1:<행사 slug 또는 출처 URL>#<key>`를 남긴다.
  다시 돌리면 이 키를 신원 키처럼 써서(`brandKeyIdentity`) 같은 브랜드를 찾는다. 인스타도 사이트도 없는 브랜드가
  중복으로 생기지 않게 하려는 것이다.
- **칸 상태**: intro는 파일이 준 상태(collected 또는 artist_confirmed), 출처는 `intro.source`. links와 photos는 collected,
  출처는 `source.url`. `adminStatusError`(collected는 `roam:booth/` 출처만)는 관리자 손 저장용이라 이 경로엔 걸지 않는다.
  이 경로는 공식 명단을 그대로 옮기는 시스템 경로라, 출처를 명단 URL로 남기는 쪽이 사실에 맞다.
- **말투 게이트**: 원문만 넣는다(`{ original }`). 기존 fields 라우트와 워커도 display가 없으면 게이트를 돌리지 않고 원문만
  둔다. 앱은 display만 보이므로(`publicValue`) 이 상태의 소개는 아직 앱에 안 보인다. 워커가 다음 초안 잡에서
  원문과 출처를 그대로 둔 채 display와 게이트 결과를 채운다(통과 collected, 실패 ai_draft). 작가 확인 소개는 건드리지 않는다.
- **이력**: change_log에 source `"intake"`로 남긴다. 엔티티는 `exhibitor`, `exhibition_participant`(새로 추가), `brand_profile_field`.
  프로필 칸 이력은 before가 비어 있어 검수 학습(`lessons.ts`, before가 ai_draft인 것만)에 섞이지 않는다.
- **뒤처리**: 기존 브랜드에 이 행사 출전이 새로 이어지면 부스 인입과 같이 stale 표시와 초안 잡을 한다(`lib/brands/jobs.ts`).
  부스가 나중에 들어올 때는 참가 사실이 이미 있어 "새 출전"으로 안 보이므로 지금 해야 한다.

## 부스가 나중에 들어오면

부스 인입(`intake.v1`) 뒤 `planFromRepository`가 연결한다. 순서:

1. 인스타나 도메인이 맞는 기존 브랜드
2. 같은 행사에 부스 없는 참가 사실과 이름 키가 같음 → 그 참가 사실에 배정. 한 부스 이름이 두 브랜드에 맞거나, 인스타로
   묶인 여러 회차 부스가 서로 다른 브랜드에 맞으면 고르지 않는다.
3. 아니면 새 브랜드 + 다른 행사 동명 참가사는 연결 후보

같은 행사 이름 일치를 자동으로 받아들이는 이유: 같은 주최 명단 한 장에서 온 이름끼리라, 다른 행사 사이의 동명이인
(2026-10-01 "분주")과 경우가 다르다. 2로 이은 뒤에도 다른 행사의 동명 참가사는 후보로 계속 낸다 — 브랜드 먼저
인입이 새로 만든 브랜드가 사실은 지난 회차의 그 브랜드일 수 있고, 후보 승인(`/admin/brands/links`)이 둘을 합친다.

## 버린 방법

- **브랜드 전용 API와 화면을 따로 만들기**: 데이터 경로는 `/admin/intake` 하나라는 규칙을 깬다. 미리보기 뒤 적용,
  빈 칸만 채움, 이력 원장을 두 벌 유지하게 된다.
- **행사별 스크립트나 손 UPSERT로 넣기**: 레포 규칙 위반. 다시 돌릴 수 없고 이력이 안 남는다.
- **intake.v1에 부스 코드 없는 행을 허용**: 부스는 좌표를 도면에서 code로 받는다. code 없는 부스는 지도에 못 뜨는
  가짜 부스가 되고, 계획(`plan.ts`)의 모든 판정이 code를 자연키로 쓴다.
- **이름이 같으면 기존 브랜드에 자동 병합**: 0040 원칙과 "분주" 사례로 이미 버린 방법이다. 미리보기 목록으로만 보여 준다.
- **"이름 같은 기존 브랜드"를 연결 후보 테이블에 바로 넣기**: `exhibitor_link_candidate.booth_id`가 not null이라 부스 없는
  브랜드는 후보가 될 수 없다. 마이그레이션 없이 가려고 미리보기 목록 + 부스가 들어온 뒤 후보로 미뤘다.
- **파일 키를 참가 사실 metadata에만 두기**: 행사가 없는 파일(`exhibitionSlug: null`)은 참가 사실이 없어 다시 돌릴 때
  찾을 곳이 없다. 그래서 브랜드(exhibitor.metadata.brandKeys)에 둔다. 참가 사실의 `metadata.brandKey`는 추적용이다.

## 마이그레이션

없다. 0040의 `exhibitor.aliases`, `legal_name`, `metadata`와 `exhibition_participant.aliases`, `source_urls`, `metadata`를 그대로 쓴다.
`change_log.entity`는 text라 새 엔티티 이름도 마이그레이션이 필요 없다.

## 파일 위치

- 레포에 남기는 brands.v1 파일은 `data/brands/`에 둔다. `data/intake/`는 intake.v1 계약 검사(`data-files.test.ts`)가 훑는 자리라 섞지 않는다.
- `data/brands/newyear-store-2026.json`: 주최 측 사이트 251곳. 이름만 같은 16곳은 Ted 확인(2026-11-10)으로 `exhibitorId`를 적었다.
- `data/brands/moongu-artists-2026-winter.json`: 문구전 사진 허락 DM에 답한 작가 7팀. 행사가 아직 없어 `exhibitionSlug: null`.
- 새해 준비상점 부스 파일은 도면이 없어 `data/intake/_review/`로 옮겼다. 부스 번호와 도면이 나오면 되돌린다.
