# 웹 박람회 지도 돌리기 (2026-11-23)

**결정한 사람**: Ted ("회전 되게 해줘. 모든 지도맵 처럼 동일하게"). 원문과 범위는 Roam-design
`docs/decisions/2026-11-23_지도-돌리기.md`. iOS는 따로 같은 작업을 한다.

## 바꾼 것

- **카메라에 각도**: 내용 좌표를 "도면 가운데 축으로 돌린 뒤 돌린 도면을 감싸는 축 정렬 상자의 왼쪽 위를 0으로"
  정의했다(`map-camera.ts` `toContent`, `footprint`). 그래서 맞추기와 가두기 식은 각도와 상관없이 그대로 쓰고,
  전체 보기, 홀 맞춤, 부스 맞춤은 돌린 상자 크기로 맞춘다. 0도에서는 예전과 숫자가 같다.
- **누르기 판정**: 화면 점을 `screenToWorld`로 도면 점으로 돌리고 `pointInRect`로 판정한다(칸 자체 각도도 따진다.
  예전엔 칸 각도를 무시했다).
- **두 손가락**: 확대, 이동, 돌리기가 한 손짓이다. 손가락 가운데 아래 도면 점이 손가락을 따라간다(`cameraKeeping`).
  손가락 선이 12도 넘게 기울어야 돌기 시작하고, 넘은 자리부터 돈다(확대하다 지도가 도는 것을 막는 입력 폭).
- **관성**: 끌기에만 붙는다. 확대와 돌리기는 손 뗀 자리에 멈춘다. 지금 웹 확대와 iOS(973aa3f "관성은 팬에만 붙는다")와 같다.
- **글자와 표식은 바로 선다**: 이름, 번호, 하트, 다녀온 체크, 출입구와 화장실 표식, 길 안내 이름표. 층은
  `data-upright`(축과 칸 각도)만 달고, 엔진이 각도가 바뀔 때 그 요소에만 SVG `transform`을 적는다.
  멈춘 각도가 90도 쪽이면 칸의 가로세로가 화면에서 바뀌므로 이름표를 바꾼 가로세로로 나눈다(`labelQuarter`,
  멈출 때만 React가 바뀐 칸만 다시 그린다). 웹 v2 지도에는 홀 이름표가 없다(홀 바닥판만 그린다).
- **나침반 단추**: 돌린 동안만 홀 버튼 옆에 나온다. 누르면 짧은 쪽으로 0도로 돌아오고, 화면 가운데 도면 점을 축으로
  map-move 토큰 길이와 곡선으로 돈다. 홀 버튼과 같은 틀(v2 토큰만), Lucide `Compass`, 바늘이 지도 위쪽을 가리키게 돈다.
  문구 `label.mapOrientationReset` "지도 방향 되돌리기"(iOS 설정 줄 "지도 방향"과 맞춤). 이벤트 `map_control` `control: "compass"`.
- **"전체"(홀 버튼)는 각도를 그대로 둔다**. 다른 지도 앱처럼 방향을 되돌리는 건 나침반 하나다. 예전 v1 "전체 보기"는 0도로 돌렸다.
- 처음 열 때는 0도(배치도 방향). 부스 상세에 갔다 돌아오면 예전처럼 보던 자리를 되살리고 각도도 되살린다.

## 데스크톱 돌리기

- **오른쪽 단추 끌기, Ctrl 끌기**: 가로 1px에 0.8도, 화면 가운데를 축으로. 구글 지도 웹(Ctrl 끌기)과 Mapbox GL,
  MapLibre(오른쪽 단추 끌기와 Ctrl 끌기, `bearingDegreesPerPixelMoved` 0.8)와 같은 방식이다. 지도 위 오른쪽 클릭 메뉴는 막는다.
- **사파리 맥 트랙패드 비틀기**: 사파리만 `gesturechange.rotation`을 준다. 손가락이 지도에 닿아 있지 않을 때만 쓴다
  (iOS 사파리는 터치 핀치에도 gesture 이벤트를 보내므로 두 번 돌지 않게).
- 버린 안: Shift나 Alt 끌기(널리 쓰는 웹 지도 기본이 아니다), 크롬 트랙패드 회전(크롬은 회전 값을 웹에 주지 않는다).

## 성능 (SIF 목 데이터 914칸, SVG 요소 5,735개, 프로덕션 빌드, 헤드리스 크롬, 손짓 60번)

| 방식 | 두 손가락 이동 | 두 손가락 돌리기 |
|---|---|---|
| 처음 시도: SVG 뿌리에 각도 CSS 변수, 글자가 `rotate(var())` | 스타일 97ms | 스타일 3,176ms(손짓당 약 53ms) |
| 지금: 바로 세울 요소에만 transform 속성 | 스타일 76ms | 스타일 444ms(손짓당 약 7ms) |

- 상속되는 변수를 바꾸면 지도 요소 전체의 스타일을 다시 계산해서 버렸다.
- 레이아웃 시간은 이동과 돌리기가 비슷했다(각 2초 안팎). 돌리기 때문에 생긴 비용이 아니다.
- 멈출 때 이름표 사분면이 바뀌는 순간: 스크립트 5ms, 스타일 7ms, 레이아웃 15ms.
- 이동과 확대만 할 때는 각도가 그대로라 글자를 건드리지 않는다.
