# 웹 지도: 카메라를 한 루프로, 손 뗀 뒤 관성, 부스 층 메모, 라벨 단계

_2026-11-21. 브랜치 `fix/map-smoothness`. 근거: Roam-design `docs/research/2026-11-21_메가주-3D-부스지도-분석.md`의 "웹" 절,
Ted 11-21 "지도 매끄러움 = 메가주 기준"._

## 원인 (코드로 다시 확인)

- `exhibition-map.tsx` `applyView`: 프로그램 이동(부스로 가기, 홀 바꾸기, 전체 보기, 확대 버튼)이 전부 CSS
  `transition: transform 220ms ease-out`. 220ms와 ease-out은 토큰이 아니고, 진행 중에 새 이동이 오면 전환이 겹친다.
  회전이 섞이면 CSS가 함수별로 보간해 길이 휜다. 배율도 덧셈으로 보간해 확대가 끝에서 느려 보인다.
- 손을 떼면 그 자리에서 멈춘다(`onPointerUp`에 속도 없음).
- 엔진이 다시 그려질 때마다 `renderLayer(ctx)`를 새로 불렀다. 화면(`fair-map-screen.tsx`)의 `renderLayer`, `routeOverlay`가
  렌더마다 새 값이고 `geomOf`, `hallRegions`, `upright`도 새 함수와 배열이라, 홀 버튼 하나에 부스 수백 칸의 이름 줄바꿈
  (`layoutBoothLabel`)을 전부 다시 계산했다.
- 화면 쪽 `useEffect([insets.top, insets.bottom])`가 카드가 뜨면 같은 부스로 `focusRect`를 한 번 더 불러 이동이 둘 겹쳤다.
- SVG에 늘 `will-change: transform`. 브라우저가 처음 그린 비트맵을 키워 보여 확대 뒤 글자가 흐릴 수 있다.
- 라벨은 배율과 관계없이 늘 그려져 멀리서 뭉갰다.

## 바꾼 것

1. **카메라 한 곳**(`map-camera.ts`, `exhibition-map.tsx`): 목표 카메라(`view`, `rotationRef`)와 화면에 보이는 카메라(`shown`)를 나눴다.
   이동 요청은 requestAnimationFrame 루프 하나가 지금 보이는 자리에서 목표까지 보간한다. 배율은 곱셈으로, 위치는 두 카메라의
   고정점을 축으로 같은 진행도에 묶어 화면 위 모든 점이 곧은 선으로 간다(단위 테스트). 길이와 곡선은
   `--roam-v2-motion-map-move-duration`(d6, 300ms), `--roam-v2-motion-map-move-easing`을 계산된 스타일에서 읽는다.
   동작 줄이기면 즉시(토큰 reduceMotion). CSS transition은 지웠다.
2. **손 뗀 뒤 관성**(11-21 Ted B안, Roam-design `docs/decisions/2026-11-21_지도-관성-감속.md`): 마지막 100ms 포인터 표본으로 속도를 재고,
   그 속도로 출발해 v(t) = v0·e^(−t/τ)로 감속한다. τ는 `--roam-v2-decay-map-fling-tau`(250ms)이고 끝까지 가면 v0·τ(초속 2000pt면 약 500pt).
   map-move(300ms)와 묶지 않는다. 지도 끝을 넘으면 그 자리에서 안쪽으로 정착한다. 동작 줄이기면 관성 없이 그 자리에 멈춘다.
   움직이는 중에 손이 닿으면 그 자리에서 잡는다. 휠과 트랙패드 확대는 커서 지점이 고정점이다(전과 같음, 진행 중 이동은 끊는다).
   감속과 곡선 이동은 같은 requestAnimationFrame 루프 하나가 돈다.
3. **부스 층 메모**: 엔진이 도면 상자, 홀 바닥판, `upright`, 층 입력(ctx)과 층 요소를 메모한다. 화면은 `renderLayer`와 `routeOverlay`를 메모한다.
   `MapLayerV2`와 칸 하나(`BoothCell`)는 `memo`라 선택이나 하트가 바뀌면 그 칸만 다시 그린다. 카메라는 transform 하나만 바꾼다.
   **여백**: 화면 쪽 두 번째 `focusRect`를 지우고, `focusRect(r, { keepWhileSelected: id })`로 엔진이 맡는다. 그 부스가 선택된 동안 여백이 바뀌면
   진행 중인 이동의 목표만 바꿔(시작 시각과 출발점은 그대로) 한 번의 이동으로 끝난다. 크기 변화로 다시 가둘 때도 진행 중이면 목표만 바꾼다.
   `will-change`는 움직이는 동안만 켠다.
4. **번호 줄 단계**: 칸 **번호**가 화면에서 `font-size-t1`(v2 글자 눈금의 가장 작은 값, 11px. `map-entry.ts`의 "코드가 11px보다 작으면 읽히지 않는다"와 같은 값)
   보다 작아지는 배율에서 숨는다. 배율 2배를 4단계로 나눠, 단계가 바뀔 때만 엔진이 SVG에 `--map-zoom-level`을 적고, 번호는 opacity로
   `--roam-v2-motion-map-level-*`(d4, easing) 동안 잇는다. **이름은 어떤 배율에서도 숨기지 않는다**(2026-10-15 결정, 11-21 Ted 다시 확인 —
   처음엔 이름도 숨겼다가 같은 날 되돌림). 하트와 다녀온 체크는 늘 보인다.

## 토큰 선택

- **경계 밖에서 안으로 정착하는 곡선**: 토큰은 `spring.settle`이지만 웹 근사가 미정이다. 대신 `--roam-v2-easing-enter`(0, 0, 0.15, 1)를
  map-move 길이(300ms)로 쓴다. 감속 곡선이라 넘은 자리에서 바로 안쪽으로 출발해 서서히 멈춘다. settle의 웹 근사가 정해지면 바꾼다.
- 처음(첫 커밋)에는 관성이 map-move 300ms에 묶여 초속 2000pt로 튕겨도 약 90pt만 갔다. `decay.map-fling` 토큰이 생겨 떼어 냈다.
- 경계에서 고무줄처럼 늘어나는 끌기 저항값은 토큰에 없어 넣지 않았다. 끌기는 전처럼 경계에서 멈춘다.

## 디자인 값이 아닌 숫자

- 속도 표본 폭 100ms(입력 거르기), 감속이 멈췄다고 보는 남은 거리 0.5px(화면 반올림), 라벨 단계 4단계/2배(스타일 재계산 횟수), 휠 확대 간격(전과 같음).
- `--map-zoom-level`은 엔진 상태 변수라 v2 토큰이 아니다. v2 가드(`var(--roam-v2-*)`만)를 지키려고 그 변수를 쓰는 스타일은 엔진 쪽 `map-camera.ts`의
  `labelFadeStyle`이 만든다.

## 고르지 않은 방향

- CSS transition을 토큰 값으로만 바꾸기: 겹친 전환과 휘는 길, 손 뗀 속도 이어받기가 그대로 남는다.
- framer-motion 같은 라이브러리로 카메라 보간: 이미 의존성에 있지만 SVG transform 하나를 매 프레임 쓰는 일에 비해 무겁고, 진행 중 목표 바꾸기를 직접 다뤄야 하는 건 같다.
- three.js `MapControls`로 옮기기(분석 문서 가설): 2.5D, 3D까지 갈 때 맞는 길이지만 SVG 층을 통째로 바꿔야 한다. 이번엔 지금 층 위에서 고쳤다.
- 번호 숨김을 JS로 칸마다 계산: 배율이 바뀔 때마다 칸 수백 개를 다시 그리게 된다. CSS 변수 하나로 브라우저에 맡겼다.
