## 무엇을 했나

- 관리자 `/admin/brands/contacts`를 새로 만들었다. 박람회 하나의 출전 브랜드에 연락한 현황을 한 화면에서 본다.
  - 위쪽: 상태 깔때기 아홉 칸과 쌓인 막대, 오늘 할 일 세 칸(보낸 지 7일 넘게 답 없음, 답장 왔는데 처리 전, 수정이나 내려 달라는 요청)
  - 표: 브랜드, 부스 번호(있을 때만), 인스타 프로필과 DM 열기, 상태 칩, 보낸 지 며칠, 마지막 기록, 허락 범위
  - 거르기(상태, 계정 유무, 계정 출처, 할 일), 이름 찾기, 정렬
  - 한 번 누르기: 상태 바꾸기, 여러 곳 골라 "보냄으로 표시", "DM 문구 복사"(박람회 문안에 브랜드 이름과 품목을 채움)
  - 키보드: `/` 찾기, j/k 이동, x 고르기, c 문구 복사, s 보냄, o 인스타 열기, Enter 자세히, 1~9 상태
- 인스타 계정 csv 가져오기. 먼저 미리 보기로 채움, 같음, 충돌, 계정 없음, 못 찾음, 여러 곳 걸림을 보여 주고, "적용"을 눌러야 빈 칸만 채운다. 충돌은 덮지 않는다. 자동으로 돌지 않는다.
- 연락 패널(브랜드 상세 연락 탭과 보드의 "자세히")을 입력칸 없이 고쳤다. 아래 표 참고.

## 왜 이렇게 했나

### 입력칸 줄이기

| 예전 입력칸 | 이제 값이 오는 곳 |
|---|---|
| 상태(선택) | 정해진 목록이라 칩 버튼 |
| 보낸 날짜(입력) | "보냄"을 누른 날(서울 기준 오늘). 고치기는 예외일 때만 |
| 채널(선택) | 계정 모양에서 추론(@는 인스타, 메일 주소는 메일) |
| 계정(입력) | 부스 링크, 브랜드 프로필, csv 가져오기에서 미리 채우고 "이 계정으로 확정" |
| 답 요지(입력) | 받은 연락 버튼(답장 받음, 허락 관련 답장, 수정 요청, 내려 달라는 요청)으로 기록. 요지는 선택 |
| 허락 범위 | 원래 칩. 누르면 바로 저장 |
| 사진과 글 위치(입력) | 선택, 접어 둠 |
| 메모(여러 줄) | 내부 메모 기록 한 줄로 바꿈. 옛 메모는 읽기만 |
| 체크리스트 | 스위치. 누르면 바로 저장 |
| VOC 방향, 종류, 채널(선택) | 누른 버튼에서 정해짐 |
| VOC 요약(필수 입력) | 동작에서 문장을 만든다("보냄으로 표시", "상태 바꿈: 보냄 → 허락") |
| VOC 시각(입력) | 지금 |
| 저장 버튼 | 없앰. 누를 때마다 저장하고 기록이 같이 남는다 |

자주 하는 일(보냄 표시, 상태 바꾸기, 허락 범위)은 글자를 하나도 치지 않는다. 남은 입력은 받은 말 요지, 내부 메모, 다른 계정 적기, 날짜 고치기, 사진과 글 위치이고 전부 선택이다.

### 보내는 이는 Roam

`OUTREACH_SENDER`(src/lib/constants.ts)에 인스타 `withromi.con`, 메일 `roam.ai.kr@gmail.com`을 둔다. 메일 주소는 약관과 개인정보 처리방침의 연락처와 같다. 이 화면은 보내지 않는다. DM은 문구 복사와 DM 열기, 메일은 mailto 초안까지만 한다.

### 연락의 열쇠 둘: 브랜드와 출전

부스 번호는 어디서도 요구하지 않는다(새해 준비상점은 부스 없이 브랜드부터 들어왔다). 보드의 한 줄은 출전(브랜드 × 박람회)이다.

- 계정, 연락 금지, 오간 말: 브랜드 하나에 모인다(다음 박람회에도 이어진다)
- 상태, 보낸 날, 허락 범위, 체크: 출전마다 따로

저장 자리는 `src/lib/brands/outreach-store.ts` 한 곳이 고른다. 화면과 API는 participantId만 말한다.

- participant(목표): 스키마 정규화 감사(`docs/decisions/2026-11-17_스키마-정규화-감사.md`, 브랜치 docs/schema-normalization) 초안의 `brand_outreach`, `brand_outreach_log`, `participant_permission`. mock은 늘 이쪽이다.
- booth(폴백): 0061 `brand_contact`(부스 키). 그 테이블이 운영에 없으면 이쪽으로 돈다. 부스 없는 출전은 읽기만 되고, 연락 금지는 저장하지 않는다.

이 브랜치에는 마이그레이션이 없다. 목표 테이블은 위 초안 STEP 1이 운영에 들어갈 때 생긴다. 그 전에는 저장소가 테이블이 없음을 확인하고 부스 키로 돈다.

### csv 계정은 브랜드 프로필 links 칸에

계정은 브랜드에 붙는 사실이라 박람회 보드가 아니라 브랜드 프로필 `links` 칸에 쓴다. 다른 링크는 그대로 둔다. 계정 확실도(확실, 높음, 후보)는 칸이 없어 출처에 `handle-confidence:<값>` 표식으로 남기고, 후보는 칸 상태를 stale로 둔다. 쓸 때마다 change_log에 남긴다.

## 버린 방법

- **부스 키 brand_contact에 새 칸을 더하는 마이그레이션:** 부스 없는 출전 251곳을 담지 못한다. 정규화 초안과 겹치는 테이블이 하나 더 생긴다.
- **보드가 부스 목록을 줄로 쓰기:** 부스 번호 전 브랜드가 사라진다.
- **csv를 바로 적용:** 동명이나 오타로 다른 브랜드 계정을 덮을 수 있다. 미리 보기와 빈 칸만 채우기로 막았다.
- **보드에서 DM 자동 발송:** Ted 결정으로 보내기는 사람이 한다. 로그인 계정 자동화는 인스타 계정 제한을 부른다.
