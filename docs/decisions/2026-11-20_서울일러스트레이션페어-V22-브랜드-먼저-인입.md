# 서울일러스트레이션페어V.22 브랜드 먼저 인입

_2026-11-20. 결정: Ted("브랜드 먼저 넣어"). 구현 판단은 아래에 근거와 함께 적는다. 순서와 명령: `docs/runbooks/sif-2026-winter-brands.md`._

## 무엇을 했나

- 경로는 새해준비상점, 문구전, 서울디자인페스티벌과 같다: 행사 행(`data/exhibitions/`) + brands.v1(`data/brands/`) + 출처별 생성기(`scripts/brands-from-sif.ts`, 변환은 순수 `src/lib/intake/sif-official.ts`).
  운영 반영은 `/admin/intake` 하나다. 새 마이그레이션 없음.
- 입력은 Roam-design `docs/content/engine/runs/sif-2026-v22/`의 오크레오 공식 참가자 목록(964줄, 분류와 이름)과 V.21 이름 대조. 생성기는 네트워크를 타지 않는다.

## slug: `sif-2026-winter`

같은 해 두 번째 회차는 계절을 붙인다(`moongu-2026-winter`). V.21이 `sif-2026`(2026-07-30)이라 V.22(12-24)는 `sif-2026-winter`.
회차 번호(`sif-2026-v22`)는 버렸다: 레포의 다른 행사 slug에 회차 번호를 쓴 예가 없고, V.21에 번호가 없어 둘이 짝이 안 맞는다.

## V.21과 잇는 방법

| 대조 | 처리 | 근거 |
|---|---|---|
| 같은 이름 | V.21 부스의 인스타, 웹, 소개 원문을 적는다 → 운영 V.21 브랜드에 인스타, 도메인으로 이어진다 | brands.v1 규칙: 이름으로 합치지 않고 신원 키로 잇는다 |
| 같은 이름인데 V.21 링크 없음 | 이름만 같음 → 미리보기 보고서로 기존 브랜드가 하나뿐이면 `exhibitorId`를 적는다(`--name-matches`) | 새해준비상점 때 사람이 id를 적던 일을 보고서에서 한다. 둘 이상이면 사람이 고른다 |
| 짧아서 확인, 비슷한 이름 | 오크레오 프로필 대조 판정(같은 작가/다른 작가/모름)을 따른다. 판정 전이면 파일에서 뺀다. 11-20 대조: 같은 작가 102, 다른 작가 3 | 새 브랜드로 넣었다가 같은 작가로 밝혀지면 브랜드가 둘이 된다 |
| 같은 작가인데 V.22 프로필 인스타가 다름(브르, 서로, 히밍) | V.22 인스타를 적고 V.21 웹으로 잇는다. 런북의 확인 대상 | 페어 이력으로 같은 작가. 인스타는 V.22 쪽이 최신이라 V.21로 덮지 않는다 |
| 새 참가 | 새 브랜드 | |

- 파일 키는 `sif22-<이름>`. 명단 순서가 바뀌어도 같은 브랜드를 찾는다. 오크레오에 같은 이름 작가가 둘인 카드(결, 이륙)는 프로필 대조 줄과 짝지어 `sif22-<이름>-<프로필 id>`로 따로 넣었다. 대조 줄이 모자라면 명단 중복으로 보고 하나만 넣는다.
- 소개는 작가가 오크레오 프로필에 쓴 원문 그대로다(브랜드 규칙 §1 예외, 2026-11-09). 말투 변환은 워커가 한다. Roam이 쓴 문구는 행사 행 설명과 안내뿐이고 해요체, 가운뎃점 없음.
- 참가 구분(국내 작가, 국내 기업, 해외 작가, 해외 기업)은 참가 사실 `metadata.category`, `participationType`에 남긴다.

## 링크 모음 서비스로 뭉친 V.21 브랜드에 잇는 82곳은 뺐다

`identity.ts`는 link.inpock.co.kr, instabio.cc, grafolio.ogq.me, marpple.shop, threads.net, linkon.id, linkseller.net, twenty.style,
picturebook-illust.com, youtube.com/channel 등을 계정 단위로 나누지 못한다. 하위 도메인은 테넌트로, 나머지는 도메인 이름 하나로 본다.
mock에서 V.21 부스를 백필하면(운영 0063과 같은 판정) 서로 다른 작가가 브랜드 하나로 묶인다: "러브미모어" 아래 27곳, "무운" 17곳, "달콤한 일러스트" 13곳 등.
여기에 V.22를 이으면 V.22 작가도 남의 브랜드에 붙는다. 그래서 V.21 링크가 그렇게 뭉치는 부스(`v21MergedCodes`)에 잇는 82곳(같은 이름 56, 프로필 대조로 같은 작가 26)은 파일에서 뺐다.

- **가설**: 운영 V.21 브랜드도 같이 뭉쳐 있다. 운영 DB를 보지 않았다. 미리보기의 "이음 … → <기존 이름>" 줄로 확인한다.
- 고칠 것(이 PR 밖, Roam #208): identity.ts에 이 서비스들을 계정 단위로 넣고, 운영에서 뭉친 브랜드를 가른다. 생성기의 보류 판정도 identity.ts를 쓰므로 그 뒤 다시 돌리면 82곳이 들어간다.
  #208 위 mock 미리 계산: 82곳 → 81묶음 모두 V.21에 이음, 새 브랜드 0(융과 요즘강아지 덕구는 같은 작가라 한 묶음).

## 버린 방법

- **V.21 이름이 같으면 exhibitorId를 바로 적기**: 운영 id를 알려면 운영을 조회해야 하고, 이름만 같은 다른 작가를 막을 수 없다(0040, "분주" 사례).
- **확인 필요한 곳을 새 브랜드로 일단 넣기**: 같은 작가면 브랜드가 둘이 되고, 연결 후보 승인으로 합칠 때까지 남는다.
- **링크 모음 서비스 주소만 빼고 인스타로 잇기**: 운영 V.21 브랜드가 이미 뭉쳐 있으면 인스타로도 그 뭉친 브랜드에 붙는다.
- **identity.ts를 이 PR에서 고치기**: 품질 게이트와 부스 연결이 같이 쓰는 판정이고, 고치면 운영의 뭉친 브랜드를 가르는 일이 같이 따라온다. 데이터 준비와 섞지 않는다.

## 확인

- mock 끝까지(`src/lib/intake/sif-2026-winter.test.ts`): V.21 백필 → 행사 행 → 미리보기 → 적용 → 다시 돌림. 새 브랜드 569, V.21에 이음 313(모두 V.22 이름이나 V.21 표기와 같음), 참가 882, 같은 이름 다른 작가는 브랜드도 따로,
  한 브랜드에 이 행사 참가 하나, 다시 돌리면 새로 0, 목록 `openable: false`, `availability: "upcoming_no_map"`.
- 운영 dry-run은 하지 않았다(운영 조회 금지). Ted가 런북 2단계에서 한다.
- `mapWidth`, `mapHeight`는 V.21 C홀 도면 값이다. 배치도가 나오면 도면 JSON과 같이 맞춘다.
- 코엑스 C홀 층은 적지 않았다. V.21 시드는 "C홀은 코엑스 1층"이라 했는데 확인하지 못했다.
