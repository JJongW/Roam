# 참가사 부스 정보 제출 양식

> **참가사(브랜드)가 직접 자기 부스 정보를 채우는 양식.** 주최 측을 거치지 않는다.
>
> 이 문서는 두 가지로 쓰인다:
> 1. 지금 당장 — 그대로 복사해 브랜드에 보내는 양식
> 2. 나중에 (롤아웃 Phase 6) — Roam 자체 디자인으로 만들 웹 폼의 필드 명세
>
> 대응 코드: `RawBooth` + `BoothEnrichment` 6종 필드
> (→ `docs/admin-automation-architecture.md` §5, `docs/booth-enrichment.md`)

---

## 설계 원칙

**5분 안에 끝나야 한다.** 브랜드 담당자는 전시 준비로 바쁘고, 길면 그 자리에서 닫는다.
그래서 필수는 4개뿐이고 나머지는 전부 선택이다. **비어 있어도 부스는 올라간다** —
Roam이 공개 정보로 초안을 만들고 우리가 검수한다. 이 양식은 *더 정확하게 만드는 수단*이지
*없으면 멈추는 관문*이 아니다.

**브랜드에게 뭐가 좋은지를 먼저 말한다.** 부탁이 아니라 제안이어야 채워진다.

# 📮 브랜드에 보내는 양식 (여기부터 복사)

## Roam에 부스를 소개해 주세요

안녕하세요. **Roam**은 전시·박람회 관람객이 *어떤 부스가 자기에게 맞는지* 판단하도록 돕는 서비스입니다.

관람객은 Roam에서 부스를 미리 보고 "꼭 갈래 / 끌려 / 패스"를 정한 뒤 현장에 옵니다.
**아래 정보를 채워 주시면, 우리 부스가 그 관람객에게 정확히 소개됩니다.**

### 채워 주시면 이렇게 됩니다

| | |
|---|---|
| 🎯 | **맞는 관람객에게 노출됩니다.** 굿즈를 찾는 사람, 제작 과정이 궁금한 사람 — 취향이 맞는 관람객에게 먼저 보입니다 |
| 📊 | **전시 종료 후 리포트를 드립니다.** 몇 명이 우리 부스를 봤고, 몇 명이 실제로 왔고, 반응이 어땠는지 |
| ⏱️ | **5분이면 됩니다.** 필수는 4개뿐이고, 나머지는 아는 만큼만 |

# 🔧 폼 구현 노트 (내부용)

Phase 6에서 이 양식을 Roam 자체 디자인 웹 폼으로 만들 때의 명세.

## 필드 매핑

| 폼 항목 | 저장 위치 | 후처리 |
|---|---|---|
| 1 부스 번호 | `booth.code` | 초대 토큰에서 자동 채움 (수정 불가) |
| 2 브랜드명 | `booth.name` | 기존 값과 다르면 승인 큐에 diff 표시 |
| 3 한 줄 소개 | → `summary` 재료 | Gemini가 로미 보이스로 재작성 → `roamInterpretation` |
| 4 공식 링크 | `officialUrl` · `socialUrl` | `enrichment-drafter`의 `urlContext` 입력으로도 사용 |
| 5 주요 품목 | → `goodsKeywords` | 쉼표 분리 + 정규화 (`normalize.ts`) |
| 6 **이번 전시 특별한 것** | → `summary` · `thingsToDo` | **공개 정보로 대체 불가.** 초안 신뢰도 가중치 ↑ |
| 7 현장 이벤트 | → `things_to_do` · 혜택 | |
| 8 시간 정보 | → `timing_notes` | |
| 9 취향 체크 | → `value_tags` **직접 입력** | 브랜드 자기 인식 vs 실제 반응 비교 가능 ← 흥미로운 지표 |
| 10 자유 메모 | 원문 보관 | 승인 화면에만 표시 |
| 이미지 | Cloudinary + `booth-originals` 백업 | 동의 항목을 `image_consent` jsonb로 함께 저장 |

## 인증

**계정 가입을 요구하지 않는다.** 그 자리에서 이탈한다.

```
부스 코드 + 서명된 초대 토큰 → /intake/{token}
  · 토큰에 exhibitionId + boothCode + 만료 담김 (jose 이미 사용 중)
  · 1회용 아님 — 만료 전까지 재편집 가능 (브랜드가 나중에 추가하도록)
  · 링크는 우리가 브랜드에 직접 전달 (DM·메일)
```

## 제출 후

```
폼 제출 → enrichment_candidate (status: pending, source: 'exhibitor')
        → quality-gate 검증
        → 승인 큐 (모바일)
        → upsertBoothEnrichment
```

**별도 파이프라인이 아니다. 기존 승인 큐의 또 다른 입력구일 뿐이다.**
`source` 필드로 출처를 구분해두면 나중에 "참가사 제출 vs 자동 초안"의 승인 통과율을
비교할 수 있고, 그게 폼을 계속 돌릴지 판단하는 근거가 된다.

## 디자인

`shadcn/ui` + Tailwind v4 + Pretendard, `docs/brand.md`의 로미 보이스.
방문객 앱과 같은 톤이되 **로그인 게이트 밖**(`src/proxy.ts` 예외 경로에 `/intake` 추가 필요).

## 나중에 — 주최 측 일괄 CSV

참가사 폼이 자리 잡고 주최 측과 관계가 생기면, 명단 일괄 업로드를 추가한다.
얕지만(부스번호·이름·카테고리) 한 번에 전부 들어와서 **골격**을 만들고,
참가사 폼이 그 위에 **깊이**를 채우는 2단 구조가 최종형이다.
