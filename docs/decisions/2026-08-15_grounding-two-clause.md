# 근거 카드 2절 분리 — 저작 해석과 가치별 근거를 경쟁시키지 않는다

**날짜**: 2026-08-15
**관련 파일**: `src/lib/feed/grounding.ts` · `src/lib/feed/grounding.test.ts`
**근거 감사**: `docs/qa/2026-08-15_grounding-audit.md` 발견 1

## What — 무엇이 달라졌나

`roamInterpretation`(저작 해석)과 `recommendationReasons`(가치별 저작 근거)가
**같은 자리를 놓고 경쟁하던 것**을 각자의 절로 나눴다.

```
BEFORE   1절 ← roamInterpretation 또는 recommendationReasons (하나만 이김)
         2절 ← 내가 누른 부스 (있을 때만)

AFTER    1절 ← roamInterpretation → 공식 소개 → 테마·굿즈 파생 → 굿즈 → 부스명
         2절 ← 내가 누른 부스 있으면 그걸로,
               없으면 겹치는 가치의 recommendationReasons
```

## Why — 왜 필요했나

`grounding.ts`는 1절 사다리에서 `roamInterpretation`을 `recommendationReasons`보다
**먼저** 평가했다. 그런데 전수 조사 결과:

```
SIBF roamInterpretation 보유        16곳
SIBF recommendationReasons 보유     16곳
reasons만 있고 해석은 없는 곳         0곳   ← T2가 뜰 수 있는 유일한 조건
```

**완전히 같은 16곳이다.** `roamInterpretation`이 항상 먼저 걸리므로
`recommendationReasons`는 **도달 불가능한 분기**였다. 전 전시에서 이 분기 사용률이 0%인
게 그 증거다.

**저작자에게 쓰라고 시키고 쓰면 버리고 있었다.** 지금까지 한 번도 사용자에게 닿은 적 없는
저작 문장이 **45개**다.

그리고 이건 단순한 낭비가 아니라 **브랜드 약속의 손실**이다. 태그라인이
"반응할수록 정확해져"인데, 정확해지는 걸 화면에서 보여주는 문장이 바로
`recommendationReasons`다. 같은 부스라도 사람마다 다른 말이 나오는 유일한 재료였고,
그게 죽어 있으니 **모두가 같은 문장을 보고 있었다.**

## 판단 근거

**둘은 답하는 질문이 다르다.** 경쟁시킬 이유가 애초에 없었다.

| | `roamInterpretation` | `recommendationReasons` |
|---|---|---|
| 답하는 질문 | 이 부스가 **무엇인가** | 너한테 **왜 맞는가** |
| 부스당 개수 | 1개 | 가치 수만큼 (2~3개) |
| 사람마다 | 똑같음 | **다름** |

브랜드북은 로미의 한 줄을 **사실절 + 근거절**로 정의한다. 위 표를 그대로 겹치면
`roamInterpretation`은 사실절이고 `recommendationReasons`는 근거절이다.
기존 코드는 근거절 재료를 사실절 자리에 넣어두고 하나만 고르게 했던 것이라,
**필드를 없애는 대신 원래 있어야 할 자리로 옮겼다.**

**왜 폐기하지 않았나.** 감사 시점의 선택지는 (A) 순서 뒤집기 (B) 필드 폐기였는데,
A는 이번엔 `roamInterpretation`이 죽고, B는 개인화 재료를 통째로 버린다. 둘 다
"하나만 살린다"는 전제를 깔고 있었고, 그 전제가 틀렸다.

**왜 행동 근거가 가치 근거보다 우선인가.** 브랜드북은 근거절을 "내가 실제로 반응한
부스"로 정의한다. `"아까 ‘비온뒤’ 좋아했잖아"`가 `"제작자 취향이 강한 책을 찾기 좋아"`
보다 강한 근거다 — 전자는 내 행동이고 후자는 추론이다. 둘 다 있으면 행동이 이긴다.

**왜 하나만 쓰는가.** `matchedReasons[0]`만 쓴다. 두 개를 이으면 한 호흡 규칙(§1-2)이
깨진다. `[0]`이 가장 강하게 겹치는 가치다 — `valueTags`가 강도 내림차순으로 정규화돼
있어(`values/derive.ts`의 `normalize`) `overlap` 순서가 그대로 강도 순이다.

**겹치는 가치가 없으면 안 붙인다.** 없는 근거를 지어내지 않는다는 원칙 그대로다.

## 결과 (SIBF 저작 16곳 시뮬레이션)

같은 부스, 사용자 유형별로 달라지는 2절:

```
A1001 평산책방
  1절 (공통)  유명인의 서재를 엿보듯, 한 사람의 독서 취향을 따라가며 인문서를 발견하는 부스야.
  2절 학습형  …추천도서 큐레이션을 따라가며 인문 주제를 깊게 파기 좋아.
     굿즈형  …올해 도서전에서 가장 화제인 부스라, 지금 뭐가 회자되는지 감이 와.
     소통형  …즉석 북토크가 열려서 저자·독자와 같은 공기를 느낄 수 있어.

A1102 윌라스토리
  1절 (공통)  귀로 듣는 책이 궁금하면, 오디오북을 직접 체험해보고 굿즈까지 챙기는 부스야.
  2절 학습형  (겹치는 가치 없음 → 1절만)
     굿즈형  …NFC 키링·리유저블백 같은 챙길 굿즈가 쏠쏠해.
     소통형  …오디오북 체험·라디오 포토존처럼 직접 해볼 거리가 많아.
```

| | 결과 |
|---|---|
| 되살아난 저작 문장 | **45개** (그동안 노출 0) |
| 저작 16곳 × 3유형 = 48건 중 2절이 붙는 경우 | **28건 (58%)** |
| 사람마다 다른 문장이 나오는 부스 | 0 → **16곳 전부** |

나머지 42%는 관심 가치가 안 겹쳐 1절만 나온다. 이게 정상이다 —
겹치지도 않는데 근거를 붙이면 그게 지어내는 것이다.

## 저작 규칙에 주는 함의

이제 두 필드의 역할이 갈렸으니 `docs/booth-enrichment.md`의 안내도 이렇게 읽어야 한다.

- `roamInterpretation` — **누가 봐도 같은** 한 줄. "이 부스는 무엇인가."
- `recommendationReasons[가치]` — **그 가치에 끌리는 사람에게만** 하는 말. "너한테 왜."
  가치 이름을 문장에 쓰지 않는다(§4-2). 기존 16곳은 이미 그렇게 쓰여 있다.
- 가치를 많이 채울수록 그 부스가 더 많은 사람에게 다르게 말한다.
