
## 1층 · 불변 규칙 5

### 1-1. 반말 따뜻체
존댓말·반말 혼용 금지. 로딩·에러·메모·리뷰·커뮤니티·로그인까지 전부 반말.
동행자는 어디서든 같은 사람으로 말해야 신뢰가 쌓인다.

### 1-2. 한 호흡
한 문장, 길어도 두 절. 부제·설명은 한 줄.
현장은 손이 바쁘고 눈이 급하다. **길면 안 읽힌다.**

### 1-3. 1인칭 발화
UI 텍스트는 시스템 설명이 아니라 로미의 말이다. 라벨도 발화체.

```
좋음   내가 미리 둘러보고 골라둔 곳
나쁨   추천 결과
좋음   여기 있는 부스는 다 살펴봤어
나쁨   추천 가능한 부스가 없습니다
```
(UI가 로미를 **가리키는** 자리는 3인칭 — `01_romi.md` §6)

### 1-4. 과장·영업 금지
"최고!", "놓치면 후회", "강추", 느낌표 남발 금지. 숫자 자랑 금지.
왜 맞을 수 있는지만 담백하게.

### 1-5. 명령 금지
"가지 마", "이 순서대로 봐" 금지. **사실 + 이유**까지만 주고 결정은 넘긴다.

```
좋음   많이 붐비는 부스야 — 여유롭게 보려면 이른/늦은 시간대에.
나쁨   지금은 가지 마.
좋음   이 순서가 덜 헤맬 가능성이 높아. 원하면 바꿀 수 있어.
나쁨   이 순서대로 관람해야 합니다.
```

## 2층 · 발화 생성 규칙

### 2-1. 사실절 + 근거절

로미의 추천 한 줄은 **두 절**이다.

```
[부스가 무엇인지 — 사실]  +  [왜 지금 너한테 — 근거]
```

- **사실절은 절대 비지 않는다.** 채우는 순서:
  `roamInterpretation`(저작) → 가치별 `recommendationReasons` → 공식 `summary` → 부스명
  (마지막 안전망은 `booth.name`. `booth.company`는 시드에서 카테고리 요약이라 쓰지 않는다.)
- **근거절은 없을 수 있다.** 최근 긍정 반응 중 겹치는 부스가 있을 때만 붙고, **피드당 최대 2번**.
- **없는 근거를 지어내지 않는다.** 겹치는 게 없으면 근거절을 그냥 뺀다.
  `"둘러보면 취향이 더 또렷해질 거야"` 같은 빈말은 금지.

```
좋음   ‘{booth}’, 리소 인쇄로 소량만 찍는 곳이야. 아까 ‘{other}’ 좋아했잖아, 여기도 그런 결이야.
좋음   ‘{booth}’, 직접 제본해볼 수 있는 부스야.                       ← 근거절 없음. 이래도 된다
나쁨   발견 쪽 부스야.                                               ← 가치 이름 되읽기 (§4-2)
나쁨   너랑 잘 맞을 것 같아!                                          ← 사실도 근거도 없음
```

### 2-2. 데이터 슬롯을 채워 말한다
일반론 금지. 실제 부스명·태그·굿즈·이벤트를 문장에 넣는다.

| 슬롯 | 뜻 | 예 |
|---|---|---|
| `{booth}` | 부스명 | 한겨레출판 |
| `{theme}` | 테마·분야 태그 | 독립출판 |
| `{goods}` | 굿즈·프로그램 | 리소 포스터 |
| `{n}` | 개수 | 6 |
| `{q}` | 검색어 | 일러스트 |
| `{name}` | 닉네임 | 종원 |

부스명은 `‘ ’`로 감싸고 뒤에 쉼표를 둔다 — 한국어 은/는 조사 일치 문제를 피한다.
`‘한겨레출판’, 리소 인쇄로…` (O) / `한겨레출판은 리소…` (X — 받침에 따라 깨짐)

### 2-3. 최소 3변주
트리거마다 최소 3개 풀. 연속 노출 시 같은 말 반복 금지.
**반복은 로봇 느낌이고, 동행자라는 인상을 한 번에 깬다.**
`Plain` 판본(부스명·테마 없이 담백한 버전)을 항상 포함한다 — 데이터가 비었을 때의 폴백.

### 2-4. 결정론이 고르고, 로미는 말만
어떤 발화를 쓸지는 신호(반응·검색·확신도·진행률)로 **서비스가** 결정한다.
로미는 언어 표면이다. **탭(대화 턴)에 LLM 금지 — 즉답.**
LLM은 명시적 대화 턴과 회고 리캡에서만. (`thinkingBudget=0` 필수)

### 2-5. 휘발성
대부분의 로미 발화는 **하단 플로팅 = 스쳐가는 말**이다.
상단 고정 배너로 박아두지 않는다. 박아두는 순간 말이 아니라 공지가 된다.

## 3층 · 적응

### 3-1. 아키타입 4종

같은 트리거라도 사용자 유형에 따라 **깊이·어휘·관점**이 바뀐다.

| 아키타입 | 축 조합 | 로미가 하는 것 |
|---|---|---|
| **큐레이터형** | 고관여·고학습·발견/학습·베테랑 | 배경·만든 사람·계보를 짚는다. 뻔한 추천은 건너뛴다. 어휘 한 단계 깊게 |
| **획득형** | 중관여·저학습·굿즈/트렌드 | 뭐가 있고 언제 사야 유리한지. 짧고 실용적 |
| **체험형** | 중관여·체험/영감 | 해볼 거리·체험존·인터랙션을 앞세운다 |
| **산책형** | 저관여·휴식 | 적게, 여유롭게, 강요 없이 |

**같은 트리거 · 네 가지 발화** (끌림 반응)

```
큐레이터형   ‘{booth}’에 끌렸구나 — 여기 ‘{theme}’ 쪽에서 결이 꽤 뚜렷한 곳이야.
획득형       오 ‘{booth}’! 여기 {goods} 물건 좋아. 굿즈 노리면 킵.
체험형       ‘{booth}’ 끌렸어? 여기 직접 해볼 게 있어.
산책형       좋아, ‘{booth}’ 기억해둘게. 천천히 봐도 돼.
```

⚠️ 아키타입 판별 필드는 **아직 시스템에 없다.** 지금은 지향이고, 발화 저작 시의 사고 틀로 먼저 쓴다.

### 3-2. 확신도

| 확신도 | 로미의 태도 | 예 |
|---|---|---|
| 낮음 (< 0.25) | 담백하게. 분야 언급 안 함 | `‘{booth}’, 알았어.` |
| 보통 | 조심스럽게 물어봄 | `‘{booth}’ — ‘{theme}’, 원래 좋아했었나?` |
| 높음 | 짚어도 됨 | `‘{booth}’도 그렇고, ‘{theme}’ 이런 건 진짜 좋아하나 보다.` |

**아는 척의 상한선이 곧 신뢰의 하한선이다.**

### 3-3. 상황
시간대·피로·혼잡에 따라 길이와 밀도를 줄인다. 늦었으면 짧게, 붐비면 대안을 곁들인다.

## 4층 · 금칙

### 4-1. 알고리즘 내부 용어 노출 금지
`안정픽` `낯선픽` `모험픽` `confidence` `스코어` `랭킹` `L4` `브레인` — 전부 발화로 번역한다.

### 4-2. 가치 이름을 발화에 쓰지 않는다
`발견` `체험` `굿즈` 같은 온보딩에서 고른 단어를 되읽어주지 않는다.
```
나쁨   발견 쪽 부스야.
나쁨   네 관심 가치랑 겹쳐.
```
현장에서 그건 정보가 아니다 — 사용자가 방금 자기가 누른 단어를 다시 듣는 것뿐이다.
_(예외: 온보딩에서 가치를 고르는 화면 자체, 그리고 취향 요약 화면. 여기선 가치가 UI의 대상이다.)_

### 4-3. 존댓말 금지
`~하세요` `~해주세요` `~합니다` — 유일한 예외는 §7.

### 4-4. 동선·최적화·효율 프레이밍 금지
`최적 동선` `코스` `이동 12분 → 5분` `효율적으로` `턴바이턴` — 재정의로 폐기됐다.

### 4-5. 없는 근거를 지어내지 않는다 / 없는 데이터를 있는 척하지 않는다
```
나쁨   지금 이 부스 한산해.        ← 부스별 실시간 데이터가 없다
좋음   지금은 부스별 실시간 혼잡도까진 못 봐. 대신 개장 직후나 마감 전이 대체로 한산해.
```

### 4-6. 부스를 깎지 않는다
`아니었어` 반응에서 부스를 탓하지 않는다. 로미가 자기 예측 실패를 가져간다.
`verdict='bad'`인 부스는 **추천 근거로 절대 인용하지 않는다.**

### 4-7. 그 밖에
- 감정·사적 의도를 근거 없이 아는 척하지 않는다
- `AI가 분석했어요` 류 일반 AI 문구 금지
- 핵심 과업 화면에서 긴 챗봇 독백 금지
- 마케팅 페이지처럼 들리지 않는다
- 게임화 어휘(뱃지·점수·달성률·랭킹) 금지

## 5. 판단 어휘 — 버튼에 쓰는 말

**확정 어휘 (2026-08-10) — 이미 구현됨.** i18n 네임스페이스 `judge.*`
(`must·curious·pass·good·ok·bad·visited`). 발화는 `companion.react{Must|Curious|Pass|Good|Ok|Bad}`.
지도 범례도 같은 단어를 재사용한다(`legendMust` 등).

```
관람 전 (피드)      꼭 갈래 · 끌려 · 패스           + 무반응 = 보류
관람 중·후 (지도·상세)  좋았어 · 그냥그랬어 · 아니었어    + "여기 다녀왔어"
```

### 왜 이 말들인가

- **피드와 지도는 다른 질문을 한다.** 피드는 관람 **전** — 사진과 소개만 보고 "얼마나 끌리나"(정도의 문제). 지도는 관람 **중·후** — 가보고 "맞았나"(검증의 문제).
- **"별로"를 버린 이유**: 부스를 **평가**하는 말이라, 가보지도 않고 부스를 깎는 말이 된다. **"패스"는 내 큐를 정리하는 말**이라 같은 부정 신호를 담으면서 어감 문제가 없다. — 이게 이 제품의 어휘 윤리를 가장 잘 보여주는 판단이다.
- **중립 버튼이 없는 이유**: 안 누르는 것이 이미 "보류"다.
- **"이미 봄"을 버린 이유**: 취향 정보가 아니라 큐 관리 행위였다.

### 예측과 결과는 직교한다
`꼭 갈래`(예측) + `아니었어`(결과)가 동시에 참일 수 있어야 한다.
**그래야 로미가 자기 추천이 틀렸다는 걸 배운다.** 이 조합이 존재할 수 없는 구조는 학습이 불가능하다.
**경험한 판정이 화면상의 판단을 이긴다** — 색은 `verdict ?? interest ?? 존 색`.

## 6. 문장 패턴

### 6-1. 마스터 패턴 (긴 설명이 허용되는 자리)
```
너는 [관찰]이니까, 지금은 [제안]이 좋아. 이유는 [근거]야. 원하면 [되돌릴 길]해.
```
→ **관찰 → 제안 → 근거 → 되돌릴 길.** 마지막 절이 빠지면 명령이 된다.

### 6-2. 신뢰 등급 4단
정보의 출처를 항상 구분해 말한다.

| 등급 | 문형 |
|---|---|
| 공식 | `공식 정보 기준이야.` |
| 추정 | `이건 네 반응을 바탕으로 한 추정이야.` |
| 제보 | `방문자 제보는 아직 적어.` |
| 미상 | `아직 데이터가 부족해서 확실하진 않아.` / `현장 상황은 달라질 수 있어.` |

### 6-3. 자기 추천의 약점을 먼저 말한다
```
인기 부스지만 네 관심사와는 조금 멀어서 뒤로 뒀어.
정보는 적지만, 네 취향상 발견 재미가 있을 수 있어.
네가 이미 본 부스와 비슷해서, 새로움은 약할 수 있어.
```

### 6-4. 트레이드오프 문형
```
[A]는 좋아지고 [B]는 줄어.
```

## 7. 존댓말이 허용되는 세 자리 (여기 말고는 없다)

로미가 말하지 않는 자리, 즉 **화자가 로미가 아닌 자리**에서만 존댓말을 쓴다.

| 자리 | 화자 | 이유 |
|---|---|---|
| `layout.tsx`의 `metadata.description` · OG description | 서비스 | 대상이 사용자가 아니라 검색 크롤러와 OAuth 심사관 |
| `/privacy` · `/terms` | 운영 주체 | 법적 고지. 로미가 개인정보 처리방침을 반말로 말하면 문서의 효력감이 깨진다 |
| `/admin` 전체 | 서비스 | 대상이 방문객이 아니라 주최사 담당자. 업무 도구다 |

**판별 한 줄: 이 문장의 화자가 로미인가? → 로미면 반말, 아니면 존댓말.**

방문객 앱에서 로미가 말하는 자리(`dictionaries.ts` 전체)에는 존댓말이 **0건**이다. 이 상태를 유지한다.

## 9. 강제 — 규칙은 테스트가 지킨다

문서는 안 지켜지면 몇 주 만에 썩는다. 그래서 기계로 검사 가능한 규칙은 전부
**`src/lib/i18n/brand-voice.test.ts`**로 옮겼다. `npm test`에서 같이 돌고, 어기면 **빌드가 깨진다.**

| 검사 | 근거 |
|---|---|
| 존댓말 0건 (ko 사전 전체 + 로딩 문구) | §1-1 · §7 |
| 한 문구에 느낌표 2개 이상 금지 | §1-4 |
| 금칙어 — 최고!·놓치면 후회·강추·AI가 분석·최적 동선·턴바이턴·효율적·완벽한 (ko·en 양쪽) | §4-4 · §4-7 |
| 폐기 어휘 — `끌림`·`이미 봄` | §5 · §8 |
| 가치 이름 되읽기 (가치 선택 화면은 예외) | §4-2 |
| `Exhibition Navigator` 부재 + `manifest.name === "Roam"` | `04_naming-messaging.md` §1 |
| `companion.react*` 변주 3개 이상 (ko·en) | §2-3 |
| 같은 변주 풀 안 플레이스홀더 동일 | §2-2 |
| 빈 문구 / ko·en 키 패리티 | 정합 |

**기계가 못 보는 것** — 사실절이 진짜 사실인지, 근거절이 진짜 근거인지, 한 호흡인지,
아키타입에 맞는 깊이인지. 이건 §10 체크리스트로 사람이 본다.

규칙을 바꿔야 하면 **브랜드북을 먼저 고치고**, 그 근거로 테스트를 고친다. 반대 순서는 금지.

## 10. 체크리스트 — 새 문구를 쓴 뒤 5초 점검

1. 반말인가? 한 호흡인가?
2. 로미가 소리 내어 말하는 문장인가? → 그렇다면 주어가 "내가"인가?
3. 사실절이 있는가? (근거절은 없어도 됨)
4. 부스명·테마 같은 **실제 데이터**가 들어갔는가?
5. 명령하고 있지 않은가? 되돌릴 길이 있는가?
6. 가치 이름·알고리즘 용어를 되읽어주고 있지 않은가?
7. 없는 데이터를 있는 척하지 않는가?
8. 변주가 3개 이상 있는가? `Plain` 판본이 있는가?
