# 부스 카드와 상세의 홀 칸 짧게, 상세 로딩을 iOS 방식으로 (2026-11-29)

## 무엇을

1. 부스 카드, 부스 상세 위치 줄, 로미 시트와 길 안내 목록의 홀 칸을 홀 칩과 같은 짧은 이름으로 쓴다.
   `lib/floorplan/hall-of.ts`의 `boothHallLabel` = `floorplanHallOf`(배치도 홀) 또는 부스 데이터 홀 이름 → `shortHallName`(#241, iOS `FairMapModel.shortHallName`과 같은 규칙).
   - "킨텍스 제2전시장 6홀" → "6홀", "코엑스 A홀" → "A홀", "Hall A" → "A홀", "DDP 아트홀" → "아트홀", "SETEC" → "SETEC".
   - iOS: 카드 `BoothCard(hall: vm.hallName(of:))`, 상세 `BoothPageScreen(hallName:)`, 둘 다 `MapHall.shortName`. 장소 공식명은 카드와 상세 어디에도 따로 보이지 않는다.
2. 상세 로딩(`booths/[id]/loading.tsx`)이 지도에서 이미 가진 부스로 이름, 홀과 부스 번호, 분류 배지, 브랜드 칸 머리와 이름, 위치 줄을 실제 글자로 그린다.
   사진(지도가 아는 수만큼, 셋까지)과 브랜드 소개 한 줄만 회색 자리다. 링크로 바로 들어오면 예전 회색 틀 그대로.
   다 오면 틀을 한 번 더 겹쳐 두고 틀 1→0, 내용 0→1을 `--roam-v2-motion-enter-duration`(150ms), `--roam-v2-motion-enter-easing`으로 바꾼다(iOS `V2Motion.enter`, Roam-ios #254).

## 넘기는 방법: zustand 휘발성 스토어 (`lib/stores/booth-preview.ts`)

부스 카드 "자세히"와 첫 고른 곳 미리 보기 "자세히"가 누를 때 미리 보기를 넣고, 로딩 화면이 `useParams().id`로 맞는지 본다.

버린 안:
- 쿼리 문자열: 공유 링크가 지저분해지고 고친 주소가 남의 이름을 그린다.
- sessionStorage: 한 번의 이동에만 쓰는 값이라 남길 이유가 없고, 저장소 실패 처리만 늘어난다.
- 상세를 클라이언트 fetch로 바꾸기: RSC 상세와 로딩 경계를 갈아엎어야 하고 SSR 첫 화면이 늦어진다.

## iOS와 아직 다른 점

- 지도 목록에 브랜드 id가 없어(웹 지도는 `withBrandIds`를 안 붙임) 브랜드 칸 유무를 부스 소개 원문 유무로만 정하고 알림 문구를 그리지 않는다.
  iOS는 `exhibitorId || description`. 브랜드는 있는데 소개 원문이 없는 부스는 다 오면서 칸이 생긴다.
- 웹 상세 소개는 브랜드 소개 > 저작 요약 > 원문(longDescription) 순이라 iOS(brandIntro > longDescription > description)와 출처가 다르다(이번 변경 밖).
- 웹 사진 칸은 폭 2/5 비율 3:4이고 iOS는 150×200 고정. 로딩 틀은 웹 실제 칸을 따른다.
- 배치도에 없는 부스면 웹은 부스 데이터 홀 이름을 줄여 쓰고 iOS는 홀 칸을 비운다(원래 있던 차이).
- 로딩 틀 위 뒤로 버튼은 예전처럼 빈 자리(iOS는 머리가 로딩 바깥이라 버튼이 보인다).
