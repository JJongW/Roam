## 1. 토큰 파이프라인

- `npm run tokens:sync`가 `src/styles/v2/source.json`에 고정한 Roam-design 커밋(`950463443f…`)의 `dist/web/v2/tokens.css`, `theme.css`를 바이트 그대로 `src/styles/v2/`에 복사한다. 원천은 `ROAM_DESIGN_DIR`, 옆 체크아웃 `../Roam-design`, `gh api` 순서로 찾고, 어느 길이든 **커밋으로** 읽는다(작업 폴더의 고치던 파일을 읽지 않는다).
- `npm run tokens:check`는 쓰지 않고 맞대 보기만 한다. 다르면 종료 코드 1.
- `globals.css`가 v1 `tokens.css` 다음에 v2 둘을 import한다. v2 이름은 전부 `-v2-`가 붙어 v1과 부딪히지 않는다(같이 산다).
- `src/styles/v2/lengths.generated.ts`: SVG 지도처럼 숫자가 필요한 자리용. `tokens.css`의 길이 토큰을 기계로 px 숫자로 뽑은 것이고, 손으로 적은 값이 없다. sync가 만들고 check가 맞대 본다.

## 4. W1에서 옮긴 것

- 지도(UI 3-01, 3-02, 3-03, 3-04~3-06): `components/map-v2/*`. 지도 엔진(`components/map/exhibition-map.tsx`)은 그대로 쓰고 그림 층만 바꿨다(`renderLayer`, `hideControls`, `handleRef`, `entry="whole"`). 제스처와 맞춤이 한 벌이라 v1과 v2가 따로 놀지 않는다.
  - 찾기 줄, 결과 수("N곳 있어요"), 못 찾음, 편의시설 칩(데이터에 있는 종류만), 홀 버튼(홀이 둘 이상일 때만), 로미 줄, 부스 카드(로미 아바타, 다녀왔어요 알약, 하트, 분류 칩, 자세히).
  - 넓은 화면은 손가락 확대가 없어 확대, 축소 버튼을 둔다(옛 `ui_click` `map_zoom_in/out`과 새 `map_control`을 같이 기록).
  - 웹만의 차이: 찾기 줄 왼쪽 뒤로 버튼(iOS는 탭바).
  - 뼈대(`map/loading.tsx`): 그 박람회 배치도의 홀과 칸 자리를 그대로 그린다. 배치도가 없으면 바닥과 로미 줄만.
  - 배치도 없는 박람회: "이 박람회는 아직 배치도가 없어요".
- 부스 상세(UI 4-02): `components/booth-v2/*`. 사진 줄(3:4), 이름, 위치, 분류 배지, 소개 상자, 정보 줄(위치와 지도에서 보기, 파는 것, 인스타그램, 브랜드 사이트), 아래 바(하트, 다녀왔어요). 뼈대(`booths/[id]/loading.tsx`)는 같은 자리, 같은 크기.
- 홀 이름은 배치도 홀 이름을 먼저 쓴다(`lib/floorplan/hall-of.ts`). mock 데이터의 홀 이름이 "전시장"이라 사용자 문구에 "전시"가 새는 걸 막는다.
- 하트, 다녀왔어요: PR #172의 `heart`, `visited` 칸. 기기 저장(`stores/visit.ts`의 `setHeart`, `setVisited`, `restore`)이 먼저고, 로그인했으면 서버에도 남는다. 빼기는 확인 없이 바로, 스낵바로 되돌리기.
- 문구: `lib/copy/v1.ts` 한 곳(iOS `V1Copy.swift`와 같은 문장).
- 이벤트: `lib/analytics/app-track.ts`. iOS `AnalyticsTaxonomy.swift`와 같은 이름, 같은 수신구(`POST /api/analytics/events` 묶음, `platform: "web"`). `screen_view`, `map_load_result`, `booth_card_open`, `search_submit`, `search_zero_result`, `search_result_tap`, `hall_switch`, `map_control`, `heart_add`, `heart_remove`, `visit_mark`, `visit_unmark`, `booth_show_on_map`. 옛 `view`(부스 상세), `ui_click`은 그대로 둔다.
- `/api/floorplans` 봉투 한 겹으로(`{ data: [...] }`). 쓰던 클라이언트는 웹, 스크립트, 워커, Roam-ios 모든 브랜치에서 0곳.

## 5. 고르지 않은 방향

- 지도 엔진을 새로 쓰기: 제스처, 회전, 저장된 보기, 누르기 판정을 다시 만들어야 하고 iOS와 맞춘 규칙(부스 이름 줄바꿈)이 갈린다. 그림 층만 바꿨다.
- v1 상세의 메모와 평가를 v2 모양으로 덧칠해 남기기: UI 6 설계(평가는 나중에 로미가 묻기)와 다른 흐름이 굳는다. W2에서 설계대로 옮긴다.
- 웹 안에 빠진 토큰(콘텐츠 폭, 사진 높이 200, 흐리게 0.35)을 정의하기: Ted 결정과 어긋난다. 비율(`w-2/5`, `aspect-3/4`)로 피했고 남은 것은 미정에 적었다.

## 6. 미정

- 카드, 버튼 둥글기: 토큰이 시험값 1(16, 8)과 2(24, 14)만 있다. iOS처럼 시험값 1을 썼다.
- 지도에서 흐리게 하는 정도, 출입구 알약 글자 비율: W2에서 Roam-design PR #38로 더했다. 머지 뒤 다시 고정.
- 길 안내(UI 9) 웹 버튼, 걷는 시간("출입구에서 걸어서 N분쯤"): 축척이 없는 박람회가 많아 뺐다.
- v2 화면 영어 문구: 지금은 한국어만.
- 큰 화면 배치: 지도는 W2에서 화면 전체를 쓴다. 부스 상세와 목록은 아직 본문 폭 한 줄이다.
- 첫 방문 온보딩이 지도를 덮는 문제(W4에서).
- `-v2-` 접두어를 언제 떼는지(v1이 다 빠진 뒤).
- 브랜드 하트(브랜드 단위)와 "체험 있음" 배지: 데이터가 아직 없다.

## 7. W2에서 옮긴 것 (2026-11-18)

**결정(Ted, 헤더 전달)**: 같은 브랜치(`feat/web-design-v2`, PR #175)에서 UI 6과 v1 상세 섹션 복원, 지도 자리 고치기를 이어서 한다. 빠진 토큰은 Roam-design에 작은 PR을 열어 더한다.

- 토큰: Roam-design PR #38(`feat/tokens-v2-web-map`, `523cfb8`)에 `size.content-max-width`(448), `opacity.map-dim`(0.35), `opacity.map-code`(0.7), `ratio.map-entrance-label`(0.16)을 더했고 웹은 그 커밋에 고정했다. Ted가 머지하면 master 커밋으로 다시 고정한다. 단위 없는 값은 `lengths.generated.ts`의 `V2_NUM`으로 받는다.
- 지도 자리: 390에서 배치도가 오른쪽과 검색창 밑으로 잘리던 것을 엔진 `safeInsets`로 고쳤다(검색과 칩 아래, 로미 줄이나 카드 위 띠 안에 맞춤). 1280에서는 지도가 화면 전체를 쓰고 검색과 카드는 본문 폭(448)으로 왼쪽에 떠 있다. 카드가 올라와 띠가 바뀌면 마지막 초점을 다시 잡는다.
- 뼈대: `?skeletonDelay`로 개발 서버에서 붙잡아 찍는다. 지도 뼈대도 같은 띠 안에 맞춘다.
- UI 6:
  - 6-02 지도 위 다녀온 칸 체크 표시(하트보다 앞), 6-03 로미 줄 "다녀온 곳으로 기억해 둘게요"와 되돌리기, 6-04 "오늘 다녀온 곳" 알약과 시트(평가 칩, 메모 한 줄).
  - 6-05 상세 "남기신 것"(하트, 다녀온 시각, 메모), 6-06 다녀왔어요 빼기는 평가도 함께 빠지고 스낵바로 되돌리기, 6-07 메모 50자, 6-08 메모 지우기와 되돌리기.
  - 6-09 끝난 박람회 상세 맨 위 "어떠셨어요?" 띠(다녀온 곳에만, "나중에 할게요"로 접기). 박람회 중에는 묻지 않고 오늘 다녀온 곳 시트에서 고른다(설계서 섹션 8 C).
  - 6-10 `/visited`: 박람회별 카드(다녀온 칸 둘레 미니 지도, 날짜와 행사장, 부스 줄). 여러 박람회를 한 번에 주는 API(A-1)가 없어 부스마다 `/api/booths/{id}`를 6개씩 묶어 부른다. 옛 메모장 경로는 여기로 넘긴다. 기기 기록을 보여 주므로 로그인 없이 연다(`proxy.ts` 공개 경로).

**되살리지 않은 것과 이유**
- AI 요약(`summaries.json` 509개): 전부 합니다체이고 80개에 가운뎃점, 9개에 "전시"가 들어 있다. Roam이 만든 글이라 브랜드 규칙 §1, §5에 걸린다. 실시간 생성 프롬프트도 규칙 검사를 거치지 않는다.
- 후기(리뷰): Figma UI v1에 자리가 없고 "리뷰"와 "후기" 표기가 갈려 있다.
- AI가 뽑은 신간, 굿즈 강조와 보강 팁: 확인되지 않은 생성 글이다.
- 개인 사진 올리기: UI 6에 사진이 없다. 이미 올린 사진도 v2 상세에 보이지 않는다.

**남은 지역 값(토큰 아님, 그림 판정용 비율)**: 지도 칸 글자 맞춤 휴리스틱(`map-layer.tsx`), 체크 표시 크기 비율, 다녀왔어요 미니 지도의 글자 비율과 칸 안쪽 여백. 디자인 값이 아니라 칸 크기에서 계산하는 비율이라 토큰으로 올리지 않았다.

**고르지 않은 방향**
- 다녀온 즉시 평가를 묻기: 현장에서는 체크만 하고 평가는 나중에(11-10 결정). 끝난 박람회와 오늘 다녀온 곳 시트에서만 고른다.
- 6-10용 새 API부터 만들기: 화면을 먼저 내고 묶음 API는 iOS와 같이 정한다. 부스가 많으면 요청이 늘어나는 단점이 있다.
- 한 홀짜리 박람회에서 검색으로 고른 부스를 크게 확대하기: 띠 안에 홀 전체를 맞추라는 지시를 따랐다. 휴대폰에서는 고른 부스가 작게 보인다.
