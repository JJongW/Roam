# 두 번 찾아보고 손을 뗀다

**날짜**: 2026-10-16
**관련 파일**: review-policy.ts, run-draft.ts, 초안 검수 화면

## What — 무엇이 달라졌나

근거를 못 찾은 부스를 기계가 **두 번까지만** 다시 쓴다. 그래도 안 되면 그만두고
"기계가 못 찾은 곳" 목록에 올려 사람이 직접 찾게 한다. 화면이 몇 곳이 그렇게
넘어왔는지 보여준다.

## Why — 왜 필요했나

재시도에 상한이 없었다. 초안 대상을 고르는 기준이 "저작 필드가 비었나" 하나뿐이라,
근거를 못 찾아 반려·재초안으로 빠진 부스는 **다음 배치마다 자동으로 다시 대상이
됐다.** 끝나는 조건이 없다.

실제로 그렇게 돌고 있었다. 지금 데이터에서 주류&와인박람회는 부스 88곳이 3~4번째
초안까지 갔고, SIF도 8곳이 4회차다. 초안 한 번이 검색 각도 3개 × 재시도 2번이라
Gemini 호출 최대 6회니, 그 114곳이 **쓰지 않아도 됐을 호출 수백 회**다.

## 판단 근거

**다시 물어봐도 웹에 없는 정보는 여전히 없다.** 두 번 해서 안 되면 모델이 운이
나빴던 게 아니라 근거가 없는 것이고, 그때부터 유일한 길은 사람이 인스타나 브랜드
사이트를 직접 찾는 것이다. 기계를 더 돌리는 건 요금만 쓰면서 같은 결론에 반복해서
도달하는 일이다.

**2회로 잡은 근거**: 초안기는 한 번 돌 때 이미 세 각도를 시도하고 가장 좋은 것만
남긴다. 2회면 실제로는 여섯 각도를 본 것이다.

**상한을 센 다음 판정을 다시 본다.** 두 번 썼어도 마지막 초안이 쓸 만해졌으면 손을
떼지 않는다 — 그건 재초안이 아니라 검수 대상이다. 횟수만 보고 자르면 두 번째에
근거를 찾아낸 것까지 버린다.

지금 데이터에 걸어 보면 부스 1,173곳 중 **73곳(6%)**이 사람 목록으로 넘어간다.
`data/verified/`에 직접 적으면 대조 검수로 들어오는 기존 경로를 그대로 쓴다.

## 이것으로 흐름이 닫혔다

```
① 인입(주최 자료)                                모델 0
② 스크립트가 빠진 주소 메우기 → 사람이 표로 확인    모델 0
③ 초안기가 글을 쓴다                              모델
④ 코드 + 점수로 분류
     치명 코드 → ⑤                              사람에게 안 간다
     애매      → 사람
     통과      → 전시를 믿으면 자동 승인
⑤ 기계가 2회까지 다시 찾는다 → 그래도 안 되면 사람 목록   ← 이번 변경
```

예전엔 ⑤에서 돌아온 것이 다시 ③으로 들어가 영원히 돌았다. 이제 끝이 있다.
