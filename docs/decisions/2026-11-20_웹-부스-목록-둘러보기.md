# 웹 부스 목록(UI 8 둘러보기)

_2026-11-20. 브랜치 `feat/web-booth-list`. main(#201 머지 뒤) 위에서 팠다._

## 왜

웹에는 박람회 부스를 분류별로 훑어보는 자리가 없었다. #198 로미 시트는 부스 목록 줄을 일부러 뺐다(그때는 목록 화면이 없었다).
iOS는 #187에서 UI 8을 넣었다. Figma UI 8의 8-01~8-03대로 웹에도 만든다.

## 결정 근거

- L-B 분류 먼저(11-11), 하트 남긴 곳이 맨 위이고 하트가 0이면 그 줄을 빼고 "0곳"이라 세지 않는다(11-12, 8-03).
- 입구는 로미 시트의 "둘러보기 > 부스 목록 보기"(7-02 넷째 줄, 11-11). 지도 위에 따로 버튼을 두지 않았다(Figma에 없다).
- 줄을 누르면 지도에서 그 부스 카드가 열린다(8-02 → 5-01). 지도에 이미 있는 `?booth=`를 쓴다.
- 로그인 없이 연다(브랜드 규칙 §4). `proxy.ts` 공개 패턴에 `/exhibitions/[slug]/booths`를 더했다.
- 화면을 지도 안 시트가 아니라 주소가 있는 페이지로 뒀다. Figma 8-01, 8-02는 뒤로 버튼과 "지도로 보기"가 있는 전체 화면이고,
  분류를 고른 뒤 뒤로 가기가 브라우저 뒤로 가기와 같아야 해서다. 지도 화면 파일(`fair-map-screen.tsx`)을 건드리지 않아
  같은 시간에 지도를 고치는 다른 작업과 부딪히지 않는다(고르지 않은 쪽: 지도 안 시트는 지도 상태를 그대로 쥐지만 주소가 없다).

## Figma와 다르게 한 것

- 하트 남긴 곳 목록은 처음 열 때의 하트로 줄을 고정한다. 목록에서 하트를 빼자마자 줄이 사라지면 되돌리기를 누를 곳이 없어서다.
  다시 열면 빠진 부스는 없다.
- 사진이 없거나 못 불러오면 회색 자리(Figma "사진 자리")만 둔다.

## 만들지 않은 것

- **8-04~8-08 로미가 고른 곳(K-C)**: 웹에 오늘 고른 답(UI 1 온보딩)이 아직 없다. iOS는 온보딩에서 고른 사진의 부스와 같은
  분류로 고른다(`FairEntry.morePicks`). 답 없이 고르면 이유를 지어내게 되고(브랜드 규칙 §5), 설계서 8-04도 "건너뛰었으면 R-2와
  지도에 켜기 없음"이다. 웹 UI 1이 들어온 뒤 그 답을 읽어 붙인다.
- 로미 시트 "제가 알고 있는 것"(8-05 입구)도 같은 이유로 없다.
