# 부스 하트가 브랜드 하트도 남긴다 (UI 23)

_2026-11-24 · 원천 결정: `../Roam-design/docs/decisions/2026-11-24_부스-상세-하트-하나.md` · Figma UI v1 UI 23(Q1 C, Q2 A)_

## 결정 (Ted)

- 부스 상세의 하트는 아래 바 왼쪽 하나. 부스에 하트를 남기면 그 브랜드에도 하트를 준 것으로 본다.
- 브랜드 줄의 "이 브랜드 하트" 알약을 없애고 설명 한 줄만 남긴다(Q1 C).
- 내비 가운데 이름은 `booth.name`, 큰 제목이 화면 밖으로 나가면 나타난다(Q2 A).

## 구현

**서버(웹과 iOS 같이)**: `PUT /api/me/notes/[boothId]`가 부스 하트가 실제로 바뀐 요청(heart 또는 옛 interest)에서
`lib/brands/follow.ts`를 부른다. 클라이언트는 브랜드 하트 API를 따로 부르지 않는다.

- 부스 → 대표 브랜드는 `booth_participant`의 `role=primary` 하나(`listPrimaryBrandLinks`). 공동 입점 브랜드는 따라가지 않는다.
  부스 상세 브랜드 줄에 보이는 브랜드와 같다.
- 남기기: 브랜드 하트 줄이 없으면 `source='booth'`로 만든다. 있으면 그대로(직접 줄을 booth로 내리지 않는다).
- 빼기: 같은 브랜드의 다른 부스(다른 박람회 포함) 하트가 남아 있으면 둔다. 없으면 `source='booth'` 줄만 지운다.
- 직접 하트(`PUT /api/me/brand-hearts/[id]`, 로그인 뒤 기기 하트 올리기)는 `source='direct'`. booth 줄에 직접 하트가 오면 direct로 올린다.
- 따라가기가 실패해도 부스 하트 저장은 성공으로 돌려준다(로그만). 0074 적용 전에 코드가 먼저 나가도 부스 하트가 막히지 않게.

**DB**: `0074_brand_heart_source.sql` — `brand_heart.source`(기본 direct, check direct|booth)와 자기 줄 update 정책.
기존 줄은 전부 사용자가 직접 남긴 것이라 기본값 direct가 맞다.

**채우기**: UI 23 전에 남긴 부스 하트에는 브랜드 하트가 없다. `npm run brand-heart:backfill`(드라이런 기본, `--apply`로 씀)이
하트인 부스의 대표 브랜드마다 없는 줄을 `source='booth'`로 넣는다. 돌릴지는 Ted가 정한다(아래 미정).

**웹 화면**: `components/booth-v2/brand-row.tsx`는 설명만(문구는 Figma C 화면 글자 그대로). 위 내비는 sticky로 두고
`IntersectionObserver`로 큰 제목이 내비 밑으로 사라지면 이름(t5-5 bold, 한 줄 말줄임)과 아래 선(stroke/neutral-weak)을 보인다.

## 버린 안

- 출처 칸 없이 처리: 부스 하트를 뺄 때 직접 남긴 브랜드 하트와 부스가 만든 하트를 가를 수 없어, 직접 하트를 지우거나
  부스가 만든 하트를 영영 못 지운다.
- 알림 잡이 부스 하트를 읽어 브랜드를 계산(쓰기 없음): 마이 브랜드 목록과 홈 줄에 안 나오고, 목록에서 빼기를 할 수 없다.

## 미정

- 채우기(backfill)를 돌릴지. 돌리면 지난 부스 하트도 다음 박람회 참가 알림의 근거가 된다. 넣는 줄의 created_at은 적용 시각이라
  이미 있던 참가는 알리지 않는다(브랜드 알림의 "하트 뒤 생긴 참가만" 규칙).
- 마이 브랜드 목록(14-10)에서 부스 하트가 만든 브랜드를 빼면 브랜드 하트만 빠지고 부스 하트는 남는다. 그 부스 하트를 다시 바꾸기 전엔 돌아오지 않는다.
