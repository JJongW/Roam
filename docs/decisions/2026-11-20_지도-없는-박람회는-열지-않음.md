# 지도에 놓인 부스가 없는 박람회는 방문객에게 열지 않는다

_2026-11-20 · Ted 결정_

## 결정

Ted: "아예 보여 주면 안 되지. 해당 박람회를 띄우면 안 된다고. 그냥 눌러지진 않지만 희미한 처리로 진행 예정 박람회라고 표시하는 게 더 좋을 것 같음."

- 브랜드부터 올린 박람회(참가 사실은 있고 지도에 놓인 부스 0곳)는 방문객이 열 수 없다.
- 목록에는 흐리게, 눌리지 않게, "진행 예정" 라벨로 보인다. 참가 브랜드 목록은 내주지 않는다.
- 부스가 지도에 놓이면 그때부터 평소처럼 열린다.
- 같은 날 Ted: 흐린 줄 위의 "열리면 알려 주세요"(UI 18-04A) 버튼은 눌린다. 줄만 안 눌린다.

## 기준 하나

`lib/exhibition/openable.ts` — **지도에 놓인 부스가 한 곳이라도 있나.** 놓였다 = 좌표가 0,0이 아니고 편의시설이 아니다.
날짜 상태(예정, 진행 중, 종료)와 다른 축이다. 웹, API, iOS가 같은 기준을 쓴다(iOS는 API 칸을 읽는다).

## API

- `GET /api/exhibitions`: 모든 행사를 그대로 내고 `openable`, `availability`(`open` | `upcoming_no_map`)를 더한다. 키를 더하기만 해서 옛 앱 디코딩은 그대로다.
- `GET /api/exhibitions/[slug]`, `.../booths`, `.../floorplan`, `.../feed`, `.../heatmap`, `.../events`, `.../keywords`, `.../community`(GET), `GET /api/booths/[id]`: 열 수 없는 박람회면 409 `NOT_OPEN`.
  - 일부만 비운 데이터(빈 부스 목록, 빈 도면)를 주면 옛 앱 빌드가 빈 지도를 그린다. 그래서 분명한 실패 하나로 말한다.
  - 409를 CONFLICT와 같이 쓰지만 코드를 나눴다. 앱이 "다시 불러오기"가 아니라 "홈으로"를 고르게.
- 운영자(admin 쿠키)는 막지 않는다. 콘솔은 부스를 놓기 전부터 그 박람회를 다룬다.

## 웹

- 홈: 흐린 행(`opacity-50`, 링크 아님, `aria-disabled`, 이름 "{행사명}, 진행 예정"), 날짜 상태와 상관없이 행으로. 추천과 신호 계산에서 뺀다.
- 주소로 바로 들어오면(행사 홈, 지도, 부스 상세) 빈 지도 대신 "아직 진행 예정인 박람회예요" 한 장(`FairNotOpen`).
- 사이트맵에서도 뺀다.

## 고르지 않은 안

- 목록에서 아예 숨기기: Ted가 "희미한 처리로 진행 예정이라고 표시"를 골랐다. 숨기면 곧 열릴 박람회를 알 길이 없다.
- 상세를 200으로 주고 `openable: false`만 붙이기: 옛 앱은 칸을 몰라 지도를 열고 빈 화면을 그린다.
- 도면 등록 여부(FLOORPLANS)로 판정: 도면만 먼저 넣고 부스 인입 전이면 지도는 빈다. 실제로 놓인 부스를 본다.

## 확인할 것

- 열림 조회는 행사마다 한 줄(limit 1) 질의다. 홈 20개, 사이트맵 100개까지 병렬로 묻는다.
- 운영 dry-run은 하지 않았다(이 작업은 운영에 쓰지 않음). 머지 전 읽기 전용 경로 확인이 필요하다.
