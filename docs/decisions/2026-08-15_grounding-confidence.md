# 신뢰도 배지를 "필드 개수"가 아니라 "읽는 문장의 출처"로

**날짜**: 2026-08-15
**관련 파일**: `src/lib/feed/grounding.ts` · `src/lib/feed/grounding.test.ts`
**근거 감사**: `docs/qa/2026-08-15_grounding-audit.md` 발견 3

## 먼저, 감사의 진단이 틀렸다

감사는 발견 3을 이렇게 적었다.

> 하우스 아카이브는 99곳 전부 저작 해석이 있는데 confidence high는 0곳이다.
> **가장 잘 저작된 전시가 카드에서 "근거 보통"으로 표시된다.** 신뢰 신호가 거꾸로 간다.
> `valueTags`만 채우면 99곳이 한 번에 high가 된다.

**이 처방은 잘못됐다.** 하우스 아카이브 부스가 실제로 가진 건 저작 해석 한 줄과 공식
요약뿐이다 — `goodsKeywords` 0/99, `tips` 0/99, `thingsToDo` 0/99. 그 상태에서
`valueTags`를 채워 high로 올리면 **없는 근거를 있다고 말하는 것**이다(브랜드북 §4-5).

게다가 채울 방법도 마땅치 않았다. 부스 텍스트로 기존 테마 분류기를 돌려봤더니 99곳 중
64곳이 걸리긴 하는데, 결과가 틀렸다 — 덴마크 조명 브랜드 '루이스폴센'이 `craft/한국적`으로
분류된다. 그 분류기는 일러스트페어용 키워드 사전이라 디자인 브랜드에 맞지 않는다.
**억지로 돌리면 틀린 취향 신호를 데이터에 심는다.**

그래서 `valueTags`를 채우지 않았다. **하우스 아카이브의 "근거 보통"은 정확한 표시다.**

## 그럼 진짜 문제는 뭐였나

배지를 계산하는 방식 자체다. 예전 공식은 **enrichment 필드 개수**를 셌다.

```ts
const basic = [e?.summary, e?.goodsKeywords?.length, e?.tips].filter(Boolean).length;
const confidence = authored >= 2 ? "high" : authored >= 1 || basic >= 2 ? "medium" : "low";
```

여기서 두 가지가 어긋났다.

**(a) 질이 다른 부스가 같은 배지를 단다.** 로미가 자기 말로 해석해준 부스(하우스 아카이브)와
굿즈 목록·팁만 있는 부스가 똑같이 "근거 보통"이었다.

**(b) 화자 분리 이후로는 배지가 과장한다.** 작가 자기소개가 인용으로 밀려나 로미는
`'{이름}' 부스야`밖에 말하지 않는데, 그 요약이 `basic` 점수에 계속 잡혀
"근거 보통"이 뜬다. **카드에 안 보이는 필드가 배지를 올리고 있었다.**

## What — 무엇이 달라졌나

배지를 **사용자가 지금 읽는 1절이 어디서 왔는지**로 계산한다.

```
factSource   authored  저작 해석(roamInterpretation)
             official  공식 소개 인용
             derived   테마·굿즈 파생 / 굿즈
             name      부스명 폴백

충분(high)   authored + 저작 부가재료 1개 이상
             official + 저작 부가재료 2개 이상
보통(medium) authored 단독
             official + (저작 부가재료 또는 굿즈·팁)
적음(low)    derived · name — 로미가 부스를 설명한 게 아니다
```

**인용은 근거로 세지 않는다.** 남의 말이 붙어 있다고 로미가 그 부스를 아는 건 아니다.

덤으로 인용 노출 조건도 좁혔다. **요약이 실제로 1절에서 밀려났을 때만** 인용한다.
저작 해석이 있으면 요약은 애초에 1절 후보가 아니었으니 인용할 이유가 없다 —
하우스 아카이브의 주최 측 소개가 `"부스가 직접 쓴 소개"`로 잘못 붙던 것도 여기서 막힌다.
(이건 어제 화자 분리 작업이 만든 회귀였다.)

## 결과

| 전시 | | 충분 | 보통 | 적음 |
|---|---|---:|---:|---:|
| SIBF 241 | BEFORE | 16 | 80 | 145 |
| | AFTER | 16 | 79 | **146** |
| SIF 914 | BEFORE | 0 | 436 | 478 |
| | AFTER | 0 | 369 | **545** |
| 하우스 아카이브 99 | BEFORE | 0 | 99 | 0 |
| | AFTER | 0 | 99 | 0 |

**과장하던 배지 68개가 정직해졌다.** 전부 SIF·SIBF에서 요약이 인용으로 밀려났는데도
"근거 보통"을 달고 있던 부스다.

숫자만 보면 나빠 보이지만, 그게 실제 상태다. **배지가 낮아진 게 아니라 원래 낮았다.**
"정보 적음"이 545곳이라는 건 SIF 저작이 시급하다는 신호로 읽어야 한다 — 예전엔 그 신호가
가려져 있었다.

## 하우스 아카이브를 정말 올리려면

배지를 건드릴 게 아니라 재료를 채워야 한다. 가장 값싼 건 **`thingsToDo`** 다 —
부스당 "여기서 뭘 하면 좋은지" 한두 개. 99곳이 이미 저작 해석을 갖고 있어서
`thingsToDo`만 붙으면 그 자리에서 "근거 충분"이 된다.

`valueTags`는 사람이 부스를 보고 판단해야 한다. 기계 분류는 위에서 확인한 대로
틀린 답을 낸다.

## 테스트

밀려난 인용=적음)와 저작 해석이 있을 때 인용을 중복 노출하지 않는지.
