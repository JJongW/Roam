# 부스 상세 응답에 브랜드 이름(exhibitorName)을 싣는다

_2026-11-19. iOS 부스 상세의 브랜드 줄(Figma UI 19-A1, 11-19 Ted "A로 가.")이 브랜드 하트를 남기는 자리다. 그 줄과 스낵바(19-A2, 19-A4)는 브랜드 이름을 보여야 하는데, 부스 응답에는 `exhibitorId`만 있었다._

## 다섯 칸

- **결정(Ted)**: 브랜드 하트는 부스 하트와 따로 남긴다(11-17). 남기는 자리는 부스 상세 브랜드 줄(11-19, UI 19 A).
- **사실**: `GET /api/booths/[id]`는 `withBrandIds`로 `exhibitorId`, `participantId`만 붙였다. 브랜드 이름은 `exhibitor.canonical_name`에 있고, `/api/me/brand-hearts`의 `name`도 같은 칸(`getExhibitorNames`)을 읽는다.
- **해석**: 같은 칸을 읽어야 브랜드 줄, 스낵바, 마이페이지 "하트 남긴 브랜드"의 이름이 서로 같다. 부스 이름은 그 회차 자리 이름이라 브랜드 하트에는 맞지 않는다.
- **가설**: 없음.
- **미정**: 웹 부스 상세에도 브랜드 줄을 둘지.

## 무엇을 바꿨나

- `withBrandIds(repo, booths, { names: true })`이면 `exhibitorName`(문자열 또는 null)을 더 싣는다. 배정이 없는 부스는 키 자체가 없다(전과 같다).
- 이름 조회만 실패하면 id는 그대로 두고 이름만 null이다. 앱은 부스 이름으로 물러선다.
- 켜는 곳은 상세(`/api/booths/[id]`)뿐이다. 목록(`/api/exhibitions/[slug]/booths`)은 500곳마다 조회를 하나 더 얹지 않으려고 그대로 둔다.
- 키를 더하기만 하므로 지금 나가 있는 iOS 디코딩은 그대로다.

## 고르지 않은 것

- 회차별 표기 이름(`exhibition_participant.display_name`): 그 박람회에서 부르는 이름이라 부스 이름과 거의 같다. 브랜드 하트는 행사를 넘는 브랜드에 남기므로 `canonical_name`을 쓴다. 단점은 회차 표기와 다르게 보일 수 있다는 점.
- 목록 응답에도 이름 싣기: 지도 카드에는 아직 브랜드 줄이 없어 비용만 는다.
