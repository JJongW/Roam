# 근거 품질 감사 — 로미는 실제로 무슨 말을 하는가

_2026-08-15 · `feed/grounding.ts`의 사실절 생성 로직을 전 부스(1,254개)에 돌린 결과._

---

## 왜 이 감사를 했나

브랜드북은 Roam을 **"고를 근거를 주는 동행자"**로 정의한다. 그런데 근거는 코드가 아니라
**데이터**에서 나온다. 저작 필드가 비면 로미는 폴백으로 내려가고, 폴백까지 비면 부스명만 말한다.

**약속이 실제로 지켜지는지는 문서로는 알 수 없다.** 그래서 파이프라인을 그대로 돌렸다.

### 사실절 폴백 계층 (`grounding.ts` L66–74)

```
T1  roamInterpretation            저작 한 줄 — 로미가 자기 말로
T2  recommendationReasons[가치]    가치별 저작 근거
T3  summary 첫 조각                공식 소개 인용
T4  goodsKeywords[0]              "여기 {굿즈} 있어"
T5  booth.name                    "‘{이름}’ 부스야"   ← 마지막 안전망
```

|---|---:|---:|---:|---:|---:|
| 2026 서울국제도서전 | 241 | 16 (6.6%) | 80 (33.2%) | 0 | **145 (60.2%)** |
| 2026 서울일러스트레이션페어 | 914 | 0 (0%) | 809 (88.5%) | 27 (3.0%) | 78 (8.5%) |
| 하우스 아카이브 2026 | 99 | **99 (100%)** | 0 | 0 | 0 |
| **합계** | **1,254** | **115 (9.2%)** | 889 | 27 | **223 (17.8%)** |

**서울국제도서전에서 부스 10곳을 열면 6곳은 로미가 이름만 읽어준다.**

```
A102   "‘별빛들’ 부스야"
A103   "‘도서출판부카’ 부스야"
A107   "‘애플트리테일즈’ 부스야"
A110   "‘소동출판사’ 부스야"
A204   "‘안녕로빈’ 부스야"
```

이건 근거가 아니다. 사용자가 이미 화면에서 읽은 이름을 되돌려줄 뿐이다.
브랜드북 §4-2가 금지한 "가치 이름 되읽기"와 **구조적으로 같은 실패**다 —
이미 아는 걸 다시 말하는 것.

다만 안전망 자체는 제대로 작동한다. 폴백 145곳 중 이름이 코드뿐인 부스는 **0개**라
`'A1234' 부스야` 같은 최악의 발화는 나오지 않는다.

## 발견 1 · `recommendationReasons`는 한 번도 실행되지 않는다 ✅ 해결됨

`grounding.ts`는 T1(`roamInterpretation`)을 T2(`recommendationReasons`)보다 **먼저** 평가한다.

```ts
const fact = e?.roamInterpretation ?? (matchedReasons.length > 0 ? … )
```

그런데 SIBF에서:

```
roamInterpretation 보유          16곳
recommendationReasons 보유       16곳
reasons만 있고 해석은 없는 곳      0곳   ← T2가 뜰 수 있는 유일한 경우
```

**완전히 같은 16곳이다.** T1이 항상 이기므로 **T2는 도달 불가능한 분기**다.
가치별로 공들여 쓴 저작 문장이 사용자에게 **한 번도 도달한 적이 없다.**

감사 결과에서 T2가 전 전시 0%인 게 그 증거다.

**선택지 두 개:**

- **A. 저작 규칙을 바꾼다** — `roamInterpretation`은 가치 무관 기본 문장, `recommendationReasons`는 겹치는 가치가 있을 때만 쓰는 특화 문장으로 분리하고, **T2를 T1보다 먼저** 평가한다. 개인화가 실제로 작동한다.
- **B. 필드를 접는다** — `recommendationReasons`를 폐기하고 `roamInterpretation` 하나로 간다. 저작 부담이 줄고, `docs/booth-enrichment.md`의 "최소 필수 6종"에서 한 칸이 빠진다.

> **해결 (2026-08-15)** — 제3안을 택했다. **둘은 답하는 질문이 달라서 경쟁시킬 이유가 없었다.**
> `roamInterpretation`은 사실절(무엇), `recommendationReasons`는 근거절(왜 너한테)로 나눴다.
> 근거절은 내가 누른 부스가 있으면 그걸 쓰고, 없으면 겹치는 가치의 저작 근거로 채운다.
> 되살아난 저작 문장 **45개**, 저작 16곳 × 3유형 48건 중 **28건(58%)**에서 2절이 붙는다.
> → `docs/decisions/2026-08-15_grounding-two-clause.md`

## 발견 2 · SIF는 작가의 존댓말 자기소개를 로미 자리에 그대로 넣는다 ✅ 해결됨

SIF의 `enrichment.summary`는 `links-sif-2026.json`의 작가 자기소개(`intro`)다.
`grounding.ts`는 이걸 잘라서 **로미의 사실절**로 쓴다.

**809개 중 134개(16.6%)가 존댓말이다.**

```
피드 카드에 실제로 렌더되는 문장:
  "현실과 환상의 경계에 있는 소녀들의 이야기를 기록합니다"
  "안녕하세요! 순간을 기록하는 423희희입니다"
  "한국 전통문화를 재해석한 디지털 페인팅 작업을 합니다"
```

로미는 1인칭 반말로 말해야 하는데, 여기선 **작가가 1인칭 존댓말로 자기를 소개**한다.
화자가 뒤바뀐다. 브랜드북 §1-1·§1-3 동시 위반이고, **어제 만든 brand-voice 테스트로는 절대 못 잡는다** —
사전이 아니라 데이터라서.

일부는 홍보 문구까지 그대로 들어온다(18곳):

```
  "맹수만 판매합니다"
  "일러스트북 <갈라테이아> 교보문고 판매중"
  "썸띵비러브드(DM❌) | 다꾸러가 만드는 다꾸용 다이어리"
```

브랜드북 §1-4 영업·과장 금지 위반이 **데이터 경로로 우회 유입**되고 있다.

**이미 해법이 코드에 있다.** `booth/about.ts`는 작가 블러브를 로미 말로 고쳐 쓰지 않고
**존댓말 인용으로 분리**한다. 근거 카드에도 같은 분리를 적용하면 된다:

```
로미:  ‘{부스}’, 소녀들의 이야기를 그리는 곳이야.
인용:  “현실과 환상의 경계에 있는 소녀들의 이야기를 기록합니다” — 작가 소개
```

> **해결 (2026-08-15)** — `booth/voice.ts`의 `isSomeoneElsesVoice()`가 화자를 판별해
> 로미의 사실절에서 빼고 출처를 밝힌 인용(`Grounding.quote`)으로 내린다. 사실절은
> `boothAbout().romi`(테마·굿즈 파생)로 채운다. SIF 화자 역전 **130건 → 0건**.
> 부스명 폴백은 78 → 92로 14곳 늘었다(정보는 인용에 남는다).
> → `docs/decisions/2026-08-15_grounding-speaker-separation.md`

## 발견 3 · 하우스 아카이브는 100% 저작인데 confidence가 영원히 "근거 보통" ⚠️ 진단 정정

99곳 전부 `roamInterpretation`이 있는데 **confidence high는 0곳**이다.

```ts
const authored = [ roamInterpretation||matched, valueTags?.length>0, todo.length>0 ]
                 .filter(Boolean).length;          // → 항상 1
const confidence = authored>=2 ? "high" : …        // → 영원히 medium
```

`valueTags`와 `thingsToDo`가 비어 있어 점수가 1에서 멈춘다.
**가장 잘 저작된 전시가 카드에서 "근거 보통"으로 표시된다.** 신뢰 신호가 거꾸로 간다.

`valueTags`만 채우면(부스당 1~2개, 기계적 작업) 99곳이 한 번에 high가 된다.

> **정정 (2026-08-15)** — 위 처방이 틀렸다. 하우스 아카이브 부스가 가진 건 저작 해석
> 한 줄과 공식 요약뿐이다(`goodsKeywords` 0/99 · `tips` 0/99 · `thingsToDo` 0/99).
> 그 상태에서 `valueTags`를 채워 high로 올리는 건 **없는 근거를 있다고 말하는 것**이다.
> 기계 분류도 안 통한다 — 기존 테마 분류기를 돌리면 덴마크 조명 브랜드가 `craft/한국적`이
> 된다(일러스트페어용 키워드 사전이라). **"근거 보통"은 정확한 표시다.**
>
> 진짜 문제는 배지 계산식이 **enrichment 필드 개수**를 세는 것이었다. ① 저작 해석이 있는
> 부스와 굿즈 목록만 있는 부스가 같은 배지를 달고, ② 화자 분리 이후엔 인용으로 밀려난
> 요약이 점수에 계속 잡혀 **과장**했다. 배지를 **1절의 출처**로 재정의했다.
> 과장하던 배지 **68개**가 정직해졌다(전부 SIF·SIBF).
> 하우스 아카이브를 정말 올리려면 `thingsToDo`를 채우는 게 가장 값싸다.
> → `docs/decisions/2026-08-15_grounding-confidence.md`

## 저작 우선순위 — SIBF

| Tier | 대상 | 필요한 것 | 효과 |
|---|---:|---|---|
| **A** | **80곳** | `roamInterpretation` 한 줄 | T3 → **T1**. 요약이 이미 있어 읽고 한 줄 쓰면 끝 |
| ↳ 그중 | **29곳** | 같은 한 줄 | `thingsToDo`가 이미 있어 **confidence까지 high** |
| **B** | **145곳** | 공식 정보부터 (summary) | T5 탈출. 취재·입력 필요 |

**A부터 하는 게 압도적으로 효율적이다.** 80줄만 쓰면 SIBF의 저작 커버리지가
6.6% → **39.8%**로 오른다. 폴백률은 그대로지만, 로미가 인용이 아니라 자기 말로 말하는 부스가 5배가 된다.

전체 목록은 `sibf-authoring-priority.md`, 전 부스 원자료는 `grounding-audit-all-booths.csv`.

## 감사가 못 본 것

- **실제 노출 가중치.** 피드는 6칸이고 랭킹으로 고른다. `popularity`가 전 부스 50으로 균일해서
  "폴백 부스가 실제로 얼마나 자주 피드에 뜨는지"는 이 감사로 알 수 없다.
  스코어링을 태워 노출 가중 폴백률을 재면 우선순위가 더 정확해진다.
- **근거절(2절).** 최근 긍정 반응이 필요해 사용자 이력 없이는 시뮬레이션이 안 된다.
  사실절만 봤다.
- **문장이 실제로 좋은지.** T1이어도 그 한 줄이 부스를 제대로 설명하는지는 사람이 읽어야 한다.
