# 취향 % 재정의 — 예측 정확도

날짜: 2026-08-03

## 배경

로미 필의 "취향 {pct}%"는 지금 `tasteProgress(brain)`(`src/lib/memory/progress.ts`)이
계산한다 — 본 부스 수(접촉량, 0.50) + 관심 확신도 깊이(0.33) + 관심 폭(0.17)의 가중합.
사용자가 이 숫자의 근거를 물었을 때 설명이 안 됐다:

- 절반이 **접촉량**이다. `feed_click`(카드 클릭, 0.3)도 여기 들어가 취향을 전혀
  드러내지 않아도 카드를 눌러보기만 하면 오른다. 검색(`search_query`, 1.3)도 마찬가지다.
- **서버 공식과 클라이언트 공식이 다르다.** `ReactionBar.react()`가 자체 감쇠 곡선으로
  낙관적 bump를 하고(`Math.max(floor, Math.round((100-progress)*factor))`), 새로고침하면
  서버의 `tasteProgress` 값으로 덮인다 — 둘이 어긋나면 숫자가 오르내린다.
- **100%에 "다 파악했다"는 완료 선언이 붙어 있다**(`companion-bar.tsx`,
  `progress >= 100 && !doneRef.current`). 접촉량 기반이라 온보딩 완료 신호로는
  그럴듯했지만, 사용자가 원하는 의미("로미가 나를 제대로 알아들었는가")와 안 맞는다.

사용자가 원하는 것: **"로미가 예측했고, 사용자가 그 예측을 확인해줬다"만 %를 움직인다.**
카드를 누르거나 검색하는 건 궁금함이지 판정이 아니다.

## 채점 모델

부스에 반응하는 순간, 그 부스가 사용자의 **확신 가치**(브레인 관심 confidence ≥ 0.25,
`curate.ts`·`progress.ts`가 이미 쓰는 임계값)와 겹치는지를 얼려서 기록한다.
`interestScore(booth, confidentSlugs)`(`src/lib/engine/scoring.ts`, 기존 함수 재사용)가
0보다 크면 `confident`, 아니면 `uncertain`.

| 반응 | confident 부스 | uncertain 부스 |
|---|---|---|
| 끌림 | +1 (맞춤) | +1 (뜻밖의 적중) |
| 나중에 | +0.3 (약한 맞춤) | +0.3 |
| 별로 | −1 (틀림) | 0 (탐색 — 벌점 없음) |
| 가봄 + 되묻기 "끌렸어" | +1 | +1 |
| 가봄 + 되묻기 "별로" | −1 | 0 |
| 가봄 (안 답함) | 채점 제외 | 채점 제외 |

규칙: **자신 있다고 한 것만 틀렸을 때 깎인다.** `uncertain` 등급은 맞으면 가산되고
틀려도 무해하다 — 낯선 부스를 찔러보는 게 벌이 되면 안 된다.

정확도 = 채점된 판정들의 점수 합 ÷ 판정 수 × 100.

**표시 문턱** — 판정 5개 미만이면 숫자 대신 말로만 보여준다(거짓 정밀도 방지):

| 판정 수 | 표시 |
|---|---|
| 0 | "아직 널 모르겠어. 둘러보면서 알려줘." |
| 1~4 | "조금씩 감이 오는데, 좀 더 봐야겠어." |
| 5 (막 넘긴 순간, 1회) | "이제 좀 감이 온다. 계속 맞춰볼게." |
| 5 이상 | "취향 {pct}%" |

**범위는 전시 하나 안에서만.** `booth.exhibition_id`로 스코프 — 전시를 여러 개
열어둔 사용자는 전시마다 다른 %를 본다. 브레인(누적 관심 지식)은 전시를 넘어
이어지지만, 이 숫자는 전시마다 새로 쌓는다.

**`feed_click`·`search_query`는 관여하지 않는다.** 브레인 관심 가중치(추천 랭킹용)에는
계속 들어가지만, 정확도 계산에서는 제외한다.

## 데이터 모델

`booth_note`에 컬럼 두 개 추가(마이그레이션, 운영은 SQL Editor에서 별도 실행 필요):

```sql
alter table booth_note
  add column judged_class text,  -- 'confident' | 'uncertain' | null
  add column retro        text;  -- 'liked' | 'disliked' | null
```

- `judged_class`는 **상태를 쓸 때마다 다시 계산해서 덮어쓴다.** 그 순간의 브레인
  확신도를 얼린다. 상태를 해제하면(반응 취소) 같이 null로 지운다.
- `retro`는 `status='visited'`일 때만 의미 있다. `가봄` 자체는 채점 제외 — 되묻기에
  답해야 그때부터 채점 대상이 된다.
- **기존에 쌓인 반응은 소급 채점하지 않는다.** 지금 브레인 확신도로 과거 행동을
  되짚어 판정하면 그 시점엔 없던 지식으로 채점하는 셈이다. 그 부스에 다시 반응해야
  채점 대상이 된다 — 배포 직후엔 숫자가 조용히 0에서 다시 쌓인다(자연스러움, 판정
  5개 전까진 어차피 말로만 보여준다).

`BoothNote` 타입(`src/lib/types/index.ts`)에 `judgedClass?: "confident" | "uncertain"`,
`retro?: "liked" | "disliked"` 추가.

## 쓰기 경로

**1) 반응 쓰기** — 기존 `PUT /api/me/notes/[boothId]`를 확장. 상태를 쓸 때마다
서버가 `judged_class`를 계산해 같이 저장(브레인은 이미 `readBrain(user.id)`로 접근
가능 — `curate.ts`와 같은 패턴).

**2) 되묻기 답** — 새 엔드포인트 `POST /api/me/notes/[boothId]/retro { liked: boolean }`.
상태 변경이 아니라 의견 추가라 분리한다 — `status`는 `visited`로 유지(지도 색 안 바뀜),
`retro`만 채운다. `visited`가 아닌 부스엔 400.
`judged_class`는 **이 요청에서** (반응 당시가 아니라) 계산해 얼린다 — `가봄` 자체는
무판정이라 얼릴 게 없고, 실제 판정은 되묻기에 답하는 이 순간 드러난다.

**3) 두 엔드포인트 다 응답에 정확도를 실어 보낸다** — `{ note, taste: { judgedCount,
pct } }`(`pct`는 판정 5개 미만이면 `null`). **클라이언트는 이 값을 그대로 표시할 뿐
자기 공식으로 계산하지 않는다.**

**4) "감 잡았다" 1회 이벤트** — 서버가 이번 쓰기로 `judgedCount`가 4→5를 넘겼는지
판단해 `justReachedInsight: true`를 같이 보낸다. 클라이언트는 그 플래그를 볼 때만
1번 그 대사를 말한다(`companion-bar.tsx`의 기존 `progress>=100` 1회 이벤트 패턴 재사용,
기준만 판정수 5로 교체).

**5) 지도의 되묻기** — 부스 시트에서 `가봄`을 누르면, `retro`가 없는 동안은 시트를
열 때마다 한 줄("여기 어땠어? [끌렸어] [별로]")이 조용히 떠 있다. 강제 아님 —
무시하면 사라지고 다음에 열면 또 뜬다.

**6) 관람 마치기 회고** — `visited`이면서 `retro`가 없는 부스를 최대 3~5개 묶어
"오늘 갔던 데 중에 어디가 괜찮았어?"로 한 번에 되묻는다. 기존 `POST /api/me/reflect`
흐름에 얹는다.

**7) 지도 코치마크 한 줄 추가** — "걸으면서는 가봄·별로·끌림만 반사적으로 누르고,
판단은 나중에 물어볼게." (반복 입력 동적 감지는 이번 범위 밖 — 코치마크 한 줄로 기대치를
먼저 세팅한다.)

**8) 클라이언트 정리** — `ReactionBar.react()`의 `bumpProgress` 감쇠 휴리스틱 삭제.
반응 성공 시 응답의 `taste.pct`/`judgedCount`를 companion 스토어에 그대로 반영.

## 대체되는 기존 코드

- `src/lib/memory/progress.ts`의 `tasteProgress(brain)` — 접촉량·깊이·폭 가중합
  전체가 이 기능으로 교체된다. 정확도는 이제 브레인이 아니라 `booth_note` 직접
  집계에서 나온다.
- `companion-bar.tsx`의 `progress >= 100` 완료 이벤트 — 판정수 5 도달 이벤트로 교체.
- `companion.ts` 스토어의 `progress: number` — `tasteJudged: number`·
  `tastePct: number | null` 두 필드로 분리(숫자 없음/말만 상태를 명확히 구분).

## 엣지케이스

- **확신 가치가 아직 없을 때**(온보딩 막 끝난 시점) — 모든 부스가 `uncertain`
  등급이 된다. `uncertain`은 틀려도 안 깎이므로, 확신 가치가 쌓이기 전까진 숫자가
  내려갈 일이 없다(맞으면 오르기만) — 별도 분기 없이 채점 규칙 자체가 이 경우를
  안전하게 감싼다.
- **반응을 여러 번 바꿔 누르면**(끌림→나중에→취소) — 판정은 **항상 최신 상태
  하나만** 반영한다. 과거 판정을 누적하지 않는다. `booth_note.status`가 값 하나만
  갖는 지금 구조와 그대로 맞아떨어진다.
- **전시 여러 개 동시 진행** — `booth.exhibition_id`로 스코프하므로 전시마다
  독립된 %.
