# Roam이 쓴 데이터에서 가운뎃점(·) 제거

_2026-11-18 · Ted 결정: "가운뎃점은 빼야할 것 같고 전시는 일단 둬."_

## 결정
- Roam이 쓰고 사용자가 보는 데이터에서 가운뎃점을 뺀다(브랜드 규칙 §5).
- "전시"는 이번에 건드리지 않는다. 합니다체 문장 끝도 그대로 둔다.
- 브랜드나 주최가 쓴 원문은 고치지 않는다(§1, 2026-11-09).

## 바꾼 곳
- `src/lib/booth/summaries.json` 요약 80건(운영에서 바로 쓰이는 캐시)
- `src/lib/booth/enrichment-sibf-2026.json` 저작 칸 전부(summary, tips, recommendationReasons 등)
- `src/lib/booth/enrichment-sif-2026.json` goodsKeywords 5건
- 하우스 아카이브 roamInterpretation 3건(enrichment JSON, 인입 파일)
- 마곡리빙마켓 인입 파일 enrichment와 `data/verified`의 같은 칸(둘을 같은 값으로 유지)
- mock 시드의 행사 소개, 교통, 안내, 분류 이름, 부스 설명 틀(`이름 · 부스 코드` → `이름 부스 코드`)

## 바꾸는 법
- 나열은 쉼표, 이름과 코드 사이는 띄어쓰기 한 칸. 뜻은 그대로 두고 내용은 더하지 않는다.
- 쉼표가 읽기 어려운 몇 곳만 "와/과"를 썼다(예: "실제 위치와 크기로", "유무선").

## 안 바꾼 곳
- 하우스 아카이브 enrichment.summary: 주최 측 브랜드 디렉터리 소개 원문이다
  (`scripts/gen-house-archive-enrichment.mjs`, 0030, 0032).
- 인입 파일의 description, longDescription, category, 브랜드 intro: 브랜드나 주최 원문.
- 마이그레이션 SQL: 이미 적용된 기록이다. 운영 DB 값은 이 PR로 바뀌지 않는다.
- `booth/themes.ts` 라벨: 코드가 `·`로 라벨을 쪼개 쓴다. 로직을 같이 바꿔야 해서 따로 다룬다.
