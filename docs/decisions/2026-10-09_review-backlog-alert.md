# 검수 적체 알림 — 아무도 안 보고 있는 걸 알려준다

**날짜**: 2026-10-09
**관련 파일**: backlog.ts · sweep.ts · kr.roam.sweep.plist · install.sh

## 사용자 프롬프트 원문

> Admin에서 검수가 진행이 안되거나 확인이 되어야하는데 확인이 안된 사항이 계속 있으면
> 알림을 줄 수가 있을까?

> macmini쪽에 워커를 만들고 해당 워커가 admin을 돌아서 안되어있는 부분을 알림을 주는
> 방식은 어떨까? 슬랙 incoming webhook이 제일 좋은 것같기도 하네.

> 웹훅 URL은 env로 관리해야해?

> 오케이 떴어. 이제부터 너가 만들어서 실제 적제수치까지 다 ㄱㄱㄱㄱ

## 그걸 이해한 내 답장

맥미니에 점검을 하나 두는 데는 동의하되 **"admin을 돈다"를 한 군데 고치겠다**고 했다 —
admin 화면을 긁지 말고 admin이 쓰는 같은 저장소 함수를 부른다. admin은 코드 게이트 뒤의
RSC라 HTML을 긁으면 화면을 고칠 때마다 알림이 조용히 깨지고, 워커는 이미 서비스 롤로
저장소에 직접 붙으므로 화면과 같은 사실을 본다.

그리고 **잡 큐를 쓰지 않겠다**고 했다. 자기 재예약 체인은 한 번 실패하면 조용히 끊기는데,
끊긴 걸 알려주는 게 바로 이 점검이다. 자기가 감시할 대상 위에 올라타면 안 된다.
launchd는 맥미니가 꺼져 있던 일정을 깨어날 때 한 번 돌려주니 집 컴퓨터에도 맞다.

웹훅 URL은 `.env`가 맞다고 답했다 — 워커가 이미 `.env`를 읽고 worktree가 심볼릭 링크로
같은 파일을 가리키므로 새로 배선할 게 없다. `src/lib/env.ts`에는 넣지 않는다. 거기는 Next
앱이 쓰는 값이고 이건 워커만 읽는다. Vercel 환경변수에도 넣지 않는다 — 이 코드는 Next에서
안 돈다.

## What — 무엇이 달라졌나

사람의 확인을 기다리는 일이 며칠째 쌓여 있으면 **슬랙으로 하루 한 번 알려준다.** 지금까지는
`/admin`을 열어보지 않으면 알 길이 없었다.

보는 것은 넷이다 — 묵은 검수 대기 초안(참가사 셀프 폼·주최 측 제출도 같은 큐를 탄다),
확인 안 된 브랜드 신원, 하루 넘게 안 집힌 잡, 실패한 잡.

처음 돌린 결과가 알림이 필요한 이유를 그대로 보여준다.

```
검수 대기 초안      537건 (그중 3일 넘은 것 460건, 가장 오래된 것 7일)
실패한 잡           1건
확인 안 된 브랜드    0건
```

## Why — 왜 필요했나

초안 파이프라인은 다 돌아가는데 **승인만 멈춰 있어도 아무 일도 안 일어난다.** 초안이 쌓일수록
로미가 할 말이 늘어나야 하는데, 537건이 큐에 앉아 있는 동안 사용자가 보는 것은 7일 전과
같다. 멈춘 것이 **조용하다**는 게 문제였다 — 실패는 로그에 남지만, 아무도 안 보는 건 아무
흔적도 안 남긴다.

워커가 멈춘 경우도 같다. 맥미니는 집 컴퓨터라 정전·재부팅으로 멈추는 게 정상 상황인데,
멈춘 걸 알아차릴 방법이 "잡이 왜 안 끝나지"라고 누군가 궁금해하는 것밖에 없었다.

## 판단 근거

**조용한 날엔 아무것도 보내지 않는다.** 매일 "이상 없음"이 오면 아무도 안 읽고, 그러면
정작 적체가 생긴 날에도 안 읽는다. 알림의 가치는 빈도가 아니라 **뜨면 뭔가 있다**는 신뢰다.

**숫자를 단정하지 않는 경우를 만들었다.** 저장소의 `limit`은 하드 캡이고 정렬이 신뢰도
순이라, 상한에 걸리면 전체 수도 "가장 오래된 것"도 사실이 아니게 된다. 실제로 첫 실행에서
500으로 잘린 값을 그대로 보고할 뻔했다(진짜는 537). 상한에 걸렸으면 "N건 이상"으로 적는다 —
조회 한계가 사실로 둔갑하는 건 이 레포가 이미 여러 번 당한 종류의 사고다.

**잡은 다른 기준으로 센다.** 초안은 3일, 잡은 하루다. 사람이 사흘쯤 안 보는 건 있을 수
있는 일이지만, 잡이 하루 동안 안 집혔다면 그건 사람 문제가 아니라 워커가 죽은 것이다.
같은 기준으로 묶으면 둘 중 하나는 늦게 알게 된다.

**집계를 `src/lib`에 두고 워커는 실행만 한다.** 워커 폴더는 테스트 대상이 아니라서, 거기에
로직을 두면 검증이 안 된다. 기존 초안기(`runDraftBatch`)와 같은 모양이다.

**재부팅마다 보내지 않는다.** `RunAtLoad`를 켜지 않았다 — 맥미니를 켤 때마다 알림이 오면
신호가 아니라 소음이 된다.
