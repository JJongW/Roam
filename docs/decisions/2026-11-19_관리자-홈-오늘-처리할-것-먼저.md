# 관리자 홈: 오늘 처리할 것 먼저

_2026-11-19. Ted의 관리자 홈 화면 비평에서 출발. 박람회 선택기 범위 정리(#183) 다음 단계._

## 왜

옛 홈은 지표부터 보여 줬고, 오류와 데이터 이슈는 맨 아래에 있었다. "오늘 무엇을 처리해야 하나"를 알려면 끝까지 내려가야 했다.
머리 지표도 어긋나 있었다. 로미 학습 곡선은 "추천 정확도"를 재는데, 로미는 11-08부터 추천자가 아니라 동행자다(브랜드 규칙 §5).
취향 지형은 "온보딩에서 확정한 가치"를 보여 줬는데, 온보딩으로 취향을 확정하지 않는다(§3).

## 무엇을 바꿨나

1. **처리할 것**: 아티클 승인, 브랜드 연락 할 일, 브랜드 확인(이름만 같음), 초안 검수, 대조 검수, 인입 대기, 오류, 데이터 이슈.
   할 일이 있는 카드만 색(primary, warning, destructive 토큰)을 쓰고 앞으로 온다. 0은 "없어요", 셀 수 없으면 "준비 전"이나 "읽지 못했어요"로 보인다. 0으로 위장하지 않는다.
   건수는 각 큐 화면이 쓰는 저장소 함수와 계산을 그대로 쓴다(`src/lib/admin/today-load.ts`). 대조 검수 계산은 `diffVerified`로 빼서 화면과 홈이 같이 쓴다.
2. **다가오는 박람회**: 60일 안에 시작하는 박람회. 운영에 없는 박람회도 `data/exhibitions/*.json`에서 읽는다. 준비 순서는 SDF 런북을 일반화했다: 배치도(FLOORPLANS 등록) → 행사 등록 → 브랜드 → 부스.
3. **지표**: "여러 행사"를 "두 곳 이상 방문한 사용자 비율"로 바꿨다.
4. 로미 학습 곡선, 취향 지형, 취향 이동은 `/admin/analytics` 아래 "참고 지표"로 옮겼다. 로직은 그대로다.
5. 홈만 `max-w-6xl`(`data-admin-wide`). 다른 화면 폭은 그대로다.

## 고르지 않은 방향

- 새 집계 쿼리나 집계 테이블: 지금 박람회 수에서는 이미 있는 함수로 충분하다. 대신 홈 한 번 열 때 읽는 양이 늘었다(연락 보드는 끝난 지 30일 안의 박람회마다 한 번, 대조는 확인 파일이 있는 박람회마다 전 필드 조회 한 번).
- 데이터 이슈를 모든 박람회로 세기: 끝난 박람회의 빈 칸이 늘 큰 숫자로 떠서 "조용히"가 안 된다. 열려 있거나 다가오는 박람회만 센다.
- 인입 대기를 "일부만 들어감"까지 가리기: 인입 미리보기가 하는 일이라 여기서는 "운영에 행사가 없거나 비어 있음"만 본다.
