# 브랜드 프로필(0061) 운영 적용 절차

_작성 2026-11-03. 브랜치 `feat/admin-brands`. 아직 운영에 적용하지 않았다._

## 무엇이 들어가나

`supabase/migrations/0061_brand_profile.sql` 하나에 세 테이블과 함수 둘이 있다.

| 이름 | 종류 | 쓰는 곳 |
|---|---|---|
| `brand_profile_field` | 테이블 | 브랜드와 출전 칸(출처, 확인 상태, 갱신일, 누가) |
| `brand_contact`, `brand_contact_log` | 테이블 | 출전 단위 연락 기록과 VOC |
| `move_brand_profile_fields(text, text, text)` | 함수 | 브랜드를 합칠 때 칸을 한 트랜잭션으로 옮긴다 |
| `validate_brand_contact_exhibition()` | 트리거 함수 | 연락 기록의 박람회가 부스와 같은지 |

전부 RLS를 켜고 정책을 두지 않는다(서비스 롤 전용). 기존 테이블은 바꾸지 않는다.

## 순서

1. **마이그레이션**: Supabase SQL Editor에서 0061 전체를 실행한다(레포 규약: 적용은 손으로).
2. **확인 쿼리**(아래)로 테이블, 함수, RLS를 본다.
3. **배포**: `feat/admin-brands`를 main에 합쳐 Vercel이 배포한다. 0061 없이 배포하면 `/admin/brands`가
   `brand_profile_field` 조회에서 500을 낸다 — 그래서 1이 먼저다.
4. **워커 재시작**: 맥미니의 Roam-worker를 새 커밋으로 맞추고 launchd 잡을 다시 띄운다. 새 잡 종류
   `brand_profile_draft`는 새 워커만 안다. 옛 워커가 먼저 집으면 "처리기가 없는 잡 종류"로 실패로
   남는다(버리지 않는다). Roam-worker는 돌고 있는 실행본이라 Ted가 직접 하거나 승인 후에 한다.
5. **운영 dry-run**: `/admin/brands`, 브랜드 하나의 상세, `/admin/brands/links`를 열어 읽기만 해 본다.
   쓰기 확인이 필요하면 테스트용 브랜드 하나에 칸 하나를 저장했다가 비운다.

방문객 부스 화면(`/booths/[id]`, `GET /api/booths/[id]`)도 브랜드 소개를 읽지만, 조회가 실패하면 소개 없이
뜨도록 접어 두었다(0061 전이어도 500이 나지 않는다).

## 초안 잡은 박람회 단위로 (2026-11-03 Ted 결정)

- 백필(모든 박람회)은 초안 잡을 넣지 않는다. 새 출전에 따른 stale 표시만 한다.
- 인입(박람회 하나)은 그 박람회에 새 출전이 이어진 **기존** 브랜드만 잡에 넣는다.
- 새 브랜드는 관리자 `/admin/brands`에서 박람회를 고른 뒤 "<박람회> 브랜드 초안 만들기"로 넣는다
  (`POST /api/admin/brands/exhibition-drafts`). 이미 다 채운 곳과 대기 중인 곳은 빠진다. 잡 하나에 20곳.

### 운영 첫 실행 순서

둘 다 아직 Roam에 인입 전이다. 한 박람회의 초안과 검수를 끝내고 다음으로 간다.

1. **문구전 2026 겨울**
   1. `/admin/intake`로 인입(intake.v1, 도면 등록 포함 — CLAUDE.md "새 전시 붙이기")
   2. 인입이 브랜드 연결까지 한다. `/admin/brands/links`에서 이름만 같은 짝을 고른다
   3. `/admin/brands`에서 박람회를 고르고 "브랜드 초안 만들기" → 워커가 처리
   4. 큐 확인: `select status, count(*) from job where type = 'brand_profile_draft' group by 1`
   5. 브랜드 목록 "확인 필요" 필터로 AI 초안과 게이트에 걸린 소개를 검수
2. **새해 준비상점 N.27** — 1과 같은 순서. 문구전과 겹치는 작가는 인입 때 기존 브랜드에 이어지고,
   그 브랜드는 인입이 자동으로 잡에 넣는다(품목, 가격대, 대표 작품은 stale로).

큐를 비워야 하면 `update job set status = 'cancelled' where type = 'brand_profile_draft' and status = 'queued';`

## 되돌리기

데이터까지 지운다. 연락 기록과 칸을 남겨야 하면 먼저 떠 둔다
(`copy (select * from brand_profile_field) to stdout with csv header` 등, 또는 SQL Editor에서 결과 내보내기).

```sql
drop function if exists move_brand_profile_fields(text, text, text);
drop table if exists brand_contact_log;
drop table if exists brand_contact;
drop function if exists validate_brand_contact_exhibition() cascade;
drop table if exists brand_profile_field;
```

되돌린 뒤에는 앞 커밋으로 배포를 돌리고, 대기 중인 `brand_profile_draft` 잡을 `cancelled`로 바꾼다.
`change_log`의 `brand_profile_field` 기록은 남아도 해가 없다(엔티티가 text라서).

## 워커가 브랜드 사이트를 읽는 방식

- 인스타그램과 판매 페이지는 읽지 않는다(`src/lib/brands/draft.ts` `mayFetch`).
- robots.txt를 먼저 본다. `RoamBot` 그룹이 있으면 그걸, 없으면 `*`. robots.txt가 없으면(4xx) 읽고,
  서버 오류나 응답 없음이면 읽지 않는다.
- 같은 호스트에는 2초 간격, 요청마다 8초 타임아웃, 브랜드당 사이트 최대 3곳, 본문 6천 자까지.
- User-Agent: `RoamBot/1.0 (+Roam brand profile drafter; contact: instagram.com/withromi.con)`
  (`src/lib/brands/polite-fetch.ts`).

## 알려진 한계

- `mergeExhibitor` 전체(참가 사실 옮기기, 후보 정리, 칸 옮기기, 브랜드 지우기)는 아직 한 트랜잭션이 아니다.
  칸 옮기기만 함수 하나로 묶었다. 전체를 SQL 함수로 옮기는 건 다음 단계.
- 워커가 읽는 판단 기준은 코드 안 프롬프트(`src/lib/brands/draft.ts`)다. 기준 문서
  (`Roam-design/docs/content/engine/brand-profile-spec.md`)가 바뀌면 같이 고친다.

## 설계 결정과 이유 (/why)

결정한 사람: Ted(2026-11-03, 헤더 세션 전달). 구현 판단은 근거와 함께 적는다.

### 1. 브랜드 칸은 칸별 테이블(`brand_profile_field`)에 둔다 — `exhibitor.metadata`가 아니라

- 모든 칸에 출처, 확인 상태, 갱신일, 누가가 붙는다(기준 문서 5장). jsonb 한 덩어리면 칸 하나를 고칠 때
  전체를 읽고 다시 써야 해서, 워커와 운영자가 다른 칸을 동시에 쓰면 한쪽이 사라진다.
- 상태값을 check 제약으로 막고, "AI 초안 칸 전부" 같은 조회에 인덱스를 쓴다.
- 출전 칸(4장)도 같은 모양이라 한 테이블에 둔다. `exhibitor.metadata`는 지금 쓰는 곳이 없다.
- 대가: 테이블이 하나 늘고 화면이 칸을 따로 읽는다. PostgREST upsert가 부분 unique 인덱스를 못 써서
  id를 `ex:<exhibitor>:<field>` / `pt:<participant>:<field>`로 정해 둔다(check 제약으로 강제).

### 2. 부스 화면의 소개는 브랜드 공식 소개가 먼저다

- 공식 소개는 브랜드에 하나만 두고, 어느 박람회 부스에서든 같은 소개를 보여 준다(Ted 결정 — 박람회마다
  소개를 새로 받지 않게).
- 우선순위: 브랜드 공식 소개(말투 게이트 통과본) > 부스 저작 요약(`enrichment.summary`) > 부스 원문.
- 근거: 레포의 부스 요약은 대부분 공개 자료를 정리한 초안이고(`lib/booth/about.ts`), 원문과 같은 종류의
  설명 문장인데 말투를 고치지 않았다. "설명 문장은 Roam 말투로"(Ted 결정)를 지키는 건 게이트를 넘은 브랜드
  소개뿐이다.
- 대가: 그 회차에만 맞는 말이 부스 요약에 있으면 가려진다. 회차별 정보는 출전 칸과 이벤트가 맡는다.

### 3. 초안 잡은 박람회 단위로만 넣는다

- 첫 실행 규모를 박람회별로 나눈다(Ted 결정). 백필은 모든 박람회라 잡을 넣지 않는다 — 새 브랜드가 한꺼번에
  1천 곳 넘게 큐에 들어가면 요금과 검수량을 가늠할 수 없다.
- 넣는 경로: 관리자 "이 박람회 브랜드 초안 만들기", 브랜드 상세 "초안 만들기", 인입(박람회 하나)이 기존
  브랜드에 새 출전을 이었을 때 그 박람회 것만.
- stale 표시(품목, 가격대, 대표 작품)는 LLM이 없어 백필에서도 한다.

### 4. 워커 판단 기준(프롬프트)은 코드에 둔다

- 워커는 Roam 레포(Roam-worker 실행본)만 가지고 돈다. Roam-design 문서를 런타임에 읽으면 레포 밖 파일에
  의존하고, 그 문서가 바뀔 때 배포 없이 워커 행동이 바뀐다.
- 프롬프트는 칸 key, 품목과 결 목록, 말투 게이트와 맞물려 같은 곳에서 테스트로 지켜야 한다
  (`draft.test.ts`가 해요체, "전시", 가운뎃점 규칙 문구를 검사한다). 부스 초안기도 같은 관례다.
- 원본 규칙이 바뀌면(00_brand-rules.md, 02_voice-tone.md, brand-profile-spec.md) 코드와 테스트를 같이 고친다.

### 그 밖의 Ted 결정(2026-11-03)

- 확실한 짝(인스타, 도메인 같음)은 연결 확인 없이 바로 잇는다.
- 사실 칸은 collected부터, 설명 문장은 말투 게이트 통과본부터 앱에 보인다. 게이트를 못 넘으면 ai_draft.
- 에디터가 고친 소개는 게이트에 걸려도 저장하고 경고로 보인다.
- 관리자 저장 예외 둘(작가 확인, 부스 정보 가져오기), 품목과 결 목록, 합칠 때 대상 칸 유지.
- 브랜드 자체 사이트 읽기는 켜고, 판매 페이지와 인스타는 끈다.
