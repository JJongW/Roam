## P0 — 홈이 근거 없는 추천을 주장한다

**위치:** `src/app/(visitor)/page.tsx:91-107` · `src/lib/i18n/dictionaries.ts:180`

첫 번째 전시에 "로미 추천" 뱃지를 달고 이 문장을 출력한다:

> **네가 고른 관람 성향을 기준으로 먼저 보여줄게.**

그런데 그 순서는 취향과 아무 관계가 없다:

| | 정렬 기준 |
|---|---|
| 운영(Supabase) | `order("id", ascending)` — `supabase/repository.ts:477` |
| mock | 배열 삽입 순서 — `mock/repository.ts:91` |

`HomePage`는 `listExhibitions`와 `getCurrentUser`만 호출하고 **`getUserBrain`을 부르지
않는다.** 개인화 데이터가 스코프에 아예 없다. 코드 주석도 스스로 인정한다 —
*"추후 가치 매칭으로 고도화"*. 그러면서 바로 아래 주석은 *"데이터 지어내지 않음"*이라고
적혀 있다. **지어내고 있다.**

문서가 가장 강하게 금지하는 항목이다:

> §51-57 Romi should not: **Pretend to know emotions or private intent without evidence.**
> §797-812 로미가 나를 안다고 주장하는 게 아니라, 내가 한 선택을 근거로 지금의 제안을
> 설명하고 있다.

**지금 당장 드러난다.** `0027` 마이그레이션을 적용하면 `exh_house_archive_2026`이 id
정렬상 맨 앞이라, **8/13 개막 전시가 내일(7/30) 개막하는 SIF를 제치고** "네 취향
기준"이라는 문장과 함께 올라간다. admin 부스·이벤트·분석 3개 화면도 `limit: 1`로
`exhibitions[0]`을 쓰므로 빈 대시보드로 바뀐다.

**재료는 이미 다 있다.** `getUserBrain(userId)`(`repositories/types.ts:147`)이
`interests`(가치 slug별 가중치)·`literacy`·`preferences`를 주고, 부스마다 `valueTags`가
있다. `rankForExhibition`이 부스 단위로 하는 계산을 전시 단위로 집계하면 된다.

**선택지 (택1):**
- **A. 진짜 개인화** — 브레인 상위 가치 ∩ 전시 부스 `valueTags`로 전시를 정렬하고,
  근거 문장을 실제 겹친 가치로 채운다. 문서가 원하는 모습.
- **B. 정직한 축소** — 개인화를 구현할 때까지 "로미 추천" 뱃지와 근거 문장을 **뺀다**.
  정렬은 `start_date`로 바꿔 "곧 열리는 순"이라고 솔직히 말한다. 한 줄짜리 수정이고
  거짓 주장이 사라진다.

B는 오늘 할 수 있고 A는 설계가 필요하다. 둘 다 지금보다 낫다.

## P1 — 지도 상단바

**문서 §379-401** (Map Screen Layout Rule):
> No top app bar. Only a back button at the top-left. Map canvas should own the screen.

**현재** `src/components/map/map-view.tsx:180-227`: 뒤로가기 + `<h1>` 제목 + 밀도 토글 +
도움말 + 메모까지 한 줄 전체 크롬.

⚠️ **의도적 결정과 충돌한다.** `docs/decisions/2026-06-24_map-topbar-fixed-sheet-cleanup.md`:
> 상단바를 고정하니 지도 컨테이너 크기가 조작 중 변하지 않아, 확대·축소·이동이
> 안정적이다. 공간을 조금 양보하더라도 "안 튀는" 안정감이 더 중요하다고 판단.

결정이 **6/24**, 문서가 **7/11**이라 문서가 최신이다. 다만 상단바를 없앨 때 그때의
"확대·축소 튐"이 재발하지 않는지 확인이 필요하다 — 원인은 상단바가 **접혔다 펴지며**
컨테이너 크기를 바꾼 것이었으므로, 완전히 제거(항상 없음)하면 크기가 안 변해 재발하지
않을 가능성이 높다. 검증 필요.

## P2 — 반응 피드백 문구 없음

**문서 §463-511:** 끌림 / 나중에 / 별로 / 이미 봄 각각에 로미가 응답해야 한다.
예: `좋아, 이 결의 부스를 조금 더 보여줄게.` / `시간 남으면 다시 꺼내볼게.`

**현재:** `src/components/feed/reaction-bar.tsx`에 toast·메시지 **0건**. 반응은 브레인과
방문 상태에만 반영되고 사용자에겐 아무 말도 하지 않는다. 문서가 말한
"반응이 다음 추천을 바꾼다는 걸 보여준다"는 피드백 루프가 화면에 없다.

## P2 — 부스 상세 섹션 제목 4종 없음

**문서 §355-371 / §765-781:** `이 부스가 너한테 맞는 이유` · `여기서 보면 좋을 것` ·
`확실한 정보` · `아직 모르는 정보`

**현재:** 코드베이스 전체에서 **0건**. 근거 카드(`src/lib/feed/grounding.ts`)가 개념적으로
같은 4분할("무엇 / 왜 너에게 맞음 / 무슨 근거 / 얼마나 확실")을 이미 구현하고 있으므로,
**제목만 문서 문구로 맞추면 되는 수준**일 가능성이 높다.

## P2 — 신뢰·불확실성 문구 거의 없음

**문서 §569-603:** `공식 정보 기준이야.` / `대기 정보는 확인되지 않았어.` /
`이건 네 반응을 바탕으로 한 추정이야.` / `아직 데이터가 부족해서 확실하진 않아.`

**현재 검색 결과:**

| 문구 | 사용처 |
|---|---|
| `공식 정보` | 2 |
| `확인되지 않` | 0 |
| `추정이야` | 0 |
| `데이터가 부족` | 0 |

P0과 같은 뿌리다 — 무엇이 확실하고 무엇이 추정인지 구분해 말하지 않고 있다.

## 권고 순서

1. **P0 홈 추천 문장** — 오늘. 최소한 선택지 B로 거짓 주장을 없앤다.
   `0027` 적용 전에 처리하는 게 좋다(적용하면 바로 눈에 띈다).
2. **P1 지도 상단바** — 6/24 결정을 뒤집는 것이므로 확대·축소 안정성 재검증과 함께.
3. **P2 문구류(반응 피드백·부스 상세 제목·신뢰 문구)** — 구조 변경이 없어 안전하고,
   "로미가 내 반응을 알아듣는다"는 체감이 가장 크다.
4. **P1 로그인** — mock 모드 대안이 정해진 뒤.

## 이 감사가 다루지 않은 것

문서의 화면별 문구 맵(§719-795), 사용자 유형 변형(§653-717), 재계획 문구(§513-567)는
개별 문장 단위 대조라 이번 감사에서 제외했다. 위 P0~P2를 처리한 뒤 별도로 훑는 게 맞다.
