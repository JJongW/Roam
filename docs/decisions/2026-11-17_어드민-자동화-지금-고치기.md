# 어드민 자동화 라운드 테이블 "지금" 항목 고치기 (2026-11-17)

근거: Roam-design `docs/product/2026-11-17_어드민-자동화-라운드테이블/README.md` "결론 > 지금". Ted가 "지금 다 고쳐"로 맡겼어요.
운영 DB에는 쓰지 않았어요. 마이그레이션도 없어요.

## 고친 것과 이유

1. **브랜드 목록 연락 배지**: 옛 `brand_contact`(부스 열쇠, 운영 0행)를 읽어 늘 "아직 안 보냄"이었어요.
   연락 보드와 같은 `outreach-store`에 `statuses()`를 더해 출전 열쇠로 읽어요. 저장 자리를 한 곳(길목)이 정한다는 원칙을 지켜요.
2. **행사 주소(slug)**: 한글 이름이면 조용히 `"exhibition"`이 됐어요. 시트에 주소 칸을 보여 주고
   영문 이름, 없으면 행사장+연월(`coex-2026-11`, 모르면 `fair-2026-11`)로 채워요. 비었거나 겹치면 해요체로 막고, 서버도 같은 주소를 칸 오류로 막아요.
   만든 뒤에는 바꾸지 않아요(도면 `FLOORPLANS`와 인입 파일이 주소를 열쇠로 써요).
3. **DM 품목 자리**: `collected`, `reviewed`, `artist_confirmed` 칸만 넣어요. AI 초안이 "공식 계정에 소개된" 사실처럼 나가지 않게 해요. 값이 없으면 그 문장이 빠져요. Ted 문안은 그대로예요.
4. **연락 보드**: 계정 후보는 브랜드 먼저, 부스 나중. 보냄을 누르면 다음 줄로 넘어가요(거르기로 줄이 빠져도 key로 찾아요).
5. **초안 워커 경쟁 조건**: 읽기 → LLM → 조건 없는 upsert라서 그사이 사람이 확인한 칸을 덮을 수 있었어요.
   `upsertProfileFieldIfUnchanged`가 `update ... where status = 읽은 상태 and updated_at = 읽은 시각`(없던 칸은 `on conflict do nothing`)으로 써요.
   조건을 DB가 한 문장 안에서 보니 SQL 함수가 필요 없어요. 고르지 않은 안: compare-and-set RPC(0064). 같은 효과에 마이그레이션 적용이 더 들어서 버렸어요.
6. **부스 먼저 코드 → 출전 기준**(5번 뒤에): 브랜드 목록, 초안 잡 대상, 출전 탭 key, 연결 후보 `participantId`.
   부스 없는 출전은 인입이 출처와 함께 모은 소개 원문을 초안 자료로 써요. 출처 없는 원문은 쓰지 않아요.
7. **게시 전 허락 문**: 게시물과 브랜드를 잇는 칸이 없었어요. 가장 작은 연결로 `ig:publish --brands <publish-brands.v1>`(출전 id와 용도)나 `--no-brands`를 받아요.
   허락(granted/partial)과 맞는 `allowed_use`, 연락 금지, 내려 달라는 요청, 철회, 게시 전 공유를 읽기만 하고 걸리면 드라이런부터 멈춰요.
   허락 범위가 빈 허락은 통과시키지 않아요(무엇을 써도 되는지 기록이 없으면 확인되지 않은 것으로 봐요).
8. **SDF brands.v1 생성기**: `npm run brands:sdf`. 공식 WP REST와 상세 HTML로 파일만 만들어요. 서울디자인스팟(행사장 밖)은 빼요. 적용은 사람이 `/admin/intake` 미리보기를 보고 해요.

## 하지 않은 것

- 워커 생존 확인(heartbeat): 테이블(마이그레이션)과 워커 재시작이 필요해서 코드로 넣지 않았어요. PR 본문에 제안만 남겼어요.
- `stale`이 작가 확인 값까지 덮는 규칙(라운드 테이블 미정 1번)은 Ted 결정 전이라 그대로 뒀어요.
