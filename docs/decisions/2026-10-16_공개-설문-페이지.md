# 공개 설문 페이지 `/survey`

- 날짜: 2026-10-16
- 범위: `/survey`(공개), `POST /api/survey`, `/admin/survey`, `survey_response`(0060)

## 왜

박람회 방문객에게 지도·관람 방식을 묻는 설문을 링크로 돌리려고 한다. 처음엔 Claude
아티팩트로 만들었지만, 거기선 **claude.ai 계정이 있고 초대받은 사람만** 답을 저장할 수
있었다. 링크를 받은 일반인에게 로그인을 요구하면 아무도 답하지 않는다. Google Forms도
대안이었지만, 질문 일부(좁은 부스 이름, 처음 열 때의 지도)는 **그림으로 보여줘야**
답이 나오고, 결과를 우리 관리자 화면에서 같이 보고 싶었다.

## 결정

- `/survey`는 **로그인 없이** 연다(`src/proxy.ts` `PUBLIC_PATHS`). 링크 미리보기
  제목·설명을 metadata에 넣었다. 검색엔진 색인은 막았다(`robots: noindex`).
- 응답자는 설문 전용 쿠키 `roam_survey`(무작위 UUID)로 구분한다. 같은 사람이 다시 보내면
  덮어쓴다. 방문 세션 `roam_session`을 쓰지 않은 이유는 `visitor_session.exhibition_id`가
  전시 FK라서다. 설문은 어느 전시에도 속하지 않는다.
- 질문은 코드 한 곳(`src/lib/survey/questions.ts`)이 정한다. 페이지, 입력 검증(Zod), 관리자
  집계가 모두 이것을 읽는다. 질문을 바꾸면 `SURVEY_ID`를 바꾼다. 같은 id로 보기를 바꾸면 예전
  응답이 집계에서 조용히 빠진다.
- **제출까지 걸린 시간**을 함께 저장한다(`duration_ms`). 브라우저가 페이지를 연 시각부터
  "답변 보내기"를 누를 때까지 잰다. "1분이면 끝나요"라고 부탁했으니 그게 맞는지 본다.
  관리자 화면은 평균 대신 **중간값**을 보여준다. 탭을 열어 두고 나중에 낸 한 명이 평균을
  끌고 가기 때문이다.
- 결과는 `/admin/survey`에서 본다(관리자 게이트 뒤). 30초마다, 그리고 탭으로 돌아올 때 새로
  센다. "오늘"은 한국 날짜로 센다(서버는 UTC).
- 테이블은 RLS를 켜고 정책을 두지 않았다. 방문객 키로는 읽고 쓸 수 없고, 입력을 검증한 라우트만
  서비스 롤로 쓴다.

## 하지 않은 것

- 페이지를 연 수(완료율). 지금은 제출한 사람만 센다. 열고 안 낸 사람을 세려면 조회 이벤트를
  따로 적재해야 한다.
- 개인정보는 받지 않는다. 자유 의견 칸에 사람이 적는 것만 남는다.

## 적용

`supabase/migrations/0060_survey_response.sql`을 Supabase SQL Editor에서 손으로 적용해야
한다. 적용 전에는 `/api/survey`가 500("답변을 저장하지 못했어요")을 주고, `/admin/survey`는
읽기 실패를 그대로 보여준다("0명"으로 위장하지 않는다).
