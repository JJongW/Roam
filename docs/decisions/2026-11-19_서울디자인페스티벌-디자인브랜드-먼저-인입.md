# 서울디자인페스티벌 2026 디자인브랜드 먼저 인입

_2026-11-19. 결정: Ted("이거 떴다 브랜드 정리해라", 범위는 `?_sdf_category=01-design-brand`). 구현 판단은 아래에 근거와 함께 적는다._

## 무엇을 했나

- `data/brands/sdf-2026-design-brand.json`(brands.v1, 96곳): 공식 2026 명단 중 참가 구분 "디자인브랜드"만. 부스 없이 브랜드와 sdf-2026 참가 사실.
  - 소개는 주최 사이트에 브랜드가 올린 원문 그대로(`intro.status: collected`, 출처는 상세 페이지 URL). 가운뎃점과 "전시"도 고치지 않는다(2026-11-09).
  - Roam이 쓴 칸은 `source.note` 하나다. 해요체, 가운뎃점 없음.
- `npm run brands:sdf`에 `--term <참가 구분 slug>`를 더했다. 목록 화면 `?_sdf_category=` 값과 같다. 대응표는 `sdf-official.ts`의 `SDF_TERM_SLUGS`
  (01-design-brand=디자인브랜드 term id 5, 02-young-design=18, 03-design-specialist=31, 04-designspot=19).
- 분류(`category`)는 구역형 분야(디자인&크래프트 무브먼트, 그래픽 컬처 등)를 먼저 고른다(`pickSdfCategory`). 전에는 REST 순서의 첫 분야라 "리빙"처럼 옛 품목 분류가 잡혔다.
- 상세 사진 주소(`imageUrls`)를 읽어 원본 기록(`--raw`)에만 남긴다. brands.v1 `photos`에는 넣지 않는다. 그 칸은 허락 범위(`scope`)를 사람이 붙인다.
- `npm run brands:dry-run -- <파일> [--brands-only-if-missing] [--json <보고서>]`: `/admin/intake` 미리보기와 같은 계획을 운영에서 읽기만 해서 세운다.

## 부딪힌 자리: 참가 사실은 행사 행이 있어야 만들어진다

- `planBrandsFromRepository`는 `exhibitionSlug`의 행사가 없으면 멈춘다(미리보기도 404).
- 메모리 결정(11-17)은 "배치도 전에 빈 지도로 행사 행을 만들지 않는다"다. 행사에는 숨김 칸이 없어 만들면 바로 목록에 보인다.
- 브랜드만 먼저 넣으려고 `exhibitionSlug: null`로 올리면 안 된다. 멱등 키가 `brands.v1:<slug 또는 출처 URL>#key`라, 나중에 sdf-2026으로 다시 올리면
  인스타도 사이트도 없는 브랜드가 두 번 생긴다.
- 그래서 파일은 `sdf-2026`으로 두고, 순서는 배치도 → 행사 행 → 이 파일 → 부스(intake.v1)로 제안한다. 배치도 전에 꼭 넣어야 하면 행사 행을 먼저 만드는 것을 Ted가 고른다.

## 버린 방법

- **세 참가 구분을 한 파일에**: Ted가 디자인브랜드만 골랐다. 나머지 44곳(영 디자이너 프로모션 39, 디자인 스페셜리스트 5)은 같은 명령에 `--term`만 바꾸면 된다.
- **사진 주소를 photos에 바로**: photos는 저장소 경로와 허락 범위를 받는 칸이다. 남의 서버 주소를 허락 없이 앱 사진으로 쓰게 된다.
- **미리보기를 위해 이 파일만 slug를 지우기**: 위의 멱등 키 문제로 미리보기 결과가 실제 적용과 달라진다. 대신 미리보기 스크립트가 행사 없이 브랜드 판정만 보는 선택지를 가진다(적용 경로는 그대로 행사를 요구).
