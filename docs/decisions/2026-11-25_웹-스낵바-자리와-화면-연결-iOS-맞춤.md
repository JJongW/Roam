# 웹 스낵바 자리와 화면 연결을 iOS #240에 맞춤

_2026-11-25. 헤더가 맡긴 일이에요. iOS Roam-ios #240(e18cc16)과 Figma UI v1(18-T, 각 화면 프로토타입 연결)에 웹을 맞췄어요._

## 바꾼 것

1. **스낵바 자리(Figma 18-T, 11-25 결정)**: 아래 바, 탭 막대, 로미 알약이 있으면 그 윗선 위 8, 없으면 안전 영역 위 8이에요.
   - 웹은 그동안 안전 영역 위 16(`mb-v2-x4`, `pb-v2-x4`)이었어요. 마이페이지(14-01), 하트 남긴 곳(14-02, 14-05), 브랜드 하트, 부스 목록(8-01, 8-02), 홈(맡겨 둔 스낵바)을 8로 내렸어요.
   - 마이페이지 하위 화면은 `MePage`에 `snack` 칸을 두어 아래 바(14-05 지도 보기, 15-11 계정 지우기)가 있으면 그 바 위 8에, 없으면 안전 영역 위 8에 띄워요. 14-05는 바 높이를 어림한 `bottom-v2-x22`였고 15-11은 바 안에 들어가 있었어요.
   - 지도 부스 카드: 카드 위에 걸친 로미 얼굴(36의 반 18) 위 8이 되게 간격을 8에서 6으로 줄였어요(6 + 카드 위 여백 20 = 26 = 18 + 8). 예전엔 로미 얼굴 위 10이었어요. **카드 위 8은 헤더 판단이고 Ted 확인 전이에요.**
   - 부스 상세 아래 바 위 8, 지도 로미 알약 위 8은 이미 맞아 그대로 뒀어요.
   - 위 자리(5-03 로그인 제안)는 Figma 18-T가 "AB-1 결과가 나오면 정해요"라 그대로 뒀어요(웹 안전 영역 아래 4, iOS 8).
2. **13-04 뒤로 가기는 홈**: 알림함(18-02) 줄로 간 화면에서 뒤로 가면 알림함이 아니라 홈이에요. 알림함은 홈 종에서만 들어오니 `router.replace`로 알림함 자리를 바꿔 끼워요. 주소로 바로 들어와 앞 화면이 없으면 `push` 그대로예요(뒤로 가기가 앱 밖으로 나가지 않게). iOS `land`가 홈 길을 비우는 것과 같아요.
3. **8-01 머리 문장**: 홀이 하나일 때 "A홀에 부스 N곳이 있어요"를 지웠어요. Figma에 없는 문장이에요. iOS `V1Copy.Romi.boothListIntro(_:halls:)`처럼 홀이 둘 이상일 때만 범위를 쓰고 하나면 홀 없이 써요.

## 확인만 한 것 (이미 맞음)

- 14-01, 14-02 하트 줄 → 부스 상세(`/booths/[id]`), 뒤로 가기는 온 화면(`router.back()`). 6-10 다녀온 곳 줄도 같아요.
- 1-09 "지금 어디인지 알려 주기" → 9-02(로미 시트 `where`).
- 14-02 하트 줄 둘째 줄은 부스 상세의 `category.name`(분류 이름)이에요. iOS처럼 `booth.tags` 첫 값(`cs-ingredients` 같은 id)을 쓰지 않아요.

## 웹에 없는 것 (만들지 않음)

- 10-06 "여는 날 로미 한 번": 웹에 화면이 없어요.
- 13-05 "브랜드가 여럿이면 목록": 웹 알림함은 부스 없는 브랜드 알림을 그 박람회 지도로 보내요. 목록 화면이 없어요.
- 13-04 푸시 착지: 웹은 서버 푸시를 보내지 않아요. 알림함에서 가는 길만 있어요.

## 고르지 않은 안

- 알림함에서 간 부스 상세의 뒤로 버튼에 `?from=inbox`를 달아 홈으로 `push`: 기록이 홈, 알림함, 상세, 홈으로 쌓여 브라우저 뒤로 가기와 화면 뒤로 버튼이 서로 다른 곳으로 가요.
- 스낵바 자리를 iOS처럼 떠 있는 것의 윗선을 재서 계산: 웹은 스낵바를 떠 있는 것과 같은 흐름 안에 두어 재지 않아도 간격 하나로 맞아요. 재는 코드는 늘 바뀌는 높이를 따라가야 해 더 쉽게 어긋나요.
