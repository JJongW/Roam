# Roam이 쓴 행사 소개와 부스 추천 이유를 해요체로 (PR #176 후속)

_2026-11-19 · Ted 결정(2026-11-18): Roam이 쓴 합니다체는 해요체로, Roam이 쓴 가운뎃점은 뺀다, "전시"는 일단 둔다, 브랜드와 주최 원문은 고치지 않는다._

## 바꾼 곳
- mock 시드의 행사 소개와 안내(SIBF, SIF, 하우스 아카이브, 마곡): description 4건, tips 9칸의 합니다체.
  "들어섭니다" → "들어서요", "1층입니다" → "1층이에요", "대중교통을 권장합니다" → "대중교통을 권장해요",
  "실제 위치로 안내합니다" → "실제 위치로 안내해요", "쉴 수 있습니다" → "쉴 수 있어요".
- `src/lib/booth/enrichment-sibf-2026.json`: recommendationReasons 45줄(16부스), conversationPrompts 2줄의 반말.
  "네가 먼저 집어들 책은 뭐야?"는 호칭을 빼고 "먼저 집어 들 책은 뭐예요?"로 썼다.
- 마곡리빙마켓 인입 파일과 `data/verified`(같은 값 유지): recommendationReasons 231줄(117부스), timing 13줄.
  timing의 한다체("초반에 빠진다", "붐빈다")도 해요체로 바꿨다. "직접 맡아봐"는 권유로 읽혀 "직접 맡아 볼 수 있어요"로 썼다.
- 문장 끝만 바꾸고 뜻, 사실, 길이는 그대로 둔다. 받침에 따라 "예요"와 "이에요"를 골랐다.

## 안 바꾼 곳
- thingsToDo, memoryHooks, SIBF tips와 timing, SIBF summary: 명사로 끝나는 메모라 반말도 합니다체도 아니다.
- roamInterpretation: 운영 DB는 2026-11-03에 해요체로 옮겼다(`2026-11-03_로미-한-줄-해요체-일괄-변환.md`).
  레포 시드 파일은 그때 안 바꿔 반말이 남아 있다. 운영 값과 같은 문장으로 맞춰야 해서 이번에 손대지 않았다.
- 시드가 합성한 부스 longDescription의 "~의 부스입니다", "참가사입니다": `booth/blurb.ts`와 iOS `BoothAbout.swift`가
  이 문장 틀로 합성 소개를 알아본다. 틀을 바꾸면 두 앱의 판별도 같이 바꿔야 해서 따로 다룬다.
- 마곡 summary의 합니다체와 한다체: 주최 디렉터리 원문이다(§1).

## 운영 DB
`scripts/roam-voice-db.mjs`가 후속 몫도 맡는다. 바꿀 값은 `scripts/roam-voice-followup.json`(before = PR #176 뒤 레포 값,
after = 이번 값)에 있고, 운영 값이 before와 같을 때만 바꾼다. jsonb는 키 순서를 바꿔 돌려주므로 키를 정렬해 비교한다.
다르면 skipped로 남기고 안 바꾼다. 레포에 원천이 없는 다른 행사의 Roam 문장 칸은 바꾸지 않고 남은 반말과 합니다체만
diff 파일의 remaining에 센다.

검증은 공식 참가사 이름에 든 가운뎃점("동아시아·허블", "Strawberry Club·草莓烟")을 빼고 본다. 브랜드가 정한 표기다.
11-19 실행이 이 두 이름 때문에만 1로 끝났다.

## 다시 생기지 않게
`src/lib/booth/roam-data-voice.test.ts`가 enrichment의 문장 칸(recommendationReasons, thingsToDo, timing,
conversationPrompts, tips, Roam summary)과 시드 행사 소개, 안내에서 반말 문장 끝과 합니다체를 잡는다.
합니다체 검사는 "들어섭니다"처럼 받침 ㅂ이 붙는 꼴도 잡게 `[가-힣]니다`로 넓혔다.

## 고르지 않은 방향
- LLM으로 다시 쓰기(11-03 방식): 300줄 남짓이고 끝맺음 규칙이 단순해 규칙 변환 뒤 한 줄씩 읽는 편이 빠르고 뜻이 안 흔들린다.
- 문자열 단위로 운영 값 고치기: 칸 전체가 레포 값과 같을 때만 바꿔야 누가 고친 값을 덮지 않는다.
