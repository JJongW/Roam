# 비로그인 브라우징 + 온보딩 타이밍 재설계 Design

**Goal:** 로그인 없이도 전시 상세·지도·부스 상세를 둘러볼 수 있게 게이트를 다시 연다.
단, 로미(컴패니언)는 로그인한 사용자에게만 "동작"한다 — 반응 즉답·개인화 피드·플로팅
바는 계정 기능으로 남고, 비로그인은 정적 브라우징 + 로컬 임시 반응만 가능하다.
로그인하면 그동안 로컬에 쌓인 반응이 한꺼번에 서버에 반영된다. 온보딩(앱 전체 +
전시별)은 비로그인 상태에서도 이어서 할 수 있지만, 그 답도 로그인해야 실제로
브레인에 반영된다.

**Architecture:** `proxy.ts`에 정확한 경로 3개(전시 홈·지도·부스 상세)만 공개로
추가한다. 컴포넌트 레벨에서는 이미 대부분 "비로그인이면 조용히 로컬만" 동작하도록
짜여 있던 잔재(무계정 설계 시절)를 재활용하고, 로미가 "말하는" 지점(반응 즉답
토스트, 개인화 피드)만 로그인 여부로 명시적으로 끈다. 앱 온보딩의 재노출 조건을
`localStorage`(비로그인 전용) + 서버 신호(로그인 후, `brain.interests` 존재 여부)
이원화로 바꿔, 로그인 후엔 계정에 묶여 정확해지고 재노출도 안 된다.

## Global Constraints

- 로미는 로그인한 사용자에게만 "동작"한다: 반응 즉답(`say()`/토스트), 개인화 피드
  (`curateFeed`), 하단 상주 컴패니언 바는 비로그인에서 전부 꺼진다.
- 비로그인 상태의 반응 버튼(끌림·나중에·별로·이미봄)은 **시각적으로는 그대로
  토글**된다(로컬 zustand에 남음) — 다만 서버 저장·로미 반응은 없다.
- "저장 안 됨" 안내는 전시당(세션 기준) **처음 반응했을 때 1회만** 토스트로 띄운다.
  이후 반응은 조용히 로컬에만 쌓인다.
- 로그인하면 그 세션 동안 로컬에 쌓인 반응을 전부 서버에 소급 반영한다(온보딩
  답변도 포함, 기존 `PENDING_VALUES_KEY` 패턴을 부스 반응까지 확장).
- 새 카피는 기존 `home.loginReasonTitle`/`loginReasonBody`("로그인하면 로미가 너를
  기억해" — 계정 벽이 아니라 기억 설정이라는 톤)와 같은 결로 쓴다.
- 그대로 로그인 필수로 남는 것: 메모장(`/exhibitions/[slug]/notes`), 커뮤니티
  (`/exhibitions/[slug]/community`), 마이페이지·북마크류. 정확한 패턴 매치로 게이트
  걸리므로 별도 예외 처리 불필요.

참고: 이 설계는 `docs/decisions/2026-07-07_google-oauth-login.md`가 정한 "로그인
필수" 전환을 부분적으로 되돌리는 것이다 — 다만 "로미가 동작하는가"라는 축으로
계정 벽을 다시 세워, 정보 열람은 열고 개인화·기억은 계정에 묶는다.

## 섹션 A — 게이트 범위 (`proxy.ts`)

정확한 경로 패턴 3개만 공개 목록에 추가한다(하위 경로는 자동으로 안 열림):

- `/exhibitions/[slug]` (정확히 이 형태 — `/exhibitions/sibf-2026`)
- `/exhibitions/[slug]/map`
- `/booths/[id]`

`/exhibitions/[slug]/notes`, `/exhibitions/[slug]/community` 등 더 깊은 경로는
패턴에 안 걸리니 그대로 로그인 리다이렉트가 적용된다.

## 섹션 B — 화면별 비로그인 동작

- **전시 홈**: 지금 `user && brain ? curateFeed(...) : []`인 피드 영역을, 비로그인이면
  **`curateFeed` 호출 자체를 하지 않고** 로그인 유도 CTA로 대체한다(섹션 C의 카피 1).
  `{user && <BoothSearch/>}`, `{user && <메모장 카드/>}` 등 기존 계정 전용 섹션은
  그대로 숨김 유지.
- **지도**: 이미 `getCurrentUser()`를 호출하지 않아 손댈 게 없다. 반응 버튼은
  `useVisitStore.setStatus()`로 로컬 토글은 되지만, `ReactionBar`의 `say(...)` 호출
  (로미 즉답)은 **로그인했을 때만** 실행한다.
- **부스 상세**: 지도와 동일한 원칙 — 로컬 토글은 되고 로미 즉답만 로그인 조건.
- **하단 상주 컴패니언 바**: 이미 `if (!user) return null`이라 비로그인엔 안 뜬다 —
  변경 없음(원하는 동작과 이미 일치).
- **지도 로딩 화면·첫 진입 코치마크** 등 캐릭터가 등장하는 순수 안내 UI는 계정과
  무관하니 그대로 둔다(로미의 "판단"이 아니라 "화면 설명").

## 섹션 C — "저장 안 됨" 안내 + 로그인 유도 카피

기존 `promptLogin()`(`src/lib/stores/auth.ts`, 토스트 + 원탭 로그인 버튼)을 재사용한다.
지금은 북마크에서만 쓰이는데, 이번에 반응 버튼(`ReactionBar`)의 비로그인 경로에도
연결한다 — **전시당 첫 반응 1회만** 호출. "세션"은 `sessionStorage`(탭을 닫으면
리셋, `localStorage`처럼 영구는 아님) 키 `roam-promptlogin-seen-<exhibitionSlug>`로
구현한다 — 로그인 유도가 "이 브라우징 세션에서 한 번은 알려줬다"는 의미면 충분하고,
영구로 기억할 필요는 없다(다음에 다시 방문하면 한 번 더 알려줘도 무해하다).

새로 쓰는 카피 3개(`home.loginReasonTitle/Body`와 같은 톤 — 짧고 반말, "로미가
기억한다" 프레이밍):

1. **전시 홈 CTA**(피드 자리 대체):
   - 제목: "로그인하면 로미가 이 전시에서 널 도와줄게"
   - 본문: "지금은 그냥 둘러보는 거야. 로그인하면 반응한 것들을 기억해서 너한테 맞는
     부스를 골라줄게."
2. **반응 시 토스트**(전시당 1회, `promptLogin` 메시지로):
   - "지금 누른 건 로미가 기억 못 해 — 로그인하면 이제부터 다 기억할게" (액션 버튼:
     로그인)
3. **로그인 직후, 소급 반영 완료 시**(섹션 D의 동기화가 끝나면 1회):
   - "아까 둘러본 것도 다 반영했어. 이제부터 제대로 골라줄게."

## 섹션 D — 로그인 시 소급 반영

기존 `PENDING_VALUES_KEY`(앱 온보딩 답변을 로컬에 뒀다가 로그인 시 `/api/me/values`로
올리는 패턴, `src/lib/stores/auth.ts`)를 부스 반응까지 확장한다.

`syncPendingValues()`·`loadNotes()`는 지금 `login()`과 `refresh()`(user 있을 때) 양쪽에서
호출된다 — 닉네임 로그인과 Google OAuth 콜백(콜백 후 클라가 `refresh()`로 `user`를
읽어옴) 둘 다 타는 공통 경로가 `refresh()`의 `if (user)` 분기이기 때문이다. 새 동기화
로직(`syncPendingReactions()`라 하자)도 같은 이유로 **`login()`과 `refresh()` 양쪽에
붙인다**(기존 두 함수 호출 옆에 나란히) — OAuth로 로그인한 사용자도 소급 반영을
받아야 한다.

- `syncPendingReactions()`: `useVisitStore.records`에 쌓인 boothId를 전부 훑어 각각
  `pushNote(boothId)`를 호출한다(이미 있는 함수 재사용, 로그인 상태라 이번엔 실제로
  서버에 저장됨). 반영할 게 하나도 없으면(records가 비어 있으면) 아무 것도 안 하고
  카피 3(완료 토스트)도 안 띄운다.
- 온보딩 답변(앱 + 전시별)도 기존 `PENDING_VALUES_KEY` 경로 그대로 유지.
- 전부 끝나면 섹션 C의 카피 3("아까 둘러본 것도 다 반영했어")을 `say()`가 아니라
  일반 토스트로 1회 띄운다(로미 발화 형식이 아니라 시스템 완료 알림 — 로그인 직후라
  아직 컴패니언 바가 마운트되기 전일 수 있어 토스트가 안전하다).

## 섹션 E — 온보딩 재노출 조건 (원래 문제 제기)

- **비로그인 상태**: 지금처럼 `localStorage`(`roam-app-onboarded`) 플래그로 "이번
  브라우저에서 이미 봤음"만 기억한다 — 계정이 없으니 서버에 물을 게 없다.
- **로그인 상태**: `localStorage` 대신 **서버 신호**로 바꾼다 — `brain.interests.length
  === 0`이면 아직 온보딩 안 한 것으로 보고 띄운다. 섹션 D의 소급 반영 덕에, 비로그인
  때 답한 온보딩이 로그인 시 이미 브레인에 들어가 있으므로 로그인 직후 다시 물어보는
  일이 없다 — 이게 애초 "매번 뜬다"는 문제 제기를 해소하는 지점이다.
- **마운트 위치**: 지금은 `(visitor)/page.tsx`(홈)에만 있어 홈을 거치지 않고 전시로
  바로 들어오면(공유 링크 등) 안 뜬다. `(visitor)/layout.tsx`로 옮겨 전시 상세·지도·
  부스 상세 등 모든 방문객 화면에서 공통으로 뜨게 한다.
- **온보딩 이어붙이기**: 앱 온보딩(계정/브라우저 공통, 8개 가치 중 상위 몇 개)을
  끝내면, 지금 보고 있는 전시의 관람 가치 온보딩(`ValueOnboarding`)으로 **자동으로**
  이어진다(지금처럼 카드를 따로 탭할 필요 없음).
- 전시별 온보딩(`ValueOnboarding`)의 재노출 조건(그 전시의 확신 가치 유무)은 기존
  그대로 — 전시마다 다시 뜨는 게 설계 의도라 안 건드림.

## 에러 처리 / 엣지 케이스

- 비로그인 상태로 `/api/me/notes/[boothId]`·`/api/me/values` 등 쓰기 API를 직접
  치면(버튼 클릭 경로 말고) 지금처럼 401을 반환한다 — 클라이언트가 이미 이 실패를
  잡아 무시하던 경로에 `promptLogin()` 호출만 얹는다. API 응답 형식 자체는 안 바뀐다.
- 로그인 소급 반영 중 일부 `pushNote` 호출이 실패해도(네트워크 등) 전체를 막지
  않는다 — 각각 독립적으로 시도하고, 실패한 건 로컬에 남아 다음 기회에 다시 시도될
  수 있다(현재 `pushNote`의 "실패해도 로컬 캐시는 유지" 원칙과 동일).
- 앱 온보딩을 비로그인으로 완료한 뒤 로그인하지 않고 이탈하면, 다음 방문 때
  `localStorage` 플래그로 다시 안 뜬다(완료·건너뛰기 둘 다 이 플래그로 기억 —
  현재 동작 그대로).

## 테스트

- 게이트: `/exhibitions/[slug]`, `/exhibitions/[slug]/map`, `/booths/[id]`는
  비로그인으로 200, `/exhibitions/[slug]/notes`·`/community`는 여전히 `/login`
  리다이렉트 — 유닛/통합 테스트로 patterns 확인.
- `ReactionBar`: 비로그인일 때 `say()` 미호출·전시당 1회만 `promptLogin` 호출을
  순수 로직 레벨에서 검증(가능한 범위에서 — 스토어/훅 의존이라 컴포넌트 테스트 필요
  할 수 있음, 계획 단계에서 결정).
- 로그인 소급 반영: 로컬에 N개 반응이 있는 상태에서 로그인 시 N번 `pushNote` 호출
  검증.
- 온보딩 재노출: 로그인 상태에서 `brain.interests.length > 0`이면 게이트가 안 뜨는지
  단위 테스트.
