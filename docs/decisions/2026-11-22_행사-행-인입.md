# 행사 행도 /admin/intake에서 미리보기 뒤 만든다

_2026-11-22_

## 왜

새 박람회의 행사 행은 로그인된 어드민 탭의 개발자 도구 콘솔에 `fetch("/api/exhibitions", POST)`를 붙여 넣어 만들었다
(`docs/runbooks/sdf-2026-upload.md` 5단계, `moongu-2026-winter-photos.md` 2단계). 붙여 넣은 본문을 아무도 미리 보지 않고,
운영 쿠키가 있는 탭에 손으로 짠 코드를 넣는 일이라 Ted가 "이거 위험한거 같은데"라고 했다.

## 결정

- `/admin/intake`가 행사 행 파일(`data/exhibitions/*.json`)도 받는다. 올리면 형식 검사, 그다음 미리보기
  ("새로 만들어요" 또는 "이미 있어요(<id>)", slug, 이름, 장소, 날짜, 설명, 지도 크기, 안내 문구), "적용"을 눌러야 만든다.
- 같은 slug가 운영에 있으면 만들지 않는다. 미리보기에서 적용 버튼이 막히고, 라우트도 409(`CONFLICT`)로 막는다. 덮어쓰기는 없다.
- 형식 검사와 파일 종류 판정은 `checkIntakeFile`(`src/lib/intake/schema.ts`) 하나다. 화면, 라우트 앞 검사, `npm run intake:dry-run`이 같이 쓴다.
  예전 화면은 첫 오류 하나만 토스트로 띄웠는데, 이제 틀린 칸을 전부 목록으로 보여 준다(부스, 브랜드 파일도 같다).

## 파일 형식 이름: exhibition.v1, version 칸은 없어도 됨

- 이름은 brands.v1처럼 `exhibition.v1`로 둔다. `"version": "exhibition.v1"`을 적으면 그걸로 가른다.
- **version이 없어도 받는다.** 레포의 행사 파일(sdf-2026, moongu-2026-winter, 열린 PR의 sif)은 version 없이 `slug`로 시작한다.
  intake.v1과 brands.v1은 `exhibitionSlug`를 쓰고 version이 꼭 있어서, "version 없음 + `slug` 있음"이면 행사 행으로 헷갈림 없이 갈린다.
  version을 필수로 하면 이미 있는 파일과 인입 대기 목록(`lib/intake/queue.ts`)을 같이 고쳐야 해서 얻는 게 없다.
- 버린 안: version을 필수로(`exhibition.v1`) — 기존 파일 세 개를 고쳐야 하고, 빠뜨리면 "모르는 파일"로 막혀 오히려 헷갈린다.
  다만 나중에 형식을 바꿀 때는 version 칸으로 가르는 게 깔끔하니, 새 파일엔 적어도 된다.

## 파일이라 더 막는 것

`POST /api/exhibitions`와 같은 `exhibitionInputSchema`에 더해:
- 모르는 칸은 오류다(위와 `tips` 안 모두). `tip`, `tickets` 같은 오타가 조용히 버려지면 안내 문구 없이 행사가 생긴다.
- 날짜는 `2026-11-26` 모양, 끝나는 날이 시작일보다 앞이면 막는다.

## 어드민 행사 만들기 화면의 slug

이미 11-17(`cf0191d`)에 slug 칸이 생겼다. 이름, 장소, 시작일로 제안을 채우고 고칠 수 있으며, 형식과 중복을 화면(`lib/exhibition/slug.ts`)과
라우트(`POST /api/exhibitions`) 둘 다 막는다. 런북의 "한글 이름에서 slug를 만들어 못 넣는다"는 그 전 이야기라 런북에서 지웠다.
이번에 라우트 쪽 형식과 중복 막기에 테스트를 더했다.
