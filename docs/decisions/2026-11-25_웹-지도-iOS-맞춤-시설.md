# 웹 지도를 iOS에 맞춤: 8-07 로미 줄 제목, 시설 칸 검색, 시설 칸 이름

_2026-11-25. 헤더(Roam-design)가 iOS와 어긋난 웹 세 곳을 맞추라고 맡김. iOS 기준은 Roam-ios `origin/dev`(PR #234)._

## 무엇을 했나

1. **8-07 로미 줄 제목**: "제가 고른 곳도 지도에 보여 드려요" → "제가 고른 곳을 지도에 켰어요"
   (`src/lib/copy/map-entry.ts`). 근거는 화면 설계서 `Roam-design/docs/product/2026-11-17_화면-설계서/B_UI05-08.md` UI 8-07이고
   iOS는 이미 이 문구다.
2. **시설 칸도 찾기에 나온다**(`components/map-v2/map-search.ts`): iOS `FairMapModel.search`처럼 무대, 특별전, 편의시설 칸도
   검색 결과에 낸다. 시설을 고르면 부스 카드 없이(시설 카드 화면은 Figma에 없다) 고른 칸을 비우고 지도만 그 칸으로 다가간다
   (iOS `focusOnResult`). 이벤트 `search_submit`의 `booth_count`는 부스만 센다(시설 제외). 목록의 "N곳 있어요"는 iOS 배지처럼
   시설까지 센다.
3. **시설 칸 이름**(`components/map/facility-label.ts`): iOS `FacilityLabel`과 같은 규칙으로 바꿨다.
   - 어절(띄어쓰기, 여는 괄호 앞) 단위로만 줄을 바꾸고 어절 안에서 끊지 않는다. 글자를 줄이지 않고 "…"도 붙이지 않는다.
   - 칸 안에 다 들어가지 않으면 칸 바로 옆 빈 바닥(오른쪽 먼저, 그다음 왼쪽, 세로는 칸 가운데)에 쓴다.
     다른 칸을 덮거나 홀 밖으로 나가면, 칸이 기울었으면, 글자가 칸 높이보다 길면 그리지 않는다.
   - 부스 이름 규칙(UI 21, `booth-label.ts`)은 그대로다.

## 맞춤 판단

| 판단 | 근거 | 버린 방법과 단점 |
|---|---|---|
| 시설 글자 크기는 부스 이름 기준 크기(`labelBaseUnits`, 토큰 `ratio.map-booth-name*`) | 웹 지도는 도면 단위로 그려 지도와 같이 커진다. iOS처럼 화면 글자 크기(labelSm)로 쓰려면 배율마다 다시 그려야 한다 | labelSm을 맞춘 배율로 나눈 도면 크기: 확대하면 iOS와 달리 같이 커져 결국 같은 일이 안 된다, 얇은 막대 옆에선 글자가 막대보다 길어져 안 그려진다 |
| 칸 안쪽 폭은 `labelInner` × `ratio.map-booth-name-width` | 토큰에 있는 값. iOS는 `칸 폭 - 12`를 쓰는데 이 12는 토큰이 아니다(`checks:allow` 주석) | iOS 12를 웹에 옮기기: 토큰 밖 값을 새로 들인다 |
| 칸과 옆 글자 사이 = `spacing-x1`(4) | iOS `V2Space.x1`과 같은 토큰 | |
| iOS의 "가까이 볼 때만"(`size-map-booth-small-*` 화면 크기) 조건은 옮기지 않음 | 웹은 글자가 도면 단위라 들어가는지가 배율과 상관없다 | |
