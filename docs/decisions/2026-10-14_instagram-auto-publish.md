# 인스타 카드뉴스 자동 게시 — 폴더와 캡션 파일로 캐러셀을 올린다

**날짜**: 2026-10-14
**관련 파일**: `src/lib/instagram/{publish,publish-cli}.ts` · `scripts/ig-publish.ts` · `package.json`의 `ig:publish`

## 배경

카드뉴스는 Figma에서 만들고(Roam-design 레포), 9장을 내보내 휴대폰으로 옮겨 올렸다. 회차마다
같은 손일이고, 장 순서나 캡션을 잘못 붙이는 실수가 날 자리다. 댓글 자동 DM(같은 날 결정,
`2026-10-14_instagram-comment-auto-dm.md`)으로 Meta 앱과 토큰이 이미 있다.

## 결정

**Instagram API 콘텐츠 게시를 쓰는 CLI를 둔다.** `npm run ig:publish -- --dir <폴더> --caption <캡션.txt>`.

- **이미지 호스팅은 Supabase Storage 공개 버킷 `ig-publish`.** API는 파일을 직접 받지 않고
  누구나 열 수 있는 URL의 JPEG만 가져간다. Supabase는 이미 쓰고 있어 새 인프라가 없다
  (Cloudinary도 있지만 변환 URL이 붙어 JPEG 원본 그대로가 보장되지 않는다). 버킷은 첫 게시 때
  스크립트가 만든다. 경로는 `<날짜>-<슬러그>/<nn>.jpg`.
- **기본이 드라이런이다.** 이미지 목록·JPEG 여부·캡션 글자 수·해시태그 수만 보여 주고 아무것도
  올리지 않는다. `--publish`를 붙여야 올리고, 그때도 `y` 확인을 받는다(`--yes`로 생략). 게시는
  공개되는 일이라 되돌리기 어렵다 — 실수로 돌려도 아무 일이 없어야 한다.
- **`--check`로 게시 직전까지 실제로 확인한다.** 업로드·장별 컨테이너·캐러셀 컨테이너를 만들고
  `FINISHED`까지 기다린 뒤 `media_publish`만 부르지 않는다. 컨테이너는 공개되지 않고 24시간 뒤
  만료되니, 토큰·권한·공개 URL·이미지 처리를 테스트 게시물 없이 확인할 수 있다.
- **JPEG만 받는다.** `sharp`가 의존성에 없어 변환하지 않고, PNG가 섞이면 멈추고 "Figma에서 JPG로
  내보내기"를 안내한다. 이미지 하나 때문에 네이티브 의존성을 들이지 않는다.
- **장 순서는 파일 이름순**(`01.jpg`, `02.jpg` …, 숫자 인식 정렬).
- 토큰은 env `IG_ACCESS_TOKEN`(없으면 `META_TOKEN`)에서만 읽고, 헤더로만 보내며 출력하지 않는다.

## Meta 쪽 준비

- 앱(이용 사례 "Instagram에서 메시지 및 콘텐츠 관리")에 **`instagram_business_content_publish`
  권한**을 추가하고 토큰을 다시 발급해야 한다. 댓글 DM 권한만으로는 게시가 안 된다.
- 제한: 캐러셀 2~10장, 캡션 2,200자, 해시태그 30개, 계정당 24시간 게시 100건.
- **음악은 API로 넣을 수 없다.** 예약 게시도 없다 — 필요해지면 워커 크론으로 만든다.
- 캐러셀 컨테이너는 처리 시간이 있어 `status_code`가 `FINISHED`일 때까지 기다린 뒤 게시한다.
  게시 전에 실패하면 인스타에는 아무것도 올라가지 않으니 그대로 다시 돌리면 된다.
