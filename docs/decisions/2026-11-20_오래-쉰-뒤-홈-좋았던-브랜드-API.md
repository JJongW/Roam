# 오래 쉰 뒤 홈(UI 18-06B)이 읽는 좋았던 브랜드 API

_2026-11-20 · 결정 근거: 2026-11-19 Ted "1-A, 2-A, 4-B로 가" (Figma UI 18, 18-06B와 그 화면 설계 카드)_

## 무엇을

`GET /api/me/reentry` (로그인 필요, 아니면 401)

```json
{ "data": { "today": "2026-11-20", "brands": [
  { "exhibitorId": "…", "name": "돌과풀", "reasons": ["verdict_good"], "hearted": false,
    "likedAt": { "slug": "newyear-store-2026", "name": "새해준비상점 2026", "at": "…" },
    "next": { "exhibitorId": "…", "participantId": "…", "displayName": "돌과풀",
              "exhibition": { "id": "…", "slug": "…", "name": "…", "venue": "…", "startDate": "…", "endDate": "…" } } }
] } }
```

- 근거는 사용자가 직접 남긴 두 가지뿐: 부스 평가 좋았어요(`verdict = good`)와 브랜드 하트. 다녀왔어요, 부스 하트, 그저 그랬어요, 반응 없음은 쓰지 않는다(브랜드 규칙 §4 "방문했다는 사실만으로 좋아한다고 판단하지 않는다").
- 부스 평가는 그 부스의 대표 참가(`booth_participant.role = primary`)로 브랜드에 잇는다. 다음 박람회는 브랜드 단위 참가(`exhibition_participant`)로 본다. 부스 배정 전 참가도 나온다(2026-11-17 브랜드 먼저 결정).
- `next`는 아직 안 끝난(end_date >= 오늘, 한국 날짜) 참가 중 가장 먼저 열리는 것. 좋았어요를 남긴 그 박람회는 "다음"으로 치지 않는다.
- 18-06B 카드는 `reasons`에 `verdict_good`이 있는 것만 쓴다(카드 문구가 "좋았어요를 남기신 곳"). `brand_heart`는 같은 응답에서 하트 상태와 아래 "하트 남긴 브랜드가 나오는 박람회" 묶음과 맞춰 보라고 함께 준다.

## 주지 않는 것

- **쓰신 말(회고 글)**: 2026-11-17 결정으로 기기에만 남는다. 서버에 칸이 없다. 앱이 기기에서 읽는다.
- **오래 쉼 판정(30일, 미정)**: 마지막으로 앱을 연 날은 기기에 있다. 서버는 판정하지 않는다.
- **열 수 있는지(openable)**: PR #195가 `GET /api/exhibitions`에 붙인다. 이 API에 따로 넣으면 판정이 두 곳이 된다. 앱은 목록의 `openable`로 흐린 줄을 그린다.

## 버린 안

- 회고 글을 서버에 올리는 칸을 새로 만들기: 11-17 "회고 글 기기만" 결정과 어긋난다.
- `/api/me/brand-hearts` 응답에 좋았어요 브랜드를 섞기: 브랜드 하트는 따로 저장한다는 11-17 결정과 그 목록의 뜻(내가 하트 남긴 브랜드)이 흐려진다.
