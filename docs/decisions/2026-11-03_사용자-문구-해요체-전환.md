# 사용자 문구를 해요체로 바꾸고, 가운뎃점과 "전시"를 걷어 냈다

**날짜**: 2026-11-03
**결정한 사람**: Ted (2026-11-02 브랜드 규칙 재정의, 2026-11-03 판단 어휘 확정과 범위 확대 승인)
**관련 파일**: `src/lib/i18n/dictionaries.ts`, `src/lib/i18n/brand-voice.test.ts`, `src/lib/booth/about.ts`, `src/lib/booth/voice.ts`, `src/lib/booth/themes.ts`, `src/lib/enrichment/{draft-prompt,quality-gate}.ts`, `src/app/{privacy,terms,survey}`, `src/lib/survey/questions.ts`, `src/app/opengraph-image.png`
**근거 문서**: `Roam-design/docs/brand/00_brand-rules.md` §1, §5, `02_voice-tone.md` §1-1, §4-3, §4-9, §5

## What: 무엇이 달라졌나

- 방문객이 보는 한국어 문구가 전부 해요체 존댓말이 됐다. 대상은 ko 사전, 로미 한 줄과 말풍선, 버튼, 안내, 빈 화면, 오류, 로딩 문구, 메타데이터와 OG 이미지다. 관리자 화면과 API 오류 메시지도 같이 바꿨다.
- 판단 버튼은 확정 어휘를 쓴다: 꼭 갈래요, 끌려요, 패스 / 좋았어요, 그저 그랬어요, 아니었어요 / 여기 다녀왔어요.
- 사용자에게 보이는 "전시", "전시회", "전시장"은 박람회, 페어, 행사, 행사장으로 바꿨다. 가운뎃점(·)은 쉼표나 "와/과"로 바꿨다. 화면 구분자는 옅은 `|`나 쉼표다.
- 로미 한 줄을 만드는 초안 파이프라인도 해요체로 바꿨다. 지금까지는 반말을 강제하고 존댓말을 반려했다.
- `brand-voice.test.ts`가 지키는 규칙이 뒤집혔다. 예전엔 존댓말 0건을 강제했고, 이제는 반말, 합니다체, 호칭, "전시", 가운뎃점, 근거 없는 단정, 따옴표 플레이스홀더 뒤 받침 조사를 막는다.

## Why: 왜

2026-11-02 Ted가 브랜드 규칙을 다시 정했다. 사용자용 문구는 로미가 말하는 자리까지 전부 해요체이고, "전시"는 어떤 사용자 문구에도 쓰지 않으며, 가운뎃점도 쓰지 않는다. 코드와 테스트는 옛 규칙(반말 따뜻체)에 멈춰 있었다. 테스트가 옛 규칙을 강제하는 한 새 문구는 빌드를 통과할 수 없었다.

## 판단 근거

**테스트부터 뒤집었다.** 규칙은 브랜드북이 먼저 바뀌고 테스트가 그 근거로 따라간다(02_voice-tone §9). 반말 판별은 문장 끝 어미만 본다. 명사형 라벨("다녀옴", "가볍게", "오늘까지")은 반말이 아니라 통과시킨다. 판별기 자체도 테스트로 고정했다.

**로미 파이프라인은 세 곳을 한 번에 바꿨다.** 프롬프트(`draft-prompt.ts`), 게이트(`quality-gate.ts`), 남의 목소리 판정(`voice.ts`)이 서로 맞물려 있다. 하나만 바꾸면 해요체 초안이 게이트에서 반려되거나, 로미 말이 남의 인용으로 내려간다. 해요체는 더 이상 남의 말 신호가 아니다. 합니다체, 권유, 1인칭 "저희", 인사말, 판매 문구만 남의 말로 본다. 로미의 자기지칭은 "제가"다.

**운영 DB의 반말 로미 한 줄은 이 변경으로 바뀌지 않는다.** DB에 이미 들어간 roamInterpretation은 데이터라서, 다시 만들려면 워커로 해당 부스만 재생성해야 한다. 그건 워커 재시작이 걸린 일이라 Ted 승인 뒤로 미뤘다(PR 본문의 재생성안 참고).

**테마 키와 표시 라벨을 나눴다.** "일상·감성", "위로·감성" 같은 테마 라벨은 enrichment.themeTags에 그대로 저장된 데이터 키다. 키를 고치면 기존 데이터와 비교가 깨진다. 그래서 원본은 두고, 화면에 보일 때만 `displayThemeTag()`로 "일상과 감성"처럼 바꾼다. "과/와"는 받침에 따라 고른다. 비교에는 원본(`themeRawLabel`)을 쓴다.

**약관, 개인정보, 설문은 표기만 바꿨다.** 약관은 법적 의미(수집 항목, 목적, 보관 기간, 권리)와 합니다체, 시행일을 그대로 두고 "전시"와 가운뎃점만 고쳤다. 설문은 응답을 받는 중이라 SURVEY_ID, 질문 뜻, 보기 순서, 저장 값(value)을 그대로 두고 표시 라벨만 고쳤다. 저장 값과 표시 라벨은 원래 분리돼 있어 예전 응답과 비교가 깨지지 않는다.

**데이터는 코드에서 고치지 않았다.** 부스 소개, 카테고리 이름, 부스 요약 캐시, 도면 속 부스명에도 가운뎃점과 "전시"가 있다. "·"는 브랜드명이나 홀 번호 같은 고유명사에도 쓰여서 표시할 때 기계로 치환하면 틀린다. 감사 쿼리로 뽑아 사람이 고친 값을 기존 인입 경로로 넣는 쪽을 제안했다.

## 고르지 않은 방향

- **화면에서 문자열을 일괄 치환하는 함수**: 손이 적게 들지만 고유명사(브랜드명, 이벤트명, 홀 이름)가 깨진다.
- **테마 키 자체를 고치는 마이그레이션**: 화면과 데이터가 한 번에 맞지만, 저장된 themeTags를 전부 고쳐야 하고 워커 산출물과도 어긋난다.
- **설문 문항까지 새로 쓰고 SURVEY_ID 올리기**: 문구가 더 깔끔해지지만, 진행 중인 응답과 비교가 끊긴다.
