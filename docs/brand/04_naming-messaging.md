# 네이밍 & 메시징 정합성

_확정: 2026-08-15 · 표면마다 어떤 문장을 쓰는지의 단일 표. 여기 없는 문장을 새로 쓰지 않는다._

---

## 1. 이름의 위계

```
Roam    서비스의 이름.  영문 표기 고정, 번역하지 않는다.
로미    그 서비스가 말하는 방식.  한글 표기 고정. 영문 UI에서만 Romi.
```

> **Roam은 서비스의 이름이고, 로미는 그 서비스가 말하는 방식이다.**

### 규칙

| | 확정 |
|---|---|
| 서비스명 | `Roam` — 어디서나 단독 |
| 부제 `— Exhibition Navigator` | **폐기.** `Navigator`는 폐기된 동선·내비 프레이밍을 되살리고, 이름이 두 개로 보이면 OAuth 심사 리스크가 생긴다 |
| 캐릭터명 (ko) | `로미` |
| 캐릭터명 (en) | `Romi` |
| 한글 음차 `롬`·`로암` | 쓰지 않는다 |
| 로고 `alt` | `Roam` |

⚠️ **OAuth 제약**: `layout.tsx`의 홈 타이틀은 Google 동의 화면의 앱 이름과 **글자 단위로 일치**해야 한다.
`"Roam — Exhibition Navigator"`는 과거 이름 불일치로 **반려된 이력**이 있다. `Roam` 단독을 유지한다.

## 2. 표면별 확정 문장

### 2-1. 메타데이터 — `src/app/layout.tsx`

```
title.default    Roam
title.template   %s · Roam
applicationName  Roam
description      Roam은 전시·박람회 모바일 가이드입니다. 볼 만한 부스를 발견하고,
                 혼잡을 피하고, 관람한 것을 기록하세요.
openGraph.siteName  Roam
themeColor       light #ffffff / dark #0b0d10
```

**존댓말인 이유**: 대상이 사용자가 아니라 검색 크롤러와 OAuth 심사관이다.
로미의 발화가 아니라 서비스 설명문이다. 존댓말이 허용되는 세 자리 중 하나 —
나머지는 `/privacy`·`/terms`와 `/admin`. (`02_voice-tone.md` §7)

### 2-2. PWA 매니페스트 — `src/app/manifest.ts` ✅ 적용됨 (2026-08-15)

```
name              Roam                 ← "Roam — Exhibition Navigator"에서 교체
short_name        Roam
description       지금까지 파악한 네 취향으로 부스를 골라 제안하고,
                  네 반응에 따라 맞춰가는 관람 동행자.
theme_color       #4f46e5
background_color  #ffffff
icons             /icon-192.png · /icon-512.png (any) · /icon-maskable-512.png (maskable)
```

### 2-4. 홈 · 미로그인 (= 공개 랜딩)

```
h1        Roam
태그라인   반응할수록 정확해져
본문      Roam은 전시·박람회 관람 동행자야. 네 취향으로 부스를 골라 보여주고,
          네가 반응하면 그만큼 더 맞춰갈게.
짧은 변형  전시·박람회 관람 동행자
```

⚠️ 본문은 **반드시 `Roam은`으로 시작한다.** 워드마크 바로 아래에서 문장이 시작되면
워드마크와 설명이 서로 다른 제품처럼 읽힌다.

### 2-5. 홈 · 로그인

```
인사      어떤 전시부터 볼까?
부제      너한테 의미 있을 부스를 골라 보여줄게. 관심 가는 곳부터 같이 둘러보자.
빈 상태   아직 열린 전시가 없어 / 곧 새 전시가 열리면 같이 보러 가자.
추천 근거  네가 고른 관람 성향을 기준으로 먼저 보여줄게.
전시 하나  지금 열 수 있는 전시는 하나야. 안에서는 네 취향에 맞춰 부스를 골라줄게.
```

### 2-6. 로그인

**프레이밍: 계정 벽이 아니라 기억 설정.**

```
h1         Roam
부제       로그인하면 너에게 맞는 부스를 골라 함께 둘러볼게.
기억 안내   네 취향을 다음 전시에도 이어가려고 닉네임을 만들어. 비밀번호는 없어.
Google     Google로 계속하기
시트 설명   관심 저장·메모·기억을 쓰려면 로그인해야 해.
```

미로그인 전환 배너:
```
로그인하면 로미가 너를 기억해
둘러보는 건 로그인 없이도 돼. 근데 네 취향에 맞는 추천·저장·다음 전시로 잇기는
로그인해야 이어져.
```

### 2-7. 앱 온보딩 3장 — 포지셔닝의 가장 압축된 형태

```
1   안녕, 나는 / 로미야
    박람회에서 너한테 의미 있을 부스만 골라주는 관람 동행자야.

2   많이 보기보다 / 의미 있게
    수백 개 부스를 다 도는 게 아니라, 네 취향에 맞는 곳부터 같이 둘러봐.

3   볼수록 / 더 잘 맞춰줘
    끌림·별로만 눌러줘. 네 반응을 기억해서 다음엔 더 정확해져.
```

⚠️ 3장 본문의 `끌림·별로`는 **구 어휘**다 → `꼭 갈래·패스`로 갱신 필요.
버튼 자체(`judge.*`)는 이미 신 어휘로 구현돼 있고, **온보딩 산문에만 옛 단어가 남았다.**
같은 문제: `valueOnboarding.doneHow`의 `'끌림'`.

## 3. 외부 자료용 문장

### 3-1. 한 줄 (30자)
> 전시장에서 뭘 볼지 같이 좁혀가는 관람 동행자, Roam.

### 3-2. 한 문단 (주최사·투자자)
> COEX 한 층, 킨텍스 한 홀. 부스는 300개고 방문객의 시간은 네 시간이다.
> 지도를 받아도 어디부터 봐야 하는지는 아무도 알려주지 않는다.
> Roam은 부스마다 "무엇을 하는 곳이고 왜 지금 당신에게 맞는지"를 붙여, 방문객이 스스로 고를 수 있게 한다.
> 추천은 정답이 아니라 가설이다 — 방문객이 반응할수록 정확해진다.
> 주최사에게는 그 반응이 곧 관람 데이터가 된다: 어떤 부스가 실제로 발견됐고, 어디서 사람이 몰렸고, 무엇이 기억에 남았는지.

### 3-3. 세 문장 (엘리베이터)
> 대형 전시장의 진짜 문제는 걷는 게 아니라 고르는 것이다.
> Roam은 부스를 고를 근거를 주고, 방문객의 반응으로 그 근거를 계속 정교하게 만든다.
> 관람이 쌓일수록 다음 전시가 더 좋아진다.

### 3-4. 앱스토어 (반말 — 사용자 대면)
```
제목    Roam — 전시·박람회 관람 동행자
부제    반응할수록 정확해져

부스 300개 앞에서 어디부터 볼지 막막했다면.

로미가 전시를 미리 둘러보고, 네 취향에 맞을 만한 곳을 골라 보여줘.
왜 그 부스가 너한테 맞는지 근거까지 같이 준다 — 갈지 말지는 네가 정해.

· 부스마다 "무엇을 하는 곳인지 + 왜 지금 너한테"
· 꼭 갈래 · 끌려 · 패스로 누를수록 더 정확해지는 추천
· 전시장 지도에 네 판단이 색으로 남는 기록
· 관람이 끝나면 오늘 본 것을 같이 정리
```
