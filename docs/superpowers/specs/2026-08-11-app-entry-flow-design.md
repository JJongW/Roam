# 앱 진입 플로우 재설계 — 설계 문서

**날짜**: 2026-08-11
**상태**: 사용자 승인 완료, 구현 계획 대기

## 배경

로그인 성공 직후 곧바로 전시 홈이 뜨는데, 이 서비스가 뭔지·어떻게 쓰는지 아무 설명 없이 화면이 등장해 사용자가 당혹스러워한다("뚜둥하고 등장하니까 너무 난처해"). 이미 `AppOnboardingGate`(`src/components/onboarding/app-onboarding.tsx`)라는 전체화면 첫 진입 온보딩 컴포넌트가 있지만, 과거 Google OAuth 심사에서 "첫 화면이 무슨 서비스인지 알아볼 수 있는 홈이어야 한다"는 이유로 반려된 적이 있어 `/`(전시 목록 홈)에서만 의도적으로 숨겨져 있다(`canShowAppOnboarding`, `src/lib/onboarding/app-onboarding-gate.ts`).

사용자가 이후 실제로 홈을 먼저 노출한 채로 재심사를 넣었는데도 Google이 같은 사유로 계속 반려하고 있음을 확인했다 — 즉 "홈을 무조건 먼저 보여줘야 심사를 통과한다"는 전제 자체가 이제 성립하지 않는다. 따라서 이 제약을 유지할 이유가 없다고 사용자가 명시적으로 판단했다.

온보딩 도중 뒤로가기를 누르면 진행 상태가 리셋되는 버그는 이미 별도 배치(세션스토리지 상태 유지, `use-session-state.ts`)로 해결됐다 — 이 설계는 그 위에서 순수하게 진입 플로우 구조만 다룬다.

## 범위

**포함**: 앱을 처음 여는 시점(기존 `AppOnboardingGate`의 dismiss 판정 그대로 — 완료/건너뛰기 후에는 다시 안 뜬다)의 화면 구성 재설계. `/`(홈)에서도 뜨도록 노출 제약 제거.

**제외**: 매 로그인마다 반복되는 화면(사용자가 "처음 앱 열 때만"으로 명시적으로 확정). 온보딩 뒤로가기 버그(이미 해결됨). 재심사 결과 자체(별도 트랙).

## 플로우

기존 `AppOnboardingGate`의 단계(`Phase = "intro" | "quiz" | "saving"`)를 확장한다. 완전히 새로운 컴포넌트를 만들지 않고 기존 것을 확장하는 방향 — 이미 로미 모션·다국어 사전·값 집계 로직이 갖춰져 있다.

```
1. intro (기존 그대로, 변경 없음)
   Roam 이름 + 태그라인 + 로미 모션 + "시작하기" CTA + 건너뛰기
   ↓ (CTA 클릭)
2. guide (신규 phase) — "이렇게 쓰면 돼" 3단계 안내
   각 단계: 상단 라벨(STEP 1/2/3) + 제목 + 설명 + 실제 컴포넌트 스타일로
   재현한 미니 미리보기(아이콘 카드 아님 — 실제 앱 색상 토큰·카드 형태 사용)
   - STEP 1: "몇 가지만 물어볼게" — 취향 질문이 뭘 위한 건지
   - STEP 2: "그럼 이런 걸 골라올게" — 피드 카드 + 반응 버튼 미리보기
   - STEP 3: "돌아다니면서 확인해" — 지도 색 미리보기(찜한 곳 색으로 표시)
   좌우 스와이프 또는 다음 버튼으로 이동. 건너뛰기 가능(기존 intro와 같은 규칙 —
   강제하지 않는다). 건너뛰어도 quiz phase로 자연스럽게 이어진다(별도 처리 불필요).
   ↓ (3단계 다 보거나 건너뛰기)
3. quiz (기존 그대로, 변경 없음)
   적응형 취향 질문(Conversation mode="adaptive")
   ↓
4. saving (기존 그대로, 변경 없음)
   "분석 중..." 로딩 — 사용자가 원한 "로딩" 단계는 이걸로 충분(확인 완료).
   건너뛰기 경로는 이 단계를 안 거치고 바로 dismiss → 홈이며, 이 경우 별도
   전환 화면은 필요 없다(확인 완료).
   ↓
5. (완료) → dismissLocally() → 홈
```

## 변경 지점

- `src/lib/onboarding/app-onboarding-gate.ts`의 `canShowAppOnboarding`: `/`(홈) 제외 규칙을 제거한다.
- `src/components/onboarding/app-onboarding.tsx`: `Phase` 타입에 `"guide"` 추가, `intro` 완료 시 `quiz`가 아니라 `guide`로 이동, `guide` 완료/건너뛰기 시 `quiz`로 이동. 새 `guide` phase의 3단계 UI를 이 컴포넌트 안에 구현(또는 별도 하위 컴포넌트로 분리 — 구현 시점에 파일 크기 보고 판단).
- `src/lib/i18n/dictionaries.ts`: `onboardingQ.*` 네임스페이스에 3단계 제목/설명 텍스트 키 추가(ko/en).
- 세션스토리지 진행 상태 유지(`use-session-state.ts`, 이미 구현됨)가 새 `guide` phase도 자동으로 커버한다 — `phase` 값 자체가 이미 세션스토리지에 저장되는 구조이므로 추가 작업 불필요.

## 자기 점검

- **플레이스홀더 없음**: 3단계 각각의 제목·설명 문구는 브레인스토밍 중 확정됨(위 플로우 섹션에 그대로 반영).
- **내부 일관성**: 기존 `intro`/`quiz`/`saving` phase는 전혀 안 바뀐다 — `guide`만 새로 끼워 넣는 구조라 기존 로직(값 집계, `complete()`, `skip()`)과 충돌 없음.
- **범위 점검**: 단일 컴포넌트(`AppOnboardingGate`) 확장으로 끝나는 크기 — 계획을 더 쪼갤 필요 없음.
- **모호성 점검**: "3단계 미리보기를 실제 컴포넌트 스타일로"라는 표현이 애매할 수 있어, 구현 계획에서는 브레인스토밍 중 만든 목업(`.superpowers/brainstorm/` 세션, 이미 정리됨)에서 쓴 실제 값(색상 토큰 `--judge-*`, `--primary`, 카드 border-radius 패턴)을 정확히 참조하도록 명시한다.
